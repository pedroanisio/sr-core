# SREP 86 — Keep the 1.3 gates of the upstreamed engine extensions

## Abstract

SREP 0 (Versioning) requires a document that uses new elements, sections or asset kinds to declare the new
`version="1.N"`. Schema 1.6.0 carries a closed list of constructs that the reference engine added under version 1.3
before they were taken upstream (SREPs 76, 78 and 80), and their gates admit every version from 1.3 on (BH1 and VOX1,
and V8 as SREP 83 amends it). This SREP records that exception to SREP 0, names the constructs and the rules it
covers, and states that it covers nothing else. No rule, declaration or picture changes.

## Motivation

SREPs 76 to 81 take upstream what the reference engine's vendored schema had and sr-core 1.5.0 lacked (SREP 76,
Motivation). The engine gated these constructs on version 1.3, the newest version when it added them, and its corpus
has documents of version 1.3 that use them. SREP 76 (Open issues, item 2) kept "1.3 or later" for BH1, SREP 80 did
the same for VOX1, and SREP 83 changed SREP 40's gates, V8 among them, to refuse only 1.0 to 1.2. The result is that
the constructs below are valid in documents of 1.3, 1.4 and 1.5, although no schema before 1.6.0 declares them, while
SREPs 66 to 75 gate their additions on 1.6. SREP 76 recorded this conflict with SREP 0 after acceptance ("The 1.3
gates against SREP 0") and named the two ways out: an exception in SREP 0 by a Process SREP, or gates of "1.6 or
later", which would refuse the documents of 1.3 to 1.5 that use these constructs today. The schema editor chose the
exception.

## Specification

1. **Constructs covered.** The exception covers exactly these constructs and these gates:

   | SREP | Construct | Gate | Refuses it in |
   |---|---|---|---|
   | 76 | `blackHole`, `accretionDisk`, `camera/@geodesics` | BH1 | 1.0, 1.1, 1.2 |
   | 78 | `pyroBlast` | V8, as SREP 83 amends it (through `pyro`) | 1.0, 1.1, 1.2 |
   | 80 | the asset kind `voxelAsset`, `object3D` with `primitive="voxels"` or `@voxels` | VOX1 | 1.0, 1.1, 1.2 |

   These constructs MAY appear in documents of version 1.3 or later, although SREP 0 (Versioning) would require
   version 1.6 for them.
2. **Meaning.** A covered construct means the same in every version that admits it. It has no version-dependent
   meaning, as SREP 83 (Semantics 3) states for SREP 40's constructs.
3. **Older validators.** A document of version 1.3 to 1.5 that uses a covered construct needs a validator of schema
   1.6.0 or later. A validator of schema 1.3.0 to 1.5.0 refuses such a document through its XSD, which does not
   declare these constructs.
4. **Nothing else.** The exception covers no other construct. Every other addition follows SREP 0 (Versioning): new
   elements, sections and asset kinds require the version of the release that adds them. Attributes with neutral
   defaults, which SREP 0 accepts in every version that admits their element (for example those of SREPs 77, 79 and
   80 on SREP 40's elements), need no exception. A later SREP that wants the same treatment needs its own Process SREP.

## Rationale

- **Documents in use keep their verdict.** Gates of "1.6 or later" would refuse every 1.3 document with a black hole,
  a blast or cells, among them the reference engine's corpus (SREP 76, Open issues, item 2). SREP 4 counts a valid
  document becoming invalid as Breaking.
- **The purpose of a gate is kept where it matters.** A gate makes an older validator refuse new syntax explicitly
  (SREP 40). For these constructs the XSD of 1.3.0 to 1.5.0 already does: it does not declare them. Checked with lxml
  against the schema-1.5.0 XSD on the kit cases `srep-0076-valid-black-hole` (version 1.3: `blackHole` is not
  expected), `srep-0078-valid-pyro-blast` (1.3: `pyroBlast` is not expected) and
  `srep-0080-valid-voxels-version-1.5` (1.5: `object3D/@surface` is not allowed).
- **A closed list.** Naming the constructs keeps the exception from becoming a precedent that later additions could
  cite without a decision.

## Rejected alternatives

- **Gates of 1.6 or later.** Breaking for documents in use (Rationale).
- **Amending SREP 0's Versioning text into a general rule.** The case is one of migration: constructs that existed
  in one engine before they had an SREP. A general rule would invite the same path for new features.

## Backwards compatibility

None. No declaration, rule, message or picture changes; the gates are those that SREPs 76, 80 and 83 already put in
schema 1.6.0.

## Conformance

None of its own. The gates are covered by the cases of SREPs 76, 80 and 83 (for example
`srep-0076-valid-black-hole-version-1.5`, `srep-0080-valid-voxels-version-1.5` and
`srep-0083-srep78-pyro-follow-version-1.5`, valid; `srep-0076-bh1-version-1.0`, refused).
