# SREP 9 — Add map tile assets and basemaps

## Abstract

A new asset kind, `<tiles>`, names a PMTiles archive of map tiles: vector tiles (Mapbox Vector Tiles) or
raster tiles (PNG, JPEG, WebP). A new child of `<map>`, `<basemap>`, draws a tiles asset with the map: vector
tiles styled by a MapLibre style, raster tiles as images warped into the map's projection. A tiles asset can
also name an online tile service, whose tiles a resolve step fetches into a pinned cache before rendering, as
`<generated>` assets do. The scene version becomes 1.2 for documents that use them.

## Motivation

`<map>` draws geographic data the document supplies (`<geo>` assets), but not the context around it: streets,
water, land use, place names, satellite imagery. Map-based explainers, news graphics and travel videos all
need that context, and it comes as tiles: OpenStreetMap-derived vector tiles (Protomaps, OpenMapTiles),
raster imagery and elevation tiles. The de facto standard for shipping a tile set as one file is PMTiles
(Protomaps), and for styling vector tiles the MapLibre (formerly Mapbox GL) style specification. Without these,
an author has to pre-render a map to an image and loses the map's projection, camera and animation.

`<tiles>` does not take the `assetProvenance` group: it has `@sha256` for `@src` and no `@license`, `@credit`
or `@proxy` (see Rationale). The basemap attribute is `mapStyle`, not `style`: rule R22 reads every `@style`
as a reference to a `textStyle`.

`@minZoom` MUST NOT exceed `@maxZoom`. No Schematron rule checks this (see Open issues).

**Asset codes.** Asset verification, run when a document is loaded, reports two conditions on tiles assets:

- **A01** (error): the file named by `@src` or `@cache` does not exist. For `@cache` the diagnostic says to run
  the resolve step.
- **A02** (error): a file's SHA-256 digest differs from the digest the document declares for it: `@sha256` for
  `@src`, `@cacheSha256` for `@cache`. The diagnostic gives both digests, in lowercase hexadecimal. A02 is the
  same code the baseline uses for `<generated>` caches and other `@sha256` pins.

A remote `@src` or `@cache` (http, https, s3 and other non-file schemes) is reported as A03 (warning, not
verified offline) at load and is an error when the map is rendered: rendering never fetches tiles.

### Semantics

#### Archive

`@src` and `@cache` name PMTiles version 3 archives: the 127-byte header, root and leaf directories of Hilbert
tile ids, metadata JSON. Internal compression and tile compression MUST be 0 (unknown, read as none), 1 (none)
or 2 (gzip); a gzip-declared blob that does not begin with the bytes `1f 8b` is read as stored. Brotli (3),
zstd (4) and other codes are errors. The header's tile type decides the kind: 1 (MVT) is vector; 2 (PNG),
3 (JPEG) and 4 (WebP) are raster. The header's `min_zoom` and `max_zoom` are the archive's zoom range.

When a tiles asset has both `@src` and `@url`, rendering reads `@src` and ignores `@url` and `@cache`.

#### Map scale and zooms

Let `k` be the map projection's scale in the sense of d3-geo: the factor that multiplies the raw projection's
output (pixels per radian at the projection's reference) for the current view. For a map it is

    k = k0 · 2^zoom

where `zoom` is the map's current (possibly animated or flown) `@zoom` and `k0` is the map's scale at zoom 0:
`512 / (2π)` for `web-mercator` (a 512-pixel world, MapLibre's convention), and for every other projection the
scale at which the map's fit target fills the frame less `@fitPadding` (the baseline's map fitting). `@zoom`
therefore counts doublings from the fitted view, except in Web Mercator, where it is MapLibre's absolute zoom.

Two zooms are derived from `k`:

    z_style = log2(2π·k / 512) + detail                       (not rounded)
    z_tile  = log2(2π·k / tileSize) + detail
              then round(z_tile) for raster tiles, floor(z_tile) for vector tiles,
              clamped to [0, 24]; vector tiles are further limited to at most 22

`detail` is the basemap's `@detail` at the current time. `tileSize` is `@tileSize`, else 512 for vector and 256
for raster archives. `z_style` is the zoom at which style expressions, legacy functions, filters and layer
`minzoom`/`maxzoom` are evaluated, so `@detail` shifts both the tiles fetched and the style's zoom stops. For a
Web Mercator map with `detail = 0`, `z_style` equals `@zoom`; for any other projection it is unrelated to
`@zoom`. `round` rounds halves away from zero.

#### Tile selection

The tiles drawn at zoom `z = z_tile` are found by walking the quadtree from tile 0/0/0: a tile is kept when its
outline, projected through the map's projection with the map's clipping, is not empty; a kept tile of zoom
below `z` is replaced by its four children. The outline is a closed ring of 32 lon/lat points, 8 evenly spaced
in tile units along each edge, clockwise. The projection's clip extent is the frame widened by 64 px on each
side. The selected tiles are visited in (z, x, y) order.

Each selected tile `z/x/y` takes its content from the archive as follows.

- **Overzoom.** If `z` exceeds the archive's `max_zoom` `M`, the source is the ancestor `M/(x >> d)/(y >> d)`,
  `d = z − M`, and only the square of it that the selected tile covers is used: origin
  `(x/2^d − (x >> d), y/2^d − (y >> d))`, side `1/2^d`, in the ancestor's tile units.
- **Raster, missing tile.** If the source tile is not in the archive, its parent is tried (with the square
  halved and offset accordingly), and so on up to the archive's `min_zoom`; the first tile found is drawn. If
  none is found the selected tile draws nothing.
- **Vector, missing tile.** A missing vector tile is skipped; ancestors are not consulted.
- **Below the archive's range.** When `z` is below the archive's `min_zoom`, no source tile exists, so a raster
  or vector basemap draws nothing. Authors raise `@detail` or the map's zoom.

#### Vector tiles

Tiles are decoded as MVT 2.1: geometry in tile-extent units, y down; a polygon ring with positive area in
those units (clockwise on screen) starts a new polygon, a ring with negative area is a hole of the current one.
Each feature's geometry is clipped to the tile square in use (so the tile buffer and, when overzoomed, the
parts outside the used square are dropped), then placed on the map: for `web-mercator` with no pitch or roll
rotation, by the exact affine map from tile units to pixels (when the tile does not straddle the view's
antimeridian); otherwise converted to longitude and latitude and projected through the map's projection
pipeline (rotation, spherical clipping, adaptive resampling, planar clipping), like `<geo>` data.

The style is a MapLibre style specification version 8 document (an object with `layers`, or a bare array of
layers); `sources` are ignored and a layer's `source-layer` names the MVT layer. Layers are drawn in style
order. A layer is drawn when its `layout.visibility` is not `none` and `minzoom <= z_style < maxzoom`
(defaults 0 and 24). A feature is drawn by a layer when the layer's filter accepts it; filters see the geometry
type as `Point`, `LineString` or `Polygon` and the MVT feature id.

Layer types and the properties read (every property falls back to the MapLibre default; `a` is a colour's
alpha, `op` the basemap's `@opacity`):

| Type | Drawn | Properties read |
|---|---|---|
| `background` | the map's sphere outline, filled | `background-color`, `background-opacity`; alpha = opacity·a·op |
| `fill` | polygon features, non-zero fill | `fill-color`, `fill-opacity`; alpha = opacity·a·op |
| `line` | line features and polygon rings | `line-color`, `line-opacity`, `line-width` `w`, `line-gap-width` `g` (drawn width `g + 2w` when `g > 0`, else `w`), `line-dasharray` (each entry × max(w, 1) px), `line-cap`, `line-join` (miter limit 2) |
| `circle` | a disc at every vertex of the feature | `circle-color`, `circle-opacity`, `circle-radius` |
| `symbol` | text labels (no icons) | see Labels |

Any other layer type (`raster`, `fill-extrusion`, `heatmap`, `hillshade`, `color-relief`, and
others) is skipped, and the engine reports a warning naming the layer as not rendered. Style colours are read
as colour literals (CONVENTIONS 1.4).

**Expressions.** Property values may be constants, legacy functions (`{"stops": …}` with `property`, `base`,
`type` `identity`, `categorical`, `interval` or `exponential`, and `default`), legacy `text-field` strings with
`{name}` tokens, or expressions using these operators: `literal`, `get`, `has`, `id`, `properties`,
`geometry-type`, `zoom`, `let`, `var`, `==`, `!=`, `<`, `<=`, `>`, `>=`, `!`, `all`, `any`, `case`, `match`,
`coalesce`, `in`, `interpolate` (`linear`, `exponential`, `cubic-bezier`), `step`, `concat`, `format` (the
concatenated text of its sections), `to-string`, `to-number`, `to-boolean`, `number`, `string`, `boolean`,
`array`, `object`, `typeof`, `length`, `upcase`, `downcase`, `is-supported-script` (always true), `to-color`,
`rgb`, `rgba`, `+`, `-`, `*`, `/`, `%`, `^`, `min`, `max`, `abs`, `round`, `floor`, `ceil`, `sqrt`, `ln`,
`log10`, `log2`, `pi`, `e`. `feature-state`, `global-state`, `line-progress`, `heatmap-density`, `accumulated`
and `sky-radial-progress` evaluate to null. Legacy filters (`==`, `!=`, `<`, `<=`, `>`, `>=`, `in`, `!in`,
`has`, `!has`, `all`, `any`, `none`, with `$type` and `$id`) are told apart from expression filters by
MapLibre's rule and read as MapLibre reads them. `zoom` is `z_style`.

A style MUST use only these operators. An expression with any other operator fails, as does an expression
that fails at run time (a type error, `interpolate` with no stops): the property then takes its default and a
failing filter rejects the feature, as in MapLibre.

**Built-in styles.** `@mapStyle` names a style JSON file (a local URI resolved like any asset; a remote style is
an error) or one of the built-in names; absent, it is `protomaps-light`. The built-in styles are the Protomaps
basemap styles for the Protomaps basemap tile schema, from `@protomaps/basemaps` version 5.7.2 (BSD-3-Clause),
generated as `{"version": 8, "name": "protomaps-<flavor>", "layers": layers("protomaps", namedFlavor("<flavor>"),
{lang: "en"})}` and serialised as compact JSON (`JSON.stringify`, no whitespace):

| Name | SHA-256 of the style file |
|---|---|
| `protomaps-light` | `0b59638c710d8b4eae92ea50a10917b960821deac9935575ecbf15595a66fd7e` |
| `protomaps-dark` | `595e96949de2770eefdf664707ba29814d1329e3c48de082203d443886fccf4d` |

An engine MUST use byte-identical styles for these names.

**Drawing.** Within a layer, features are drawn tile by tile in the selection order and in tile order.
Consecutive fills (or lines) of a layer with identical paint (colour, alpha and, for lines, width, dashes, cap
and join) are merged and drawn as one shape, so shared tile and feature borders leave no seam and overlapping
features do not darken each other.

**Labels.** `@labels="false"` draws no `symbol` layer. Otherwise every `symbol` layer contributes one label
candidate per feature with non-blank text, and all candidates of the basemap are placed together after its
last layer is drawn.

- Text: `text-field`, then `text-transform` (`uppercase`, `lowercase`). Size `text-size` (px), colour the RGB
  of `text-color`; text alpha is `@opacity` (the colour's alpha and `text-opacity` are not applied). Halo:
  when `text-halo-width` > 0 and `text-halo-color` has alpha > 0, the glyph outlines stroked with width
  2 × `text-halo-width`, round caps and joins, at alpha (halo alpha × `@opacity`), under the text.
- Font: weight 700 when any `text-font` name contains `Bold`, 500 when one contains `Medium` or `Semibold`,
  else 400; italic when one contains `Italic`. The family is the generic `sans-serif`, which the reference
  engine resolves to the first installed of DejaVu Sans, Liberation Sans, Noto Sans, Arial, Helvetica. The
  family is not normative.
- Layout: the text is wrapped to a width of max(`text-max-width` × size, size), centred. Its box is the
  bounding box of the glyph outlines.
- Anchor: a Point feature gives a candidate at each of its points; a Polygon feature one at the arithmetic mean
  of the vertices of its largest projected ring (by absolute area); a LineString feature one per projected line
  piece when `symbol-placement` is `line`, and none otherwise. For point anchors the candidate positions are
  `text-variable-anchor` in order, else `text-anchor`; for anchor fractions `(ax, ay)` (left 0, centre 0.5,
  right 1; top 0, bottom 1) the box's top-left is
  `q + text-offset·size + (1 − 2ax, 1 − 2ay)·text-radial-offset·size − (ax·width, ay·height)`.
  A line label is placed at the midpoint of the piece by length, rotated to the direction of the segment there
  with the angle folded into [−90°, 90°] so text stays upright, and only when the piece is at least 1.1 times
  the text width; its box is the axis-aligned bounds of the rotated text box.
- Priority: candidates are placed in order of style layer, later layers first (MapLibre's order: upper layers
  win); within a layer, lower `symbol-sort-key` first; then feature order (tiles in selection order, features
  in tile order).
- Collision: each box is grown by `text-padding` px on every side. A candidate position is rejected when its
  grown box lies wholly outside the frame `[0, w] × [0, h]` or overlaps a grown box already placed; the first
  position not rejected is taken, and a label with none is dropped.
- Duplicates: a taken label is still dropped when a label with the same text was already placed with the top-
  left of its box in the same 8-px bucket, `(round(x0/8), round(y0/8))` (the same name repeated by neighbouring
  tiles). A dropped duplicate does not occupy space.

#### Raster tiles

Each selected tile is drawn as image cells whose corners are projected exactly; each cell is an affine image
defined by three corners: the tile point `(u0, v0)` maps to projected `p0`, and the cell's u and v edges to
`p1 − p0` and `p2 − p0`. Tile points convert to longitude and latitude by the Web Mercator tile grid.

- A tile is one cell for `web-mercator` with no pitch or roll rotation, and a fixed 8 × 8 grid of cells
  otherwise.
- A cell is dropped when any of its four corners is on the invisible side of the projection's spherical clip
  (the far side of a globe), when any corner lies further than the frame's diagonal (the frame widened by 64 px
  each side) from `p0` (a cell torn across the view's antimeridian), or when its projected bounds lie outside
  the frame `[0, w] × [0, h]`.
- A cell inside the frame is drawn whole. A cell crossing the frame's edge is cropped exactly to the frame when
  it is axis-aligned (with the texture window moved to match); otherwise it is split into four and each quarter
  treated the same way, down to three levels of splitting, after which it is drawn whole.
- The image is sampled bilinearly. Cells are drawn with alpha `@opacity`.

An engine MAY warp raster tiles differently (finer cells, per-pixel inverse projection). Its placement of tile
content MUST then agree with the reference within the conformance tolerance, 2 px.

#### Paint order

A map paints, from the bottom up:

1. the raster tiles of every raster basemap, in document order;
2. the map's `@background` fill;
3. its vector basemaps and its other children (`geoLayer`, `graticule`, `route`, `pin`) in document order;
4. its `@outline`;
5. the tiles' credit (Attribution);
6. the text labels of `geoLayer` and `pin` (baseline).

Raster tiles therefore sit beneath the map's background. A map with a `@background` whose alpha is above 0 and
a raster basemap hides the tiles where the background covers them; the engine reports this as a warning ("the
raster basemap is drawn beneath the map's background").

Vector content, the credit and the labels are clipped to the map's frame `[0, w] × [0, h]`. Raster cells are
limited to the frame by the cell rules above.

#### Opacity and animation

`@opacity` is applied per style layer and per drawn primitive (each merged fill or line shape, each circle,
each label halo and text, each raster cell), not to the basemap as a group: where primitives overlap they
show through each other. With `@opacity` 0 the basemap draws nothing, but its credit is still drawn.
`@opacity` and `@detail` may be animated; both are evaluated per frame.

#### Attribution

The credit of a basemap is its tiles asset's `@attribution`, else the archive metadata's `attribution` string.
Credits of the map's basemaps with `@attribution` true are collected in document order, each distinct string
once, and joined with `" · "` (space, U+00B7, space). From the joined text, everything from a `<` up to the
next `>` is removed, then `&copy;` becomes `©` and `&amp;` becomes `&`; other entities are left as written.

The text is drawn in the map's bottom-right corner: size `s = clamp(h/60, 9, 14)` px with `h` the map's height,
default font, colour (0.1, 0.1, 0.1), right-aligned at `x = w − 6` within a box of width `0.8·w`, its top at
`y = h − 1.6·s`. Beneath it is a white plate at alpha 0.7: the bounds of the glyph outlines grown by `0.3·s`
on each side.

#### Resolve

For a tiles asset with `@url`, a resolve step (not rendering) fills `@cache` and pins `@cacheSha256`:

1. **Kind.** The asset is taken as raster when the URL, lowercased and without its query (`?…`), ends in
   `.png`, `.jpg`, `.jpeg` or `.webp`, and as vector otherwise. The kind gives the default `tileSize` and the
   rounding of `z_tile`.
2. **Views.** For every frame `f = 0, 1, …, ceil(duration · fps)` of the project (`t = f / fps`), for every map
   with a `<basemap>` naming the asset, the map's view at `t` gives `z_tile` (with the basemap's static
   `@detail`, not its animated value), clamped to `[@minZoom, @maxZoom]`, and the tiles selected at that zoom.
   The tiles to fetch are the union over all frames and maps.
3. **Fetch.** Each tile is requested from the template with `{z}`, `{x}`, `{y}` substituted and `{s}` replaced
   by `a`, `b` or `c` for `(x + y) mod 3` = 0, 1, 2. Status 200 stores the tile; 404 and 204 leave it out; any
   other status fails the step.
4. **Archive.** The tiles are written as a PMTiles version 3 archive. Its tile type is taken from the first
   stored tile's bytes (PNG, JPEG or WebP signature: raster; gzip signature: MVT, gzip-compressed; otherwise
   MVT). Its metadata holds only the source template, so the credit of a resolved archive comes from
   `@attribution`.
5. **Pin.** The archive's SHA-256 is written to `@cacheSha256`.

The reference engine refuses more than 2000 tiles per asset by default (a configurable engine limit, not part
of this SREP).

### Defaults and the neutral case

Both elements are new. A map without `<basemap>` renders as before.

## Rationale

- **PMTiles** is a single-file, random-access tile archive with a public specification and readers in many
  languages; it needs no tile server, which keeps renders hermetic.
- **MapLibre style specification**: the open, widely implemented styling language for vector tiles, with
  published test fixtures; the Protomaps styles are its reference use for OpenStreetMap-derived tiles. Pinning
  the built-in styles by version and digest makes `protomaps-light` render the same in every engine.
- **512-pixel zoom 0** is MapLibre's convention, so a style's zoom stops mean what they mean in MapLibre;
  `z_style` is computed from the scale, not from `@zoom`, so it keeps that meaning in every projection.
- **Floor for vector, round for raster**: MapLibre loads vector tiles at the floor of the zoom and scales them
  up; raster tiles look sharpest at the zoom closest to their pixel size.
- **Resolve step and pinned cache** follow `<generated>` (baseline): the network is never touched while
  rendering, and a render is repeatable from the document and its files.
- **No `assetProvenance` on `<tiles>`.** The schema carries no licence machinery: `@license`, `@credit` and
  `@proxy` would duplicate `@attribution` or mean nothing for an archive, and the maintainers' rule is that a
  tile set has one plain credit line, `@attribution`, which is also what is drawn. `@sha256` stays, because
  pinning `@src` is what makes a render repeatable.
- **Raster tiles beneath the background.** The engine paints bitmaps of a vector drawing before its vector
  content; raster tiles use that path. The order is kept and made visible by the warning rather than changed.

## Rejected alternatives

- **`@style` on `<basemap>`.** R22 reads every `@style` as a text style reference.
- **Tile directories (`z/x/y.png`) or MBTiles.** Directories are thousands of files per asset; MBTiles needs
  SQLite in every engine. PMTiles is one file with a simple binary layout.
- **Fetching tiles while rendering.** Breaks determinism and offline rendering.
- **`assetProvenance` on `<tiles>`.** See Rationale.

## Backwards compatibility

Every document valid under 1.1 is valid under 1.2 and renders the same. The new elements require
`version="1.2"` (rule V5).

## Open issues

- Whether the built-in style names belong in the schema's documentation or in an engine note.
- `@minZoom <= @maxZoom` has no rule. The reference engine does not check it at load; its resolve step fails
  when it is violated. A Schematron assertion (`number(@minZoom) <= number(@maxZoom)` with the defaults) or an
  asset error at load would close this.
- An unsupported style operator makes the property fall back to its default, silently. Whether it should be
  an error when the style is loaded.
- The resolve step uses the static `@detail`; an animated `@detail` can select tiles it did not fetch.
- A non-axis-aligned raster cell that still crosses the frame edge after three splits is drawn whole and may
  extend past the frame by up to 1/64 of a tile.
- PMTiles tile type 5 (AVIF) is outside this SREP.
