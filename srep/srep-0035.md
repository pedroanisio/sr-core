# SREP 35 — Add presetEase to text animators, and fix three preset behaviours

## Abstract

A `textAnimator` preset (`fade-in`, `slide-up`, `pop`, `counter` and the others) moves each unit along a curve the
preset fixes, most often cubic-out. This SREP adds `presetEase`, an optional attribute that names another curve from
seven (`linear`, `quad-in`, `quad-out`, `cubic-out`, `expo-out`, `back-out`, `bounce-out`), so an author can choose a
linear, an overshooting or a bouncing entrance. It also records three behaviours that were corrected to match what the
schema and README say: a `counter` keeps the leading zeros of its authored number, `counter` and `scramble` start on the
parent timeline like every other preset, and `mask-reveal` clips each line to its own box. Documents that omit
`presetEase` render as before, except where those corrections apply.

## Motivation

- **No way to change a preset's curve.** The preset table fixes each preset's ease. Cubic-out is front-loaded: at 40 % of
  the duration it is 78 % done, so entrances that should read as steady look like they arrive at once. The G2 lab found no
  attribute that changed the curve: an `ease` attribute does not exist on `textAnimator`, and setting one is a schema
  error (S04). The engine's own review of motion listed the missing choice as a gap for captions that must land on a beat.
- **Counter lost its zeros.** A counter written `007` counted `3 … 7` and changed width while counting (the HUD and Swiss
  typographic studies).
- **Counter and scramble used another clock.** `presetStart` is a time on the layer's parent timeline for the other
  presets; `counter` read it as an offset on the layer's own clock and `scramble` mixed both.
- **Mask-reveal showed glyphs through the next line.** The clip was the union of line boxes, so a glyph waiting below its
  place showed through the line under it (README: "clips each line to its box").

## Specification

### Syntax

```xml
<!-- textAnimator gains -->
<xs:attribute name="presetEase">
  <xs:annotation><xs:documentation>
    The curve of a preset, in place of the preset's own (most use cubic-out, which is front-loaded: at 40 % of the
    duration it is 78 % done). Without @preset it has no effect.
  </xs:documentation></xs:annotation>
  <xs:simpleType><xs:restriction base="xs:string">
    <xs:enumeration value="linear"/><xs:enumeration value="quad-in"/><xs:enumeration value="quad-out"/>
    <xs:enumeration value="cubic-out"/><xs:enumeration value="expo-out"/><xs:enumeration value="back-out"/>
    <xs:enumeration value="bounce-out"/>
  </xs:restriction></xs:simpleType>
</xs:attribute>
```

A new optional attribute with no default, accepted in every version (SREP 0, Versioning). No Schematron rules.
`textAnimator/@presetStart` also gains documentation (see the annotation SREP draft).

### Semantics

**1. The curve.** With `presetEase`, the unit's progress `q ∈ [0, 1]` through its window is mapped by one of (Penner's
definitions, <https://easings.net>):

| value | f(u) |
|---|---|
| `linear` | `u` |
| `quad-in` | `u²` |
| `quad-out` | `1 − (1 − u)²` |
| `cubic-out` | `1 − (1 − u)³` |
| `expo-out` | `1 − 2^(−10u)` for `u < 1`, and 1 at `u = 1` |
| `back-out` | `1 + (c + 1)(u − 1)³ + c(u − 1)²`, `c = 1.70158` |
| `bounce-out` | the piecewise bounce with `n1 = 7.5625`, `d1 = 2.75` |

Without `presetEase` the preset's own curve applies. Presets that step (`typewriter`, `word-by-word`) and `wave` and
`scramble` have no curve and ignore `presetEase`; `counter` reads it, with `cubic-out` as its default curve.

**2. Where it acts.** Offsets (position, rotation, scale, tracking, blur) are added as `value · s` (scale as
`1 + (value − 1)·s`) with `s` computed from the curve, so a curve that leaves `[0, 1]` (`back-out`) overshoots the rest
value; positional and scale values MUST NOT be clamped. Opacity MUST stay in `[0, 1]`, and the `pop` and `bounce` presets'
opacity keeps its own curve whatever `presetEase` says.

**3. Counter keeps leading zeros.** The width of a counting number is the number of digits of the authored text
including leading zeros: `007` counts `003 … 007`. Thousands separators and fractions behave as before.

**4. Preset clock.** `presetStart` is a time on the layer's parent timeline (composition time for a top-level layer),
for every preset including `counter` and `scramble`; when absent the preset starts at the layer's own start.

**5. Mask-reveal.** Each line is clipped to its own line box. A glyph that has not yet arrived MUST NOT be visible through
the line below it.

### Defaults and the neutral case

Without `presetEase` every preset uses its own curve, as before. Documents that do not use `counter`, `scramble` or
`mask-reveal` over more than one line, and whose counters have no leading zeros, render as before.

## Rationale

- **Seven curves, not all 41.** Presets run inside a staggered window per unit and are one-shot; the seven cover linear,
  accelerating, the common decelerating family, overshoot and bounce. A named subset also keeps the attribute checked by
  the XSD enumeration. The 41-curve set belongs to keys (`curveType`).
- **A new name.** `ease` is not usable: it is not an attribute of `textAnimator`, and `ease` elsewhere (keys) means a
  segment curve. `presetEase` names what it changes.
- **The corrections follow the schema's and README's own sentences.**

## Rejected alternatives

- **Reuse `curveType`.** Many of its curves (catmull-rom, spring, steps) do not make sense for a per-unit window.
- **A per-unit curve list.** No study needed it.

## Backwards compatibility

- **Class: Added (`presetEase`), MINOR in effect but accepted in every version; the corrections are PATCH.**
- **Visible changes.** (a) A counter with leading zeros keeps them: `007` was drawn `7`, widening while counting.
  (b) A `counter` that set `presetStart` read it as a layer-relative offset; it is now a parent-timeline time, so such a
  document starts at a different time unless the layer starts at 0 (a top-level layer starting at 0 is unchanged).
  (c) `scramble` mixed clocks the same way. (d) A two-line `mask-reveal` no longer shows glyphs through the next line.
- **Version gate.** None.

## Conformance

| Case | Checks | Tolerance |
|---|---|---|
| `srep-NNNN-preset-ease-curves` | one character with `preset="ascend"` (offset 0.5 em) and each of the seven curves: at 40 % of `presetDuration` the vertical offset equals `0.5 em · (1 − f(0.4))` for that curve (0.30 em linear, 0.108 em cubic-out) | 0.02 em |
| `srep-NNNN-preset-ease-back` | `pop` with `back-out`: the scale peaks above 1.05 and returns to 1 | peak ±0.02 |
| `srep-NNNN-counter-zeros` | `007` counter at its end shows `007`, mid-count shows three digits | exact text width |
| `srep-NNNN-counter-clock` | `counter` with `presetStart="2"` on a layer starting at 1: starts at 2 s | 1 frame |
| `srep-NNNN-mask-reveal-lines` | two lines: during the reveal no pixel of line 2's pending glyphs is inside line 1's box | 0 pixels |
