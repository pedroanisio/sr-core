# SREP 2 — Correct the XSD header's statement of whom the schema serves

## Abstract

The first paragraph of the XSD's header documentation said the schema is "the interchange contract for the
deterministic C17 renderer". The schema is shared by four engines and its canonical copy is in sr-core
([SREP 0](srep-0000.md)). The sentence now says so. No declaration changes.

## Motivation

The header is the first thing a reader of the schema, or of the generated reference (`docs/schema/`), sees.
It named one engine, which is not the reference implementation and whose copy of the schema is not the
canonical one, and it said nothing about how the schema changes.

## Specification

In `scene-render-1.1.xsd` (renamed `scene-render.xsd` by [SREP 3](srep-0003.md)), the second sentence of the schema-level `xs:documentation` reads:

> This schema is the interchange contract shared by every scene-render engine (C, Rust, Python,
> JavaScript). Its canonical copy is sr-core/schema/; it changes only through an accepted SREP (sr-core/srep/).

It replaces "This schema is the interchange contract for the deterministic C17 renderer." Nothing else in
either file changes. Determinism is still stated by the header's own "Determinism" paragraph.

## Rationale

The header stays engine-neutral: which engine is the reference implementation is a process decision that may
change, so it lives in SREP 0, not in the schema.

## Rejected alternatives

- **Naming Rust as the contract's home.** That would repeat the same problem the next time the reference
  implementation changes.

## Backwards compatibility

Documentation only. Every declaration, type and default is unchanged, so every document validates and renders
as before. The file's SHA-256 changes from `15861a8f…` to `91d4d88e…`.
