# SREP 93 — Align declared attributes with the engine

## Abstract

This proposal removes three unused attributes, aligns accepted values with the reference engine, exposes chart
legends and absorbing ocean boundaries, and preserves the distinction between an omitted attribute and an
explicit preset override. It also defines missing units, corrects documentation, and permits a PDF text region
without a placeholder box. The companion XSD and Schematron are a working-tree application of this draft, not a
released schema or an acceptance decision. Engine behavior cited below is from scene-render `c0c668b`; proposed
behavior and provisional engine work are identified separately.

All paths in this section are relative to the **scene-render repository at `c0c668b`**. Evidence is source
inspection, not newly measured renders. No engine build, render, or physics test was run for this draft.

## Specification

### Syntax

The following declarations are the complete structural delta to the current XSD; unchanged annotations and
unaffected declarations retain their existing meaning. `scene/@version` and `xs:schema/@version` are unchanged
in the draft application; generated schema mirrors, documentation and hash manifests reflect the draft files.

| Element/@attribute | Declaration |
|---|---|
| `marker/@color`, `colorManagement/@bitDepth`, `project/@mode` | Remove the declarations. |
| `shapeModifier/@ridges` | Optional restriction of `xs:positiveInteger`, maxInclusive 1024, default 5. |
| `modifier/@axis` | Optional restriction of `xs:string`, enumeration x, y; default y. |
| `fractal/@palette` | Optional restriction of `colorListType`, minLength 1; retain the existing five-colour default. Only this use of colorListType gains a length restriction. |
| `audiogram/@smoothing` | Optional restriction of `unitDecimal`, maxInclusive 0.99; default 0.5. |
| 2D `rigidBody/@mass` | `positiveDecimal`, default 1. |
| `chart/@legend` | Optional `xs:boolean`, default false. |
| `ocean/@boundary` | Add absorbing to closed, open, periodic; retain default closed. |
| `ocean/@spongeCells` | Optional `xs:positiveInteger`, default 16. |
| `pdf/region/@x`, `@y`, `@width`, `@height` | Change use from required to optional; retain double coordinates and nonNegativeDecimal extents; no defaults. |
| `textAnimator/@unit`, `@overlap` | Retain their types and remove default="character" and default="0" respectively. |
| `project/@antialias3d` | Retain the type (`xs:positiveInteger`, maxInclusive 4); change the default from 1 to 4. |
| `particleEmitter` attributes listed below | Remove XSD defaults on covered attributes that have them; retain types and prose fallbacks. |

The four additional Schematron assertions MUST apply wherever their enclosing elements are already admitted:

| Code | Context | Assertion |
|---|---|---|
| PRG18 | `program[@mode='step']` | No outputSha256 attribute, regardless of its value. |
| C81 | `pdf/region` | text is present OR all of x, y, width and height are present. |
| C82 | `layout[@aspect]` | With positive components W:H, W*height = H*width. Unreduced equivalent ratios are accepted. |
| OCN15 | `ocean[@boundary='absorbing']` | Let nX=round(width/cellSize), nZ=round(depth/cellSize), w=spongeCells. Require w >= 4, 2*w < nX and 2*w < nZ. Defaults width=64, depth=64, cellSize=1, w=16 are honored without default expansion. OCN3 still checks grid integrality. |

The exact executable XPath is in the companion `schema/scene-render.sch` pattern `srep93-attributes`, including
handling of explicit positive signs in numeric XML values. No rule ids are renumbered. R32 continues to admit
image, imageSequence, video and generator sprites. P02's engine-side ridge check is removed in favor of the XSD
bound; the defensive geometry bound remains. Neither token numeric syntax nor another project projection
switch is introduced.

### Semantics

#### Removed controls and bounded inputs

Engines MUST reject the three removed controls under this proposal's schema. `project/@precision` continues to
select working texture precision, and scene360/viewport3D continue to describe their existing projections.
Invalid ridge counts, axis names, palette entries, empty palettes, smoothing above 0.99, and nonpositive 2D masses
MUST be rejected by schema validation. Fractal palettes MUST continue accepting `var(--name)` colour references;
reference resolution still follows the existing token rules. This change does not redefine the shared
`positiveDecimal` type or make claims about non-finite lexical values (Open issues).

SREP 75's `fractalAssetType/@palette` declaration is amended from `xs:string` to the nonempty restriction of
`colorListType` above. Empty and malformed lists MUST fail XSD, before Schematron or rendering; SREP 75 did not
assign them a Schematron-only rejection. Its default palette, colour interpolation and token resolution remain
unchanged. The amended declaration is also recorded in SREP 75.

#### Legend and series names

For chart kinds line, area, bar, column and scatter, `legend="true"` MUST draw one swatch in each series' resolved
colour and its `series/@name`, in series document order. False or omission MUST draw no legend. Other chart kinds
ignore legend. Names are the legend/data-label text. Legend layout and text metrics remain an acceptance blocker
under Open issues; this draft does not claim a completed pixel-level specification. Unknown `chart/@kind` values
MUST be invalid; the engine fallback sentence is removed.

#### Absorbing ocean edges

Absorbing edges MUST use open, zero-gradient boundary faces plus the reference sponge relaxation. The width is
measured in **cells**, not pixels or metres. Outside an absorbing ocean, spongeCells has no effect. Let dx be
cellSize in ocean-local units, w the sponge width, d the minimum cell-index distance to an edge, and h the solver
substep duration in seconds. For d < w, r=(w-(d+0.5))/w and rate=6*cRef*r*r/(w*dx), where
cRef=sqrt(gLocal*max(initialDepth)). The conserved state MUST relax toward its initial free-surface/velocity
state with keep=exp(-rate*h): qNew=qRest+(qOld-qRest)*keep. Depth at rest is max(restSurface+currentBed,0),
and rest momentum is that depth times initial velocity. Dry momentum is zeroed under the existing dryTolerance
rule. These constants and operations are the ones in `Sponge::relax`; no new absorber is invented here.

OCN15 extends SREP 40's ocean rule family. XSD requires a positive integer spongeCells; Schematron checks the
absorbing-only minimum and grid-dependent bounds. The SREP 40 rejecting-fixture corpus includes OCN15, and the
focused SREP 93 cases cover its defaults, boundaries and inactive sponge.

#### Step programs, PDF boxes, layout ratio

A step program's outputSha256 MUST be rejected with PRG18; build and data programs retain their existing output
pinning. A stateful frame sequence has no one byte stream to which that pin could refer. Module sha256 and
existing deterministic stepping inputs retain their meaning.

This supersedes SREP 17's unconditional XSD requirement for all four region coordinates. Their presence is now
conditional and MUST be checked by Schematron C81: without text, an incomplete box passes XSD and fails C81.
The coordinate types remain XSD constraints. SREP 17's Syntax records the amended declaration.

An author MAY omit any or all box coordinates when region text is present. Resolve MUST replace all four with
the selected text occurrence's box, in cache-image pixels (top-left origin, +y down), and treat an incomplete
cached box as a cache miss. Without text, all four MUST be provided, including zero-valued coordinates or extents
where their types permit them. An empty text attribute satisfies the presence rule but does not guarantee that
resolve can find a phrase. Rendering a text region still requires its resolved box; omission is an authoring and
resolution feature, not an unspecified render-time box.

Aspect is an assertion only: engines MUST use layout width and height as the source of frame size and reject an
inconsistent ratio with C82. For example, both 9:16 and 18:32 agree with 1080 by 1920; neither agrees with 1080 by
1080. No floating tolerance is introduced. Large-integer XPath precision is recorded under Open issues.

#### Authored presence and presets

For textAnimator, an explicit unit MUST override the preset, including character. Omission uses the preset unit,
or character without a preset. An explicit overlap MUST override the preset, including zero; omission uses the
preset overlap. Its existing applicability exceptions (typewriter, word-by-word, wave, scramble, counter) remain;
without a preset overlap has no effect. The renderer MUST test presence rather than compare against zero or
character.

For particleEmitter, resolution MUST be: explicit attribute, else the selected preset's entry, else the
no-preset fallback below. Animation/expression overrides retain their existing precedence. These are the
attributes actually covered by the reference preset table and read through `Attr`; values shown are fallbacks,
not XSD defaults:

| Attribute(s) | No-preset fallback |
|---|---|
| lifetime | 1 second |
| lifetimeVariance | 0 seconds |
| speed; speedVariance | 100; 0 pixels/second |
| direction; spread | -90; 0 degrees |
| gravityY; turbulence | 0 pixels/second squared |
| drag | 0 per second |
| size; sizeEnd | 4 pixels; resolved size |
| sizeVariance | 0 (dimensionless fractional spread) |
| color; colorEnd | opaque white; resolved birth colour |
| opacityEnd | 1 (no fade) |
| rotationVariance | 0 degrees |
| angularVelocity; angularVelocityVariance | 0 degrees/second |
| shape | disc |
| trail | 0 seconds |

The engine MUST remove `schema_default` and equality-to-default detection. `rate` remains default 10 and outside
preset resolution: changing the previously ineffective preset rate entries would be a separate behavior change.
`gravityX` also keeps default 0: no current preset contains it. Attributes already lacking defaults (speedVariance,
sizeEnd, colorEnd, opacityEnd) remain optional. Preset value tables and random algorithms themselves are unchanged.

#### Colour tokens, material exceptions and PDF implementation record

Styles tokens MUST denote colours. Numeric constants use parameters/expressions; the styles annotation loses
“number.” A loaded MaterialX document MUST preserve the material's uvScale and doubleSided and any maps that the
loaded document does not supply. This confirms the current annotation rather than inventing another exception.

The SREP 17 Engine impact row is corrected to **implemented**, with hayro 0.8.0 under feature pdf. Its published
crate metadata declares `Apache-2.0 OR MIT`; this was verified in the locally installed hayro-0.8.0 Cargo.toml,
matching the engine Cargo.lock version, not inferred from a similarly named library. “Implemented” records source
availability; it does not claim that the SREP 17 compatibility kit was run here or change its Accepted status.
The earlier mention of pdfium as an example rasterizer in its rationale remains historically correct.

#### Parametric path closure

`parametricPath/@closed` MUST close only a nonempty path with no non-finite sample after the first finite sample.
Each non-finite sample is discarded and lifts the pen; the next finite sample starts a new subpath. A trailing
non-finite point prevents closure; leading discarded points alone do not. All-non-finite input is empty. Samples
retain their existing XSD range; the engine's defensive bounds do not license invalid document values.

#### D7: soft-body pressure and self-collision

D7 gains the following definitions, verified in `SoftState::step`. Coordinates below are solver metres, masses
kilograms, time seconds. This proposal does not amend D7's unrelated lattice/cloth/rope description.

For jelly with a nonzero pressure coefficient P and at least three boundary vertices, let A0 be signed rest area
and A signed current area. P has units **N/m**. At each integration substep:

- p = P * (abs(A0)/max(abs(A), 1e-9 m2) - 1).
- For each oriented boundary edge e = position[j]-position[i], take sign = +1 if A0 >= 0, else -1, and
  n = sign*(e.y,-e.x), an unnormalized outward normal in metres.
- Both endpoints MUST receive force 0.5*p*n in newtons. The factor half shares the edge load; it is not a unit
  normal. P=0 adds no force; pressure applies only to jelly.

For selfCollision, let r=0.5*max(minimum spring rest length,1e-6 m). Each unordered pair with distance l satisfying
1e-12 m < l < r MUST receive equal opposite repulsive forces of magnitude kEff*(r-l), directed along the pair,
where kEff is the effective stiffness after the reference stability limit. Pinned points remain pinned; exactly
coincident points are skipped. This is a penalty force, **not a hard minimum-separation guarantee**. False adds
none. The XSD defaults remain pressure=0 and selfCollision=false.

For completeness, that stability limit uses point mass m=max(totalMass/max(pointCount,1),1e-9 kg),
need=max(1,ceil(dt*sqrt(8*k/m))), subs=min(need,4096), and h=dt/subs, with declared stiffness k in N/m.
kEff is m/(8*h*h) if need>subs, otherwise k. This is the existing `soft.rs`, `substeps` and `SoftState::step`
calculation, not a new stiffness control.

#### Shadow bias and procedural sky exponent

`light/@shadowBias` MUST be interpreted as dimensionless normalized light-depth bias, subtracted from z/w before
shadow comparison. The default is 0.0005. It is neither a distance in scene pixels nor the separate 0.5-unit
world-normal offset used by the reference shadow shader.

For a dome procedural sky, skyExponent is positive and dimensionless, default 0.5. Given unit direction d in
dome space, s=-d.y, horizon H, zenith Z and ground G in linear working colour, the gradient MUST be
H+(Z-H)*min(s,1)^k when s>=0, and H+(G-H)*min(-s,1)^k otherwise, k=skyExponent. The existing sun contribution
is separate and unchanged.

#### Constraint units

`constraint/@maxForce` MUST be documented as the angular motor torque limit in **N*m (kg*m2/s2)** for the current
2D and 3D motor constraints. Both implementations pass it to an angular motor with no pixelsPerMeter multiplier.
It is not agents/@maxForce, which denotes acceleration. No explicit limit is passed when absent.

`constraint/@breakForce` MUST be documented in **N (kg*m/s2)**, comparing the magnitude of the linear constraint
impulse divided by the integration interval, removing the joint only for a strict exceedance. Angular impulse
components are excluded. At c0c668b, 2D uses sqrt(Jx²+Jy²)/dt; 3D uses sqrt(Jx²+Jy²+Jz²)/(dt/max(iterations,1)).
This SREP records that discrepancy, and does not assert those measurements are equivalent or silently select a
replacement. A unified interval and its test remain an acceptance blocker (Open issues). Absence means no break
threshold.

#### Ocean gravity in physical units

Ocean gravity MUST mean **m/s2**, default 9.81. For physics pixelsPerMeter P and a positive uniform world scale S
(scene pixels per ocean-local unit), local gravity MUST be gLocal=gravity*P/S. A local depth D is D*S/P metres;
therefore physical shallow-water speed is sqrt(gravity*D*S/P) m/s, or sqrt(gLocal*D) local units/s. The conversion
follows the inverse-transform scale used by `Colliders::crossing` and the existing metres=S/P cavity conversion.
It is a proposed correction, not a claim that c0c668b already applies it. Buoyancy and cavity physical laws MUST
receive gravity directly in m/s2; default analytic wave speeds use gLocal. Physics P defaults to 100 when absent.
The scale policy for nonuniform or animated ocean transforms is unresolved below.

#### Trim mode

For `shapeModifier type="trim"`, mode values MUST be simultaneous or sequential, with simultaneous when absent.
Simultaneous applies the trim fraction to each subpath; sequential consumes the combined measured length in
subpath order. `shape/@trimMode` already has this default. Other shapeModifier kinds retain their own mode
vocabularies, so there is no unconditional mode default on the shared declaration.

### Defaults and the neutral case

Legend=false draws nothing new. Boundary remains closed; the new sponge width is unused unless absorbing is
selected. Removing preset-inserted defaults leaves the no-preset fallbacks unchanged. Existing complete PDF boxes
and absent aspect assertions keep their behavior. Tokens, MaterialX, parametric closure, soft-body forces and
light formulas are documentation of existing behavior.

Not every change is neutral: explicit zero/character/default-valued preset overrides now win, trim omission
switches to simultaneous, ocean wave dynamics change with the gravity conversion, invalid-input boundaries
change, and provisional engine implementations can make formerly inert controls visible. These exceptions are
intentional and are recorded under Backwards compatibility rather than hidden as documentation corrections.

## Rationale

The reference source and declared defaults decide the corrections first: 1024 ridges, 0.99 smoothing, false
legend, closed ocean boundaries, and the documented 9.81 physical gravity are concrete constraints. SREPs 17,
35, 58, 66, 69, 71 and 75 supply the existing PDF, text, length-measure, program, sky and fractal contracts.
SREP 0's neutral-default principle and the need to distinguish authored values favor explicit overrides over
equality-to-default guessing.
No external rendering convention is used to override source evidence. In particular, D7's proposed separation
guarantee was discarded because the solver uses a force, and motor maxForce is torque rather than pixel force.

The semantic changes are deliberate: retaining unused attributes or accepting a value that secretly becomes
another value does not produce a reliable authoring contract. The physical camera gate, true per-glyph
perspective, source video timecodes, broader sprite support and ocean m/s2 choice are binding design decisions
represented in the provisional work, not alternatives reopened by this draft.

## Rejected alternatives

- Remove video timecodeStart: the source in/out record has a conforming and editing use; implement it instead.
- Add numeric style tokens: parameters already supply numeric values; colour token syntax remains unchanged.
- Restrict R32 to images: implement all already admitted sprite kinds, preserving sequence-age versus layer-time
  sampling in the provisional contract.
- Keep smoothing=1 valid: the chosen authoring limit is 0.99, not a second value that secretly means 0.99.
- Keep preset equality tests: explicit zero, character and fallback-valued emitter attributes need to win.
- Use scene-unit ocean gravity: 9.81, physical density and the existing buoyancy interface support m/s2; local
  geometry needs a conversion, not a second interpretation of the same attribute.
- Claim this is PATCH or add a blanket version="1.8" requirement: neither repairs unconditional XSD removals.
- Reuse the SREP 86/90 exceptions: each is explicitly limited to its own constructs and grants no authority here.

## Backwards compatibility

**Decision: document version 1.8 and a 1.8 gate are not sufficient under SREP 0 as written.** This proposal is
Breaking, provisionally targeting **2.0**, and requires a separate Process SREP enumerating the breakages plus a
migration tool before release. If the editor instead chooses release 1.8, a new, explicit Process SREP exception
is required; this Draft neither grants nor assumes it. No version gate is added to the draft Schematron, and no
schema or document-version declaration is bumped in this working tree. A 1.8 gate on new syntax alone would not
preserve 1.7 documents rejected by unconditional XSD removals/type changes, nor preserve old ocean pictures.

SREP 0 admits neutral new attributes in every version; chart legend and unused-by-default spongeCells qualify.
No new element, section or asset kind is introduced, so there is no new-element 1.8 gate to add. Existing gates
for charts, oceans, PDFs and programs remain. Adding absorbing to an existing enum and permitting omitted PDF
box coordinates are additive syntax, but their presence cannot turn the entire bundle into a compatible MINOR.
Published schema 1.7.0 remains the old contract; these draft files are not a replacement release of that tag.

## Open issues

1. **Release authority and migration:** the proposed 2.0 release needs a Process SREP and migration tool; an
   alternative 1.8 release needs its own explicit Process exception. Neither exists in this work. The existing
   1.7 version strings are deliberately not a claim that these changed files can be released as 1.7.0.
2. **Constraint break-force interval — verified discrepancy, unified semantics unverified:** 2D divides by dt,
   3D by dt/iterations. The same physical units do not make those the same threshold. A known-load test against
   the locked Rapier solver version is needed before choosing and documenting one integration interval. No
   promise of identical 2D/3D breaking behavior is made. The 2D rigid-body friction, damping and sensor response
   are also unverified at library level; this draft changes only mass's declaration.
3. **Ocean scale — unverified beyond uniform fixed scale:** the source establishes metres per local unit as
   S/P through the inverse world transform, but it does not establish one scalar conversion for nonuniform or
   time-varying scale. The engine branch needs a defined policy and tests for those transforms, without changing
   the binding choice of physical gravity. Ocean goldens and arrival-time tolerances have not been measured.
4. **Legend layout — unverified/new:** swatches/names/order and neutral omission are specified, but placement,
   reserved plot area, text style, wrapping, clipping and label collision behavior await the engine agent's
   concrete implementation and measurable case. No pixel layout is guessed here.
5. **Provisional attribute section — not source-confirmed implementations:** all its sentences await the engine
   agents' replacement text and test results. In particular independent easeHigh/easeLow endpoint formulas,
   per-glyph perspective/camera treatment, warpable mesh interpolation, the lighting smooth falloff curve,
   trackData's complete compatibility table, container language mapping/tag retention, MSAA support, caption
   interleaving and time-mapped audio-description delivery are unverified. No unverified numerical formula is
   adopted for those new implementations. The mesh position default pairs x with column and y with row in the
   existing regular grid; the final warp interpolation still needs a definition.
6. **Stroke/outline softness presence:** the provisional intent distinguishes absent softness from explicit
   0.1, but the shared effect declaration currently inserts default 0.1. Whether the engine retains authored
   presence before default expansion is unverified; the coordinator needs to resolve it before acceptance.
   This draft does not silently remove a shared default outside its declared structural scope.
7. **Shared numeric type:** positiveDecimal is historically a restriction of xs:double, not xs:decimal. Local
   lxml accepts NaN and INF on that type despite the intended positive finite physical domain. This proposal
   does not rewrite the shared type; non-finite rejection and engine structural validation need separate
   verification. No mass finiteness guarantee is claimed from this type change alone.
8. **Aspect arithmetic:** XPath 1.0 represents numbers as doubles. The cross-product assertion is exact for
   normal frame dimensions but can round for very large integer lexicals; arbitrary-precision equivalence is
   unverified. Final engine validation should compare integer cross-products without overflow, and the schema
   editor needs a consistent supported dimension range or exact-ratio strategy before acceptance.
9. **Draft integration:** generated HTML, the scene SDK, packaged mirrors and hash manifests are synchronized
   with the draft. No engine tests or raster goldens were produced. The Process decision, engine branch and
   compatibility-kit cases remain prerequisites for acceptance/release.
