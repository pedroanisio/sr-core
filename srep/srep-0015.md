# SREP 15 — Add stroke markers that ride on trim paths

## Abstract

Open outlines gain markers at their ends: `markerStart` and `markerEnd`, from a closed set (arrowheads,
dots, squares, diamonds, bars), sized in stroke widths. A marker sits at the end of the part of the
outline that is actually drawn, so a line that draws on with `trimEnd` carries its arrowhead with it.
Stroke and markers are painted as one coverage, so a translucent stroke shows no seam under its head. The
attributes default to `none` and are accepted in every version. [SREP 16](srep-0016.md) uses the same
markers on connectors.

## Motivation

The format has no arrowhead, and an arrowhead cannot follow a draw-on.

- **A published production with 31 campaign arrows on a map** draws each arrow as three shapes:
  - a dark casing and a gold core, two `shape="path"` nodes whose 60-odd vertices are identical;
  - a separate triangle for the head, with coordinates computed outside the document;
  - `trimEnd` keys on both strokes, and hand-set opacity keys on the head so that it pops in when the
    strokes finish drawing (0.12 s before `trimEnd` reaches 1).

  The head cannot travel with the draw-on, because nothing places a shape at the end of another shape's
  trimmed outline. The 31 arrows take 93 shapes and 124 animations, and a change to an arrow's route means
  recomputing three coordinate lists and re-timing the head.
- **The feature showcase fixture** fakes an arrowhead with a `polygon` riding a `motionPath` under
  `autoOrient`. That only works because its path is fixed.

## Specification

### Syntax

The XSD gains the declarations below, and `shapeType` gains `<xs:attributeGroup ref="strokeMarkers"/>`
after `trimPath`.

```xml
<xs:simpleType name="strokeMarkerType">
  <xs:restriction base="xs:string">
    <xs:enumeration value="none"/><xs:enumeration value="arrow"/><xs:enumeration value="open-arrow"/>
    <xs:enumeration value="circle"/><xs:enumeration value="square"/><xs:enumeration value="diamond"/>
    <xs:enumeration value="bar"/>
  </xs:restriction>
</xs:simpleType>
<xs:attributeGroup name="strokeMarkers">
  <xs:annotation><xs:documentation>
    Markers drawn at the start and end of an open outline, in the stroke's paint, pointing along it
    (the start marker points backwards). markerSize is in multiples of strokeWidth. With trim paths,
    markers sit at the ends of the visible part.
  </xs:documentation></xs:annotation>
  <xs:attribute name="markerStart" type="strokeMarkerType" default="none"/>
  <xs:attribute name="markerEnd" type="strokeMarkerType" default="none"/>
  <xs:attribute name="markerSize" type="positiveDecimal" default="4"/>
</xs:attributeGroup>
```

```xml
<sch:pattern id="p64">
  <sch:rule context="shape[@markerStart[.!='none'] or @markerEnd[.!='none']]">
    <sch:assert id="C65" test="@shape='path' or @shape='line'">markers need an open outline: shape="path" or "line".</sch:assert>
  </sch:rule>
</sch:pattern>
```

The type is named `strokeMarkerType` because `markerType` already names the timeline markers.

### Semantics

The **drawn interval** of an outline is the part that is stroked after trim paths, in path order. For a
shape it is the trimmed outline; SREP 16 defines it for connectors. Let u = `strokeWidth` and
L = `markerSize` · u.

1. **Where markers apply.**
   - On a `shape`, `markerStart` applies at the first point of the drawn interval in path order, and
     `markerEnd` at the last, each only when the subpath holding that point is open.
   - Markers are drawn in the element's node space.
2. **Marker frame.** A marker is drawn in a frame whose:
   - origin is its end of the drawn interval;
   - +x axis is the direction of travel there for `markerEnd` (along the last segment of nonzero
     length), and the reverse of it for `markerStart` (along the first segment of nonzero length);
   - +y axis is +x turned 90° clockwise on screen.
3. **Geometry**, in the marker frame:

   | Marker | Shape | Setback |
   |---|---|---|
   | `arrow` | filled triangle (0, 0), (−L, −L/2), (−L, L/2) | L |
   | `open-arrow` | polyline (−L, −L/2), (0, 0), (−L, L/2), stroked with width u and the stroke's cap, join and miter limit | 0 |
   | `circle` | filled disc, centre (−L/2, 0), radius L/2 | L/2 |
   | `square` | filled square, centre (−L/2, 0), side L, sides parallel to the axes | L/2 |
   | `diamond` | filled quadrilateral (0, 0), (−L/2, −L/2), (−L, 0), (−L/2, L/2) | L/2 |
   | `bar` | segment (0, −L/2) to (0, L/2), stroked with width u and the stroke's cap | 0 |
   | `none` | nothing | 0 |
4. **Stroke setback.** The stroke of the drawn interval is shortened at each end by that end's setback,
   measured along the outline, and then stroked by D26. Markers are not dashed.
5. **Paint.** Markers use the stroke's paint. Stroke and markers MUST form one coverage (their union)
   before painting, so a translucent stroke is not darker where a marker overlaps it.
6. **Degenerate cases.**
   - If the drawn interval has zero length, or u = 0, neither stroke nor markers are drawn.
   - If the setback leaves no stroke, only the markers are drawn.
7. **Animation.** `markerSize` animates.

### Defaults and the neutral case

`markerStart` and `markerEnd` default to `none`, which draws nothing and shortens nothing, so a shape
without them renders exactly as before.

## Rationale

- **SVG 2 §11.6 is the model:** markers are sized in stroke widths (`markerUnits="strokeWidth"`) and
  oriented along the path, the start marker reversed (`orient="auto-start-reverse"`). A closed set of
  shapes with exact geometry replaces SVG's arbitrary marker content, so every engine's output is
  comparable and every marker measurable.
- **Markers ride on trim paths.** That is the one behaviour the production above had to fake.
- **One coverage.** The production's casing is translucent (`#0B151CC8`); a marker painted separately
  over it would show a darker seam under the head.
- **The marker frame's +y is the stroke's right-hand side,** the same clockwise-on-screen sense as
  `rotation`.

## Rejected alternatives

- **SVG-style `<marker>` definitions with arbitrary content.** They need nested rendering, a viewBox, and
  orientation and overflow rules, and no two engines would clip them alike. A later SREP can add
  `marker="url(#symbolId)"` if a closed set proves too small.
- **Markers sized in pixels.** A casing and its core would need two marker sizes; in stroke widths, one
  size serves both.
- **Markers on closed outlines.** A closed outline has no end; C65 rejects markers on shapes whose
  outline is always closed.

## Backwards compatibility

- **Class: Added, MINOR (1.2).** New attributes with neutral defaults, accepted in every version (SREP 0,
  Versioning); no version gate.
- No document valid under 1.1 becomes invalid, and none renders differently.
- **Evidence.** The XSD and Schematron above, with SREP 16's, were applied to a copy of the canonical
  schema, and 3,405 local scene documents were validated with both copies. The only changed verdicts were
  documents that already declare `version="1.2"`.
