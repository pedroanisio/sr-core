# SREP 0 — Add time-series layers to the map

## Abstract

SREP 12's M3: data with a **time** on a map that plays. Every timed element has a **data time** T, the sum of
its **`timeOrigin`** (a number of seconds, or an **ISO 8601** date-time read as seconds since **1970**-01-01T00:00:00Z)
and its animatable **`time`** offset. A **`geoLayer`** gains **`timeBy`** (the property holding each feature's
time), **`timeEndBy`**, **`trail`** and **`fade`**: a feature is drawn from its time on, until its end, and, with a
trail, for that many data-time units, fading out **linear**ly. A **`route`** over a geo asset gains **`timeBy`**
(the property holding one timestamp per vertex, **non-decreasing**), **`trail`** (default 120) and **`fade`**
(default true), after **deck.gl**'s **TripsLayer** (**MIT**): the drawn part of a trip runs from T − trail to the
**head**, the **interpolated** position at T, and each point's alpha is 1 − (T − τ)/trail; **`headRadius`** and
**`headFill`** mark the head. A **`basemap`** gains **`timeOrigin`** and **`time`** so that
`["global-state", "time"]` in a style **filter** or expression is T (amending SREP 9, where it is null): the
style itself decides which features have happened. Every state is named (**pending**, **running**, **complete**,
**gone** for trips; **visible**, **pending**, **expired**, **ended**, **unreadable** for features), every pixel
is defined (strokes with **round** caps and joins, **premultiplied**, the alpha of the nearest point of the
path), and a frame depends on the document and the composition time alone, so **any frame alone** equals the
played frame (SREP 14's **seek check**). Validation rules TS1–TS4, warnings W-TS1 and W-TS2, the schema gate
V17. Reference `conformance/tools/time_series_reference.py` (**numpy**), tests `tests/test_time_series.py`.
Engine card [SR-114](https://faz-ai.atlassian.net/browse/SR-114).

## Motivation

A science explainer shows earthquakes as they happened, ships and storms moving along their tracks, outbreaks
spreading county by county. SREP 9 draws tiles and styles, SREP 36 draws a `geoLayer`'s lines on with
`progress`, and a `route` is drawn on by ground length; none of them knows what time a feature belongs to. An
author today filters the data in a notebook, exports one asset per frame and swaps them, which breaks the seek
check and makes the document a list of files instead of a description. SREP 12 names this gap (M3: feature
time, timeline filters, trips) and asks for the semantics kepler.gl and deck.gl users already know: a current
time, a trail length, a fade, a head. This draft adds those on the elements the format already has, in data-time
units the author chooses, with the same `animate` keys that drive every other attribute.

## Specification

### Syntax

`geoLayerType` gains six attributes:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `timeBy` | xs:string | absent | Name of the feature property holding the feature's time (a number of seconds, or an ISO 8601 date-time). Absent: the layer is not timed and the attributes below are errors (TS3). |
| `timeEndBy` | xs:string | absent | Name of the property holding the time from which the feature is no longer drawn; a feature without it has no end. Must differ from `timeBy` (TS4). |
| `timeOrigin` | xs:string | `0` | A time: the data time at `time` 0, as a number of seconds or an ISO 8601 date-time with seconds and a zone. |
| `time` | xs:double, animatable | `0` | Seconds of data time added to `timeOrigin`; T = `timeOrigin` + `time`. |
| `trail` | nonNegativeDecimal | `0` | Data-time units a feature stays drawn after its time; 0 keeps it forever. |
| `fade` | xs:boolean | `false` | Multiply the feature's alpha by 1 − (T − τ)/`trail`; needs a positive `trail` (TS2). |

`routeType` gains five attributes; `trail` and `fade` take deck.gl's defaults:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `timeBy` | xs:string | absent | Name of the property holding the feature's timestamps: one time per vertex, non-decreasing. Only with `geo` (TS3): `@points` carry no properties. Absent: the route is drawn by `progress` as before. |
| `timeOrigin` | xs:string | `0` | As on `geoLayer`. |
| `time` | xs:double, animatable | `0` | As on `geoLayer`. |
| `trail` | nonNegativeDecimal | `120` | Data-time units behind the head that are drawn; 0 draws the whole trip from its start. |
| `fade` | xs:boolean | `true` | The trail fades from 1 at the head to 0 at its end; needs a positive `trail` (TS2). |

`basemapType` gains two attributes, `timeOrigin` and `time`, as on `geoLayer`. The data time is the value of
`["global-state", "time"]` in the style's filters and expressions.

**Validation** (an engine reports every rule it can check):

- **TS1** (error): a `timeOrigin` that is neither a finite number nor an ISO 8601 date-time with seconds and a
  zone, or a `time` that is not a number (or animation keys of numbers).
- **TS2** (error): a `trail` below 0 or not a number, a `fade` that is not a boolean, or `fade` with `trail` 0
  (a route's default `fade` with an explicit `trail="0"` included).
- **TS3** (error): `timeEndBy`, `timeOrigin`, `time`, `trail` or `fade` on an element without `timeBy`, or a
  route's `timeBy` without `geo`.
- **TS4** (error): a `timeEndBy` equal to `timeBy`.
- **W-TS1** (warning): a route feature whose `timeBy` property is not a list of one time per vertex, or whose
  times decrease, or a feature that is not a line; the feature is skipped and reported once per route.
- **W-TS2** (warning): a feature whose `timeBy` or `timeEndBy` property is missing or not a time; the feature
  is hidden (state `unreadable`) and reported once per layer.
- **V17** (error): any of these attributes in a document before version 1.8, or an attribute the schema does
  not declare on a timed element.

### Semantics

1. **Times.** `parse_time`: a time is a finite number of seconds, or an ISO 8601 date-time
   `YYYY-MM-DDTHH:MM:SS` with an optional fraction `.fff` and a zone that is `Z` or `±HH:MM`, read as seconds
   since 1970-01-01T00:00:00Z in the proleptic Gregorian calendar without leap seconds (the fraction and the
   zone offset applied; negative before 1970). A date
   without a time, a time without seconds or without a zone, a non-calendar date and anything else is not a
   time. Blanks around a number are ignored.
2. **Data time.** `data_time`: T = `timeOrigin` + `time`, where `time` is the attribute's value at the
   composition time (`animated`: the value of its `animate` keys read linearly between keys and clamped to the
   first and last; equal key times jump to the later value). Each timed element has its own T.
3. **Feature state.** `feature_state`: with τ the feature's `timeBy` time and ε its `timeEndBy` time (absent
   when the property is absent), the feature is `unreadable` when τ or ε is missing or not a time; `pending`
   when τ > T; `ended` when ε ≤ T; `expired` when `trail` > 0 and T − τ > `trail` (with `fade`, when T − τ ≥
   `trail`, where the alpha reaches 0); else `visible`. The checks run in that order.
4. **Feature alpha.** `feature_alpha`: a visible feature is drawn as SREP 9 and SREP 36 draw it (fill, stroke,
   dot, label, `progress`) with its alpha multiplied by 1 − (T − τ)/`trail` when `fade` is true and `trail` > 0,
   else by 1; other states draw nothing. A layer without `timeBy` draws every feature with alpha 1.
5. **Timestamps.** `check_timestamps`: a route feature's `timeBy` property is a list with one time per vertex
   (rule 1) whose values do not decrease; otherwise the feature is skipped (W-TS1).
6. **Head.** `interpolate`: the head at T lies on the segment from the last vertex whose stamp is ≤ T to the
   next, at the fraction (T − τᵢ)/(τᵢ₊₁ − τᵢ) of the segment, linearly in the projected map pixels of the
   vertices; before the first stamp it is the first vertex, at or after the last stamp the last vertex; equal
   stamps jump to the later vertex. (`@points` routes keep SREP 9's ground-length `progress`.)
7. **Trip state.** `trip_state`: `pending` when T < τ₀; `gone` when `trail` > 0 and T − τₙ > `trail`;
   `complete` when T ≥ τₙ; else `running`. Pending and gone trips draw nothing.
8. **Window.** `trip_window`: the drawn part of a running or complete trip is, in order, the tail (the
   interpolated position at T − `trail`, when `trail` > 0 and T − `trail` > τ₀), the vertices with stamps in
   (T − `trail`, T) (all remaining vertices once T ≥ τₙ) and the head (rule 6; the last vertex once T ≥ τₙ).
   Each point's alpha is 1 − (T − τ)/`trail` clamped to 0..1 when `fade` and `trail` > 0, else 1, with τ the
   point's stamp (the tail's is T − `trail`, the head's T). A trip at T = τ₀ is its head alone.
9. **Stroke.** `stroke_pixels`: the window is stroked with `stroke`, `strokeWidth` and `opacity` with round
   caps and joins: a pixel is covered when its centre lies within `strokeWidth`/2 of the polyline, and takes
   the alpha of the nearest point of the polyline (linear between the two ends of the nearest segment, ties to
   the earlier segment), premultiplied. `head_pixels`: when `headRadius` > 0 a disc of that radius in
   `headFill` (the `stroke` paint when absent) at `opacity` is composited over the stroke at the head.
   `trip_pixels` composes the two; a route's `dash` applies to the window as to a plain route.
10. **Style filters.** `evaluate`, `keep_feature`: in a `basemap` with `timeOrigin` or `time`,
    `["global-state", "time"]` evaluates to the basemap's T in every filter and expression of its style; other
    global-state keys stay null. A feature whose filter fails or errors is dropped (SREP 9). `to-number` reads a
    time (rule 1), so `["<=", ["to-number", ["get", "when"]], ["global-state", "time"]]` compares ISO
    date-times. Nothing is fetched: the data time selects among the tiles already resolved.
11. **Paint order.** Timed features paint where their element paints (SREP 9's order); the time attributes
    change what is drawn, never where.
12. **Seek check.** `run` is a function of the document and the composition time alone; no element keeps state
    between frames, so any frame rendered alone equals the same frame of the played sequence.

## Rationale

- **Data time, not composition time.** Earthquake catalogues are in dates, trips in seconds since departure.
  `timeOrigin` + animatable `time` lets one `animate` run a day of data in ten seconds without rewriting the
  data, and the same keys drive the basemap, the events and the trips in step.
- **ISO 8601 with seconds and a zone.** The time-frames draft's `epoch` takes the same form; a date without a
  zone is ambiguous and is refused rather than guessed.
- **deck.gl's trail semantics.** TripsLayer's `trailLength` 120, `fadeTrail` true and alpha 1 − (t − τ)/trail
  are what kepler.gl users have seen for years; the draft takes the numbers and the formula so a kepler.gl
  trip looks the same here.
- **The head is interpolated by time.** The card's acceptance test: at time t a vehicle is where its timestamps
  put it, between vertices, not at the last vertex passed.
- **`global-state` time on the basemap.** Styles already have filters; giving them the data time is the
  smallest change that makes timeline filters possible for every style layer type at once.
- **States are named.** `pending`/`running`/`complete`/`gone` and `visible`/`pending`/`expired`/`ended`/
  `unreadable` let an engine log and a test assert why a feature is absent.
- **Defaults keep untimed documents unchanged.** Without `timeBy` nothing differs from schema 1.7.

## Rejected alternatives

- **A new `trips` element.** Rejected: a trip is a route with timestamps; `stroke`, `strokeWidth`, `dash`,
  `opacity`, `headRadius` and `headFill` already exist on `route`.
- **Per-frame asset swapping.** Rejected: breaks the seek check and SREP 14's one-document rule.
- **A `timeline` element that drives every timed layer.** Rejected for now: `animate` keys on each element do
  the same with no new element; an author who wants one clock writes one key list and reuses it (open issue 2).
- **Interpolating the head along the great circle.** Rejected for the reference: the projected segment is what
  the route draws on screen; the difference is the segment's bulge (open issue 3).
- **Reading `timeBy` as an expression.** Rejected: SREP 9's style expressions live in the basemap style, not on
  `geoLayer`; a property name is enough and matches `fillBy` and `label`.

## Backwards compatibility

Additive. Documents without the new attributes are unchanged. SREP 9's rule that `global-state` evaluates to
null still holds on a basemap without `timeOrigin` and `time`. A `route` with `timeBy` is drawn by its
timestamps and ignores `progress`; without it `progress` applies as before. Schema version 1.8 (V17).

Properties that hold for every input: a frame's result is a pure function of the document and the composition
time; alphas lie in 0..1; a window's points are in stamp order with the head last; stroke coverage is symmetric
under reversing the polyline; the digests change whenever a drawn pixel changes by 1/1000.

### Kit cases

To be measured on the engine (SREP 14's seek check applies to each):

1. `events-trail`: seven point features over six hours with a one-hour fading trail and an end property; the
   drawn set and alphas at 0, 6 and 12 seconds equal the reference's, pixels within 1/255.
2. `trips-head`: two tracks with the default trail; at six seconds the first trip's head pixel is the
   reference's within 1e-3 and the second is pending; at twelve seconds both are gone.
3. `trips-short-trail`: trail 15 without fade; the window's tail is the interpolated point and every alpha 1.
4. `basemap-filter-time`: a style filter on `["global-state", "time"]`; kept features 1, 3 and 5 at 0, 6 and
   12 seconds.
5. `time-series-seek`: frames 0, 3, 6, 9 and 12 rendered alone equal the played frames pixel for pixel.
6. `time-series-errors`: the bad document; the engine reports TS1–TS4 and V17 and renders the valid remainder
   with W-TS1 and W-TS2.

## Open issues

1. Whether `trail` on `geoLayer` should default to 0 (forever) or to deck.gl's 120; the draft keeps forever
   because events without a trail are the common case.
2. A shared clock: a `timeline` element or an `@clock` reference so several elements follow one `animate`
   without repeating keys.
3. Great-circle interpolation of the head for long segments on a globe (rule 6 interpolates the projected
   segment).
4. Leap seconds: ISO 8601 times are read without them; the time-frames draft's `timeScale` could apply here.
5. Whether `W-TS2` should instead draw unreadable features untimed (always visible); the draft hides them so a
   broken column is noticed.
6. A `timeBy` on `pin` for events given as pins rather than geo features.
