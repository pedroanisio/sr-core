# SREP 0 — Add relief layers to the map

## Abstract

SREP 12's M1: the three MapLibre layer types that SREP 9 skips with a warning, **`raster`**, **`hillshade`** and
**`color-relief`**, are drawn by a **`basemap`**, and a new **`contours`** child of `map` draws level lines. A
basemap names elevation tiles with **`elevation`** (a tiles asset of **terrarium** or **mapbox** pixels, chosen by
**`encoding`**, SREP 10's decodings); heights are **signed**, so **bathymetry** shades, colours and contours like
land. Every frame assembles one **mosaic** of the visible tile set at SREP 9's raster tile zoom, bordered by one
pixel of the neighbouring tiles, x taken modulo 2^z across the **antimeridian** and rows beyond the **pole**s
extrapolated, so no **seam** appears across tiles, the poles or the antimeridian. The **Horn** gradient is taken
in metres per metre with the Mercator ground size of each row (R = **6378137** m). `hillshade-method` **basic**,
**combined**, **igor** and **multidirectional** reproduce **gdaldem**'s 8-bit levels (**GDAL**, **MIT**; the
**USGS** four-light weighting for multidirectional); **standard** is **MapLibre**'s legacy formula (**BSD-3**);
`color-relief-color` follows gdaldem's lookup; `raster` adjustments follow MapLibre's raster shader. Contours are
**marching squares** at pixel centres with the cell-mean **saddle** rule, chained into lines and cut at the
antimeridian, within **0.5 px** of **gdal_contour**. On a **globe** the layers join SREP 10's **drape** from a
whole-world mosaic at the drape's zoom, rows clamped beyond **85.0511**°. Rules RL1–RL6, W-RL1 and V17; the schema
files are unchanged, the diff is inside the draft. Reference module `conformance/tools/relief_reference.py`
(requires **numpy**); engine card SR-112.

## Motivation

SREP 9 brought vector and raster basemaps and SREP 10 raised the ground into a terrain grid, but a 2D map still
cannot show relief: `hillshade` and `color-relief` layers in a style are skipped, raster tiles take only the
basemap's `@opacity`, and there is no way to draw contour lines. Scenes about geography, climate, hydrology or
exploration want the shaded, coloured and contoured terrain every atlas has, and want the sea floor treated as
terrain too. SREP 12's M1 row asks for exactly MapLibre's three layer types, for contours by marching squares with
tile stitching, for bathymetry as signed elevation, for terrain on globes, and for reference tests against GDAL:
within 1 level of `gdaldem hillshade` and `gdaldem color-relief`, within 0.5 px of `gdal_contour`, and no seams
across tiles, poles or the antimeridian.

The definitions below are taken from their open implementations, so a scene author who tuned a hillshade in
MapLibre or in QGIS (GDAL) gets the same picture here, and a conformance test can compare against those tools
pixel for pixel.

## Specification

### Syntax

**`basemap`** gains two attributes:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `elevation` | IDREF | none | the tiles asset whose raster tiles encode heights; required for the style's `hillshade` and `color-relief` layers |
| `encoding` | terrarium or mapbox | terrarium | how the elevation tiles' pixels encode heights (SREP 10) |

**`contours`** is a new child of `map` (beside `basemap`, `geoLayer`, `graticule`, `route`, `pin` and `flyTo`),
drawn in document order like the others:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `id` | ID | none | identifier for animations and expressions |
| `elevation` | IDREF | required | the tiles asset whose raster tiles encode heights |
| `encoding` | terrarium or mapbox | terrarium | the tiles' height encoding |
| `interval` | positiveDecimal | 100 | metres between levels |
| `base` | decimal | 0 | a level every line passes through: levels are `base` + n · `interval` |
| `index` | positiveInteger | 5 | every `index`-th level counted from `base` is an index contour |
| `minLevel` | decimal | none | the lowest level drawn |
| `maxLevel` | decimal | none | the highest level drawn |
| `stroke` | paint | #5A3A1AB0 | paint of ordinary lines |
| `strokeWidth` | nonNegativeDecimal | 0.5 | width of ordinary lines in map pixels |
| `indexStroke` | paint | #5A3A1AFF | paint of index lines |
| `indexStrokeWidth` | nonNegativeDecimal | 1 | width of index lines in map pixels |
| `opacity` | unitDecimal | 1 | opacity of the lines |
| `detail` | double | 0 | tile zoom levels added to the zoom chosen for the view, as `basemap/@detail` |

**Style layers.** In a basemap's MapLibre style, three layer types are now drawn (they were skipped). Each
property is read as SREP 9 reads properties (constants, legacy functions or expressions evaluated at `z_style`;
a failing expression takes the default), with MapLibre's defaults:

| Layer | Property | Default | Read as |
|---|---|---|---|
| `raster` | `raster-opacity` | 1 | alpha multiplier |
| `raster` | `raster-hue-rotate` | 0 | degrees, period 360 |
| `raster` | `raster-brightness-min` | 0 | the black point |
| `raster` | `raster-brightness-max` | 1 | the white point |
| `raster` | `raster-saturation` | 0 | −1 … 1 |
| `raster` | `raster-contrast` | 0 | −1 … 1 |
| `raster` | `raster-resampling` | linear | linear or nearest, for overzoomed tiles |
| `hillshade` | `hillshade-method` | standard | standard, basic, combined, igor or multidirectional |
| `hillshade` | `hillshade-illumination-direction` | 335 | degrees clockwise from the top, a number or an array |
| `hillshade` | `hillshade-illumination-altitude` | 45 | degrees above the horizon, 0 … 90, a number or an array |
| `hillshade` | `hillshade-illumination-anchor` | viewport | viewport (relative to the frame's top) or map (north) |
| `hillshade` | `hillshade-exaggeration` | 0.5 | 0 … 1, scales the slope |
| `hillshade` | `hillshade-shadow-color` | #000000 | a colour or an array of colours |
| `hillshade` | `hillshade-highlight-color` | #FFFFFF | a colour or an array of colours |
| `hillshade` | `hillshade-accent-color` | #000000 | the standard method's accent |
| `color-relief` | `color-relief-color` | none | an interpolate or step expression over ["elevation"] |
| `color-relief` | `color-relief-opacity` | 1 | alpha multiplier |

`raster-fade-duration` has no meaning without interactive loading and is ignored. A `hillshade` or `color-relief`
layer whose basemap has no `@elevation` is skipped as today, and the engine reports warning W-RL1 naming the layer.

**Schema diff (applied on acceptance).** In `scene-render.xsd`, `basemapType` gains

```xml

<xs:attribute name="encoding" type="terrainEncodingType" default="terrarium"/>
```

(`terrainEncodingType` is SREP 10's enumeration of terrarium and mapbox); `mapAssetType`'s choice gains
`<xs:element name="contours" type="contoursType"/>`, and `contoursType` is a new complex type with the
`animationElements` group and the attributes of the table above. In `scene-render.sch`:

```xml
<sch:rule context="basemap[@elevation]">
  <sch:assert id="RL1" test="/scene/assets/tiles[@id=current()/@elevation]">basemap/@elevation must name a tiles asset.</sch:assert>
</sch:rule>
<sch:rule context="contours">
  <sch:assert id="RL1" test="/scene/assets/tiles[@id=current()/@elevation]">contours/@elevation must name a tiles asset.</sch:assert>

</sch:rule>
```

**Validation rules.**

- **RL1** — `basemap/@elevation` and `contours/@elevation` name a `tiles` asset.
- **RL2** — `contours/@interval` is positive and finite, `@index` at least 1, `@maxLevel` not below `@minLevel`,
  widths and opacity not negative; a frame whose levels would exceed 4096 draws no contours and is reported.
- **RL3** — `@encoding` is terrarium or mapbox.
- **RL4** — in a `hillshade` layer, `hillshade-method` is one of the five methods, the anchor viewport or map,
  the direction, altitude, shadow and highlight arrays have the same length (at least one), altitudes lie in
  0 … 90 and the exaggeration in 0 … 1; in a `raster` layer, `raster-resampling` is linear or nearest and the
  numeric properties lie in their ranges. As SREP 9 treats a failing expression, the property takes its default
  and the engine reports the layer.
- **RL5** — `color-relief-color` is `["interpolate", ["linear"], ["elevation"], e0, c0, …]` with at least one stop
  and strictly increasing elevations, or `["step", ["elevation"], c0, e1, c1, …]`; `color-relief-opacity` lies in
  0 … 1. Otherwise the layer is skipped and reported.
- **RL6** — a mosaic exceeds 8192 pixels along a side: the frame draws the layer from the archive's coarser
  tiles instead (the zoom is lowered until the bound holds) and the engine reports it.
- **W-RL1** — a `hillshade` or `color-relief` layer on a basemap without `@elevation`: skipped with a warning.
- **V17** — an unknown attribute on `basemap` or `contours` is an error.

### Semantics

The reference `conformance/tools/relief_reference.py` implements every rule; function names are in parentheses.

1. **Heights.** A pixel of an elevation tile is a height in metres by SREP 10's decodings (`decode`):
   terrarium h = R·256 + G + B/256 − 32768, mapbox h = −10000 + (R·65536 + G·256 + B)·0.1, alpha ignored.
   Heights are signed: a depth below sea level is a negative height, and no layer clamps at zero. A tile that is
   missing from the archive and has no ancestor (rule 2) is flat at h = 0.

2. **The mosaic** (`mosaic_zoom`, `mosaic`). A basemap's relief layers and a `contours` child read heights from
   one mosaic per frame at zoom z_m = SREP 9's raster `z_tile` (round(log2(2π·k/256) + `detail`), clamped to
   0 … 24) clamped to the archive's zoom range. The mosaic holds the tiles of the visible tile set (SREP 9) at
   z_m, each tile's pixels from its source square: the tile itself, else its first present ancestor down to the
   archive's minimum zoom with the square the tile covers resampled bilinearly at pixel centres
   (`source_square`, `resample`). Around the tiles lies a border of one pixel from the neighbouring tiles, tile
   x taken modulo 2^z_m (so the border wraps across the antimeridian) and the diagonal neighbours filling the
   corners; where no neighbour exists (a row beyond the world at the poles, or a tile the archive lacks) the
   border is extrapolated linearly, 2·edge − next, gdaldem's `-compute_edges` rule (`pad_grid`). The mosaic is
   bounded by 8192 pixels along a side (RL6). Because gradients and contours are computed on this one grid, a
   tile seam, the antimeridian and the poles leave no trace in the picture.

3. **The gradient** (`gradient`, `mosaic_gradient`). Horn's operator over the 3 × 3 neighbourhood of every mosaic
   pixel gives the gradient in height units per metre, east and north components

       gE = ((c + 2f + i) − (a + 2d + g)) / (8·s),   gN = ((a + 2b + c) − (g + 2h + i)) / (8·s)

   with a, b, c the row to the north, g, h, i the row to the south, d and f the pixels to the west and east, and
   s the ground size in metres of a pixel in that row, s = 2π·R·cos φ / (256·2^z_m), R = 6378137 m, φ the
   latitude at the row's centre (`pixel_size`, `row_latitude`). The slope used by every hillshade method is
   p = 2·e·(gE, gN), e = `hillshade-exaggeration`, so the default e = 0.5 shades the true slope (gdaldem with
   z-factor 1 and scale 1 on a raster in metres).

4. **Hillshade** (`shade_level`, `hillshade_pixels`). Let α be the first altitude in radians and θ the first
   direction, less the map's rotation at the current time when the anchor is viewport (`_azimuth`), in radians
   clockwise from north. The Lambert cosine of the slope under that light is

       c = (sin α − cos α·(pE·sin θ + pN·cos θ)) / sqrt(1 + pE² + pN²).

   The 8-bit level L of each method is gdaldem's (GDAL's x is west minus east, −pE, and its y north minus south,
   pN; levels round half up):

   - basic: L = 1 if c ≤ 0, else round(1 + 254·c);
   - combined: g = 1 − acos(c)·atan(|p|)·4/π², L = 1 if g ≤ 0, else round(1 + 254·g);
   - igor: slope strength atan(|p|)·180/π / 90, aspect atan2(−pN, −pE), aspect difference to 3π/2 − θ folded
     to 0 … π, aspect strength 1 − difference/π, L = round(255·(1 − slope strength · aspect strength));
   - multidirectional (USGS Open-File Report 92-422): with x = −pE, y = pN, the four lights 225°, 270°, 315° and
     360° at altitude α give v225 = max(0, sin α + (x − y)·cos 225°·cos α), v270 = max(0, sin α − x·cos α),
     v315 = max(0, sin α + (x + y)·cos 225°·cos α), v360 = max(0, sin α − y·cos α), weights
     W225 = ½(x² + y²) − xy, W270 = x², W315 = (x² + y²) − W225, W360 = y², and
     L = round(1 + 127·Σ W·v / (x² + y²) / sqrt(1 + x² + y²)); flat ground (x = y = 0) has L = round(1 + 254·sin α).

   The level becomes a premultiplied colour (`shade_colour`): with s = (L − 1)/254, s above ½ draws the first
   highlight colour at alpha 2s − 1, s below ½ the first shadow colour at alpha 1 − 2s, and s = ½ nothing. Igor
   draws instead shadow · (slope strength · aspect strength) + highlight · (slope strength · (1 − aspect
   strength)). Standard is MapLibre's legacy shader with deriv = (pE, −pN) and azimuth θ + π: slope = atan(0.625·
   |p|), aspect = atan2(−pN, −pE) (±π/2 when pE = 0), base = 1.875 − 1.75e, scaledSlope = slope when e = ½, else
   ((base^slope − 1)/(base^(π/2) − 1))·π/2; accent colour (1 − cos scaledSlope)·accent·min(1, 2e); shade =
   |mod((aspect + θ + π)/π + ½, 2) − 1|; shade colour mix(shadow, highlight, shade)·sin(scaledSlope)·min(1, 2e);
   result accent colour·(1 − shade alpha) + shade colour. Only the first entry of each array is used by every
   method (open issue 2). The layer composites over what is below it; the basemap's `@opacity` multiplies.

5. **Colour relief** (`relief_stops`, `relief_colour`, `relief_pixels`). The expression's stops are (elevation,
   colour) pairs; step mode prepends (−∞, c0). A height h takes gdaldem's lookup: the first colour when h is at or
   below the first elevation, the last when above the last, a stop's colour exactly at it, otherwise between the
   neighbouring stops with ratio r = (h − e0)/(e1 − e0) and each 8-bit channel int(0.5 + c0 + r·(c1 − c0)),
   clamped to 0 … 255; step mode takes the last stop at or below h. The colour's alpha times
   `color-relief-opacity` premultiplies it.

6. **Raster** (`raster_pixels`, `sample`). A raster tile's pixel, overzoomed by `raster-resampling` (bilinear at
   pixel centres, or nearest), is adjusted as MapLibre's raster shader does: un-premultiply; alpha ×
   `raster-opacity`; hue rotation by the spin weights w = ((2c + 1)/3, (−√3·s − c + 1)/3, (√3·s − c + 1)/3) of
   the angle (r', g', b') = (r·w0 + g·w1 + b·w2, r·w2 + g·w0 + b·w1, r·w1 + g·w2 + b·w0); saturation
   rgb += (average − rgb)·f with f = 1 − 1/(1.001 − sat) for sat > 0, else −sat; contrast rgb = (rgb − ½)·f + ½
   with f = 1/(1 − con) for con > 0, else 1 + con; brightness rgb = min + rgb·(max − min); clamp to 0 … 1;
   premultiply. A raster basemap without a style draws as a `raster` layer with defaults, which is what it drew
   before.

7. **Contours** (`levels`, `marching_squares`, `contours`). The levels are `base` + n·`interval` for every
   integer n with min(h) ≤ level ≤ max(h) over the mosaic, narrowed to `minLevel` … `maxLevel`; more than 4096
   is RL2. For each level, marching squares over the mosaic's padded grid, pixel (i, j) at (i + ½, j + ½): a
   pixel at or above the level is inside; in each cell of four pixel centres the crossing on an edge is placed
   by linear interpolation, t = (level − h0)/(h1 − h0); the two saddle cases join the inside corners when the
   cell's mean is at or above the level and separate them otherwise; crossings are chained into lines, closed
   lines repeating their first point. Line vertices are world pixels from the mosaic's origin, cut where they
   cross x = 0 or x = 256·2^z_m and wrapped into the world (`_split_at_world_edges`), then longitude and
   latitude by the inverse Web Mercator, and drawn through the map's projection like `geoLayer` lines. A level
   whose n is a multiple of `index` is an index contour drawn with `indexStroke` and `indexStrokeWidth`; the
   others with `stroke` and `strokeWidth`; `@opacity` multiplies. Lines run unbroken through tile seams and
   across the antimeridian, where the two pieces meet at ±180°.

8. **Globe** (`globe_mosaic_zoom`, `globe_row`, `globe_drape_heights`). On a `globe` (SREP 10) the relief layers
   and contours are part of the drape, laid out in its equirectangular frame of 2T × T pixels. Their mosaic is
   the whole world at zoom round(log2(2T/256) + `detail`), clamped as in rule 2, with x wrapping. A drape pixel
   at longitude λ and latitude β samples the mosaic bilinearly at column (λ + 180°)/360°·256·2^z − ½ (wrapped)
   and at the Mercator row of β clamped to the first and last rows beyond ±85.0511° (the Mercator limit,
   atan(sinh π)), so the polar caps take the nearest row's heights and shade. The hillshade azimuth is relative
   to north (the drape's up) whatever the anchor. Contours are cut at ±180° as in rule 7, so the drape's left and
   right edges meet on the sphere.

9. **Bathymetry.** Nothing distinguishes the sea floor: a negative height has a gradient, a level and a colour
   like a positive one. `base` 0 puts a contour on the coastline; a `color-relief-color` with stops below zero
   colours depths; a terrarium archive carries −32768 … 32767 m, a mapbox archive −10000 … 1677721 m.

10. **Order and every frame alone.** Layers draw in style order among the basemap's other layers; `contours`
    draw in document order among the map's children. A frame reads only its own tiles (SREP 14): tiles are
    resolved as SREP 9 and SREP 10 resolve them, the `elevation` archive's tiles at z_m of the frame's visible
    set, and for a globe the whole world at the drape's zoom.

## Rationale

- **Formulas from the tools people use.** gdaldem is the reference the card names and what QGIS runs; MapLibre is
  the style vocabulary SREP 9 adopted. Taking the four GDAL methods from `gdaldem_lib.cpp` and standard from
  MapLibre's shader lets the conformance tests compare pixels instead of impressions, and lets an author move a
  style between MapLibre and this engine.
- **Slopes in metres per metre.** MapLibre scales its derivative by an ad-hoc power of the zoom; GDAL by the
  raster's resolution. Taking the gradient in metres per metre with the ground size of the pixel's row makes the
  default exaggeration ½ the physical slope and keeps the picture consistent across zooms and latitudes.
- **One mosaic with a borrowed border.** Shading a tile alone needs its neighbours' edge pixels or it shows a
  seam; MapLibre borders every DEM tile with its neighbours for the same reason. One padded grid per frame does
  this once and also lets contours run through seams and wrap.
- **gdaldem's edge rule.** Where no neighbour exists, 2·edge − next keeps a plane's slope to its edge (edge
  replication would halve it); this is `-compute_edges`.
- **Contours at pixel centres.** gdal_contour places vertices between pixel centres by linear interpolation; so
  does marching squares here, which is why the 0.5 px bound holds.

## Rejected alternatives

- **Tile-by-tile hillshade without a border.** Shows a seam at every tile edge; rejected by the card.
- **MapLibre's zoom-dependent derivative scaling.** Not physical, differs from GDAL, and would make exaggeration
  mean different things at different zooms.
- **Contours as a vector tile product (pre-computed).** Needs a second archive per interval; computing them from
  the elevation tiles keeps one source and lets `interval` and `base` animate.
- **A `hillshade-opacity`.** MapLibre has none; the basemap's `@opacity` and the colours' alpha suffice.
- **Clamping depths at zero.** The card asks for bathymetry as signed elevation.

## Backwards compatibility

Additive. Styles that already contain `raster`, `hillshade` or `color-relief` layers were skipped with a warning;
a `raster` layer now adjusts the tiles (with all defaults it draws them as before), and `hillshade` and
`color-relief` layers stay skipped (W-RL1) until the basemap names `@elevation`. A raster basemap without a style
draws exactly as before. Existing documents validate unchanged; `contours` is a new element.

The properties: `decode` agrees with `terrain_grid_reference.decode` and `encode` inverts it within the
encoding's step; a plane's Horn gradient is its gradient up to the grid's edge and a plane shades uniformly;
flat ground is level 181 (basic, multidirectional) and 255 (combined, igor); a slope facing the light is
brighter than one facing away for every method; exaggeration scales the slope; the viewport anchor turns the
light with the map; the mosaic's border holds the neighbours' pixels, wraps across the antimeridian and
extrapolates beyond the poles, and a mosaic cut at a tile seam shades the same pixels as the whole; signed
heights shade like positive ones; colour relief clamps at the ends and interpolates with gdaldem's rounding;
the raster shader's factors are MapLibre's; a cone's contour rings lie within 0.5 px of their circles; saddles
follow the cell mean; contours cross tile seams unbroken and are cut at ±180°; the drape clamps beyond the
Mercator limit and wraps in longitude; the example runs the same twice; validation reports one code at a time.
When GDAL is installed, the hillshade levels of the four GDAL methods and the colour relief are within 1 level
of `gdaldem` on a 48 × 48 synthetic DEM with `-compute_edges`, and every contour vertex is within 0.5 px of
`gdal_contour`'s lines; without GDAL those three tests are skipped and reported as such.

## Open issues

1. **The visible tile set of the mosaic.** The reference takes the frame's world-pixel rectangle at the mosaic
   zoom; SREP 9's quadtree walk with the projection's clipping gives the same tiles for a Web Mercator map
   without rotation and is the rule for every other view.
2. **Light arrays.** MapLibre's multidirectional averages the lights of its arrays; this draft's multidirectional
   is gdaldem's fixed four lights, as the card's reference is gdaldem, and every method reads the first entry of
   each array. An engine may offer MapLibre's averaging under a later SREP.
3. **Hillshade on non-Mercator maps.** Rule 3's ground size assumes Web Mercator tiles; on another projection the
   mosaic is still Mercator and the layer is warped with the tiles (SREP 9), so the lighting stays in the
   tiles' frame. Terrain in other projections is left to a later SREP, as SREP 10 left it.
4. **Overzoom beyond 8192 pixels.** RL6 lowers the zoom; a tiled evaluation (shading each tile with its border)
   would allow finer views at the cost of the single-grid contour chaining.
5. **Contour smoothing and labels.** gdal_contour has neither; a `smooth` attribute and level labels are left to
   a later SREP once the lines are stable.
6. **Nodata.** The encodings have no nodata value; SREP 10's "missing tile is flat" rule is kept. An archive
   with a declared nodata colour (open issue in SREP 10) would need a mask here too.
7. **Expressions with `["elevation"]`** are read only inside `color-relief-color`; elsewhere `elevation`
   evaluates to null as the other unsupported operators do.
