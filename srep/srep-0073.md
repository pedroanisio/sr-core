# SREP 73 — Let flock agents keep their sprites upright (`flock/@orientToVelocity`)

## Abstract

`flock` gains `orientToVelocity`, a boolean that defaults to `true`, which is today's behaviour. With `false`, each
agent's disc or sprite keeps rotation 0 in the flock node's own space, so a sprite of a bird, a fish or a card stays
upright while the agent steers. The name and meaning are those of the existing `particleEmitter/@orientToVelocity`.
A `streak` is drawn along the velocity by definition, so the attribute is inert on streaks and is reported as
`INERT-I16`.

## Motivation

A film probe (internal, 2026-10-08, "swarm") used a flock of chips with the sprite "IA". On the leftward leg of the
orbit the sprite turned upside down and read as "VI". The probe recorded this as a limitation: a `particleEmitter`
keeps sprites upright, but its agents are not boids. The plan lists the fix as B3: "an attribute that keeps sprites
upright (today they always point along their velocity)".

**Checked in the reference** (`rs-scene-render` commit `c09b58a`):

- `crates/sr-eval/src/agents.rs:421` sets `orient: true` for every flock frame.
- `agents.rs:428` sets each agent's rotation to `atan2(v_y, v_x)` in degrees.
- The XSD annotation of `flockType` says agents are "drawn like particles (disc, streak or sprite), oriented to their
  velocity".
- `particleEmitterType` already has `orientToVelocity` (`xs:boolean`, default `false`, schema 1.5.0), which particles
  read.

## Specification

### Syntax

```xml
<!-- flockType gains -->
<xs:attribute name="orientToVelocity" type="xs:boolean" default="true">
  <xs:annotation><xs:documentation>true (the default): each agent's disc or sprite is turned to point along its velocity.
  false: it keeps rotation 0 in the flock's space. Streaks always follow the velocity. SREP 73.</xs:documentation></xs:annotation>
</xs:attribute>
```

The `flockType` annotation changes from "oriented to their velocity" to "oriented to their velocity unless
`orientToVelocity` is false".

Schematron: none. The inert case is a validator finding (SREP 18 and 34), not a rule.

### Semantics

1. **`true`.** An agent's disc or sprite is rotated by `atan2(v_y, v_x)` (degrees, clockwise-positive with +y down),
   where v is its velocity in the flock's space, as today.
2. **`false`.** The rotation is 0 in the flock's space: the sprite's +x axis is the flock's +x axis. The flock
   node's own transform (rotation, scale, skew, parents) still applies to the whole flock.
3. **Streaks.** `shape="streak"` is drawn along the velocity whatever the value. A validator SHOULD report
   `orientToVelocity="false"` on a streak flock as `INERT-I16`, at information severity, like the other INERT
   findings of SREP 34. The document stays valid.

### Errors

None. `INERT-I16` is a finding, not an error.

### Defaults and the neutral case

The default is `true`, which is today's behaviour (agents.rs:421, 428).

## Rationale

- **The same name as the particle attribute**, so an author who knows one knows the other. The defaults differ
  (true for flocks, false for particles) because each keeps its own element's current behaviour. A shared default
  would change existing flock documents.
- **A boolean, not an angle offset.** The probe needed upright sprites. An offset (`orientOffset`, as on
  `motionPath`) can be added later without changing this attribute.

## Rejected alternatives

- **`autoOrient`** (the `motionPath` and `transformConstraint` name): it describes path following. The particle name
  matches what the flock draws.
- **Changing the default to false**: it would turn every existing flock's sprites. That is a MAJOR change under
  SREP 4.

## Backwards compatibility

The change is MINOR: one attribute whose default is today's behaviour.

## Conformance

The cases are in `conformance/srep_cases/srep-0073.json`. They are written, with the sprite
`srep_cases/assets/srep73-halves.png` (left half red, right half blue), by `conformance/tools/srep73_cases.py`.

- **Placement.** A one-agent flock in a 1 × 1 box has its agent within 1 px of the node's origin at time 0. The
  reference draws initial positions inside the box: `crates/sr-sim/src/flock.rs`, `init`.
- **Assumption, not checked:** a sprite is drawn as a `size` × `size` square centred on the agent. The sprite is
  40 × 40 and drawn at `size="40"`, one texel per pixel, so that the halves' widths do not depend on how an engine
  filters a magnified image, which this SREP does not specify.

Which cases are pending, and why, is in `conformance/tools/kit_pending.py` (Engine impact).

| Case | Checks | Tolerance |
|---|---|---|
| `srep-0073-upright-sprite` | with `false`, red is left of blue at the same height (2) | 2 px |
| `srep-0073-upright-sprite-node-rotation` | the node's rotation of 90° still turns the upright sprite: red above blue (2) | 2 px |
| `srep-0073-streak-inert` | `false` on a streak flock: valid, INERT-I16 (3) | exact |
| `srep-0073-default-no-finding` | no finding without the attribute | exact |
