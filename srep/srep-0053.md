# SREP 53 — Add a hold argument to `wiggle`

## Abstract

`wiggle(freq, amp, octaves, ampMult, t)` returns a continuous value. A sixth argument, `hold`, a time in seconds, holds
the wiggle for that long at a time, so it jumps instead of gliding: the stepped look of animating on twos or threes. A
call with five arguments or fewer is unchanged.

## Motivation

The NOLN motion research (§1.4, item E9, "wiggle on-twos option; manual quantisation only"): with the Rust reference an
author who wants a stop-motion jitter has to compute the quantised time by hand and pass it as the fifth argument, in
every expression.

## Specification

### Syntax

```xml
None.
```

```xml
None.
```

The documentation of `expression` lists `wiggle(freq, amp[, octaves, ampMult])`; it gains `[, t, hold]`.

### Semantics

`wiggle(freq, amp, octaves, ampMult, t, hold)`: when `hold` is a number greater than 0, the time `t` the noise is read at
(the fifth argument, else `time`) is replaced by `h · ⌊t / h + 10⁻⁹⌋` with `h = hold`; the rest of the definition is
unchanged. `hold` of 0, negative or not finite leaves `t` as it is. Because the fifth argument must be given to give the
sixth, `wiggle(2, 10, 1, 0.5, time, 1/12)` holds each value for 1/12 s.

### Defaults and the neutral case

No sixth argument: `t` is used as before.

## Rationale

- **In the function**, because the quantum belongs to the noise lookup, not to the expression's result (quantising the
  result would hold the sum of the base value's own motion too).
- **A time in seconds**, as the fifth argument is; an author states "twos at 24 fps" as `2/24`.
- **The 10⁻⁹ guard** is the one the engine's own frame arithmetic uses (`⌊t · fps + 10⁻⁹⌋`), so a boundary time reads the new hold.

## Rejected alternatives

- **A named option** (`wiggle(..., {hold: 0.08})`): the expression subset has no objects.
- **A project-level on-twos switch**: it would change every wiggle and every key, and the research asks for the wiggle.

## Backwards compatibility

Class: Added argument, MINOR. A document valid and rendered before is unchanged; one that uses the sixth argument needs
an engine that has it (an older engine fails to compile the call: wrong number of arguments).
