# SREP 81 — Clarify SREP 40 annotations (documentation only)

## Abstract

The reference engine's copy of the schema documents five SREP 40 declarations more fully than sr-core 1.5.0 does,
words one SREP 40 rule message differently, and differs in three blank lines. This SREP takes that text upstream, so
that after SREPs 76 to 81 the engine can vendor sr-core's XSD and Schematron byte for byte. No declaration, default or rule test changes; no document changes its verdict or its picture.
SREP 27 is the precedent.

## Motivation

This is one of six SREPs (76 to 81) that take upstream what the reference engine's vendored schema has and sr-core 1.5.0 lacks, so that the engine can vendor sr-core's XSD and Schematron byte for byte again. `conformance/tools/engine_gap.py` measures the gap between sr-core at tag schema-1.5.0 and the engine at commit 4bf7a9e (whose `schema/UPSTREAM` cites schema-1.5.0 at 3f14a20): every element, attribute, enumeration value, documentation block and Schematron pattern, rule, let and assertion the engine has and sr-core lacks or words differently, 222 items, with the engine commit that introduced each one, in `conformance/tools/engine-gap-1.5.0.json`. None of them belongs to SREPs 66 to 75 (the tool checks their declarations and rule ids), the engine has nothing that sr-core has and it lacks, and no new rule id collides with an existing one. This SREP takes 8 of them: 2 XSD items added and 5 changed, 0 Schematron items added and 1 changed.

The engine kept these changes in its copy because they were made after the 1.3.0 vendoring and never went upstream
(`conformance/tools/engine-gap-1.5.0.json`, feature `annotations`). Two of them only bring the XSD in line with what
SREP 40's own text already says; one corrects a sentence of SREP 40's text that the engine found wrong.

## Specification

The documentation and one message change. Set aside documentation, assertion messages and whitespace between
elements, and the files after this SREP are the files before it: the measurement finds no other item of this SREP
(Provenance).

1. **`attributeGroup pyroCrater`.** Adds: "`velocityX`, `velocityY` and `velocityZ` of an impulse and `velocityRateX`,
   `velocityRateY` and `velocityRateZ` of a source stay authorable with `crater`: the push is added to the cloud of the
   impact (in the volume's axes) and is not derived from it." SREP 40 never forbade these attributes on a pyro source or
   impulse with `crater`; the sentence says what the engine does with them. Engine commit 928c683 (2026-10-06), with
   the corpus document `tests/corpus/valid/pyro-crater-push.scene.xml` that holds it.
2. **`particles3DType/@gas`.** "the smoke is simulated as far as the particles need, before them in the frame" becomes
   "particles run before the smoke in the frame and ask it, in order, for the steps they need, so that it is simulated
   once for each of its steps". This corrects the order of evaluation, not a result: SREP 40 already requires that any
   order of frames gives the same bits. The engine measured the old order simulating 69 smoke steps where 30 were
   needed (its proposal, test `gas_and_splash`, commit 8c3ed9b). Engine commit a26493f (2026-10-06). The same sentence
   of SREP 40's text (§ particles3D, "The smoke is simulated as far as the particles need, and first in the frame when a
   document names a gas") is amended to read as the annotation does.
3. **`burst3DType/@angle` and `@angleSpread`.** Each gains a documentation: the launch angle above the tangent plane,
   engine default 45 degrees; the half-width of its uniform spread, engine default 15 degrees; neither is an XSD
   default, so that both can be refused on a burst that is not from a crater (P3D9). SREP 40's attribute inventory
   already gives 45 and 15 as the engine's defaults. Engine commit 928c683.
4. **Rule P3D10's message** gains "(default 45)" and "(default 15)". The test of the rule does not change.
   Engine commit 928c683.
5. **`oceanType/@bodyDrag`.** "Default 1.0." becomes "Default 1.0, the engine's: not an XSD default, so that the
   attribute can be refused on an ocean without `colliders` (OCN9)." Engine commit 928c683.
6. **Whitespace.** A blank line before `burst3DType` and before `craterType`, and none before `</xs:schema>`. These
   come from the engine's merge of 2026-10-06, which it made by component; they carry nothing, and are here only so
   that the files match byte for byte.

## Rationale

The aim is a byte-equal vendoring: the engine's files and sr-core's must not differ by anything, so that a diff
between them is empty and any later difference is a new proposal. Taking the engine's wording is right here because
items 1 and 3 to 5 say what SREP 40 already decided, and item 2 is a correction the engine measured.

## Rejected alternatives

- **Leave the documentation differences in the engine's copy.** Then the vendoring is not byte-equal and every later
  comparison has to explain these lines again.
- **Fold these into the feature SREPs (76 to 80).** They belong to SREP 40's declarations, not to any of the new
  features, and SREP 27 set the precedent of a documentation-only SREP.
