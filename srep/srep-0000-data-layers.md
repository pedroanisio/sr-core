# SREP 0 — Add data layers to the map

## Abstract

SREP 12's M2: three things a MapLibre style can ask for and SREP 9 does not draw. A **`heatmap`** layer sums a
**Gaussian** kernel over its features' vertices at pixel centres and colours the density with its ramp over
**`heatmap-density`** (MapLibre's heatmap shaders: peak weight × intensity × **0.3989422804014327**, the quad cut
where the kernel falls below **1/4080**). A **`fill-extrusion`** layer draws its features' **roofs** on a 2D map,
lit by the style's root **`light`** exactly as MapLibre's vertex shader lights an upward face (**ambient** 0.03,
the **luma** mix, the light-colour floors), and becomes the prisms of SREP 10's **`buildings`** on a 3D map, with
the vertical gradient on the **walls**. A **`symbol`** layer draws **icons** from sprite sheets: a new **`sprite`**
child of **`basemap`** names the sheet's index and image assets (**`name`**, **`index`**, **`image`**; the style's
sprite URL is never fetched), and the icon box, rotation, text fit, overlap modes (**never**, **always**,
**cooperative**), optional flags and SDF colouring follow MapLibre's `shapeIcon`, `fitIconToText`,
`getOverlapMode` and `symbol_sdf` shader, placed together with SREP 9's text labels. Every pixel is defined:
densities are **premultiplied** ramp colours, sprites are sampled **bilinear**ly, polygons fill under the
**non-zero** rule, SDF edges are the shader's **smoothstep**. Validation rules DL1–DL7, warning W-DL1 and the
schema gate V17. Reference `conformance/tools/data_layers_reference.py` (**numpy**), tests
`tests/test_data_layers.py`. Engine card [SR-113](https://faz-ai.atlassian.net/browse/SR-113).

## Motivation

SREP 12 lists, under M2, the map data layers that science explainers use and the format cannot draw: density
maps of events (earthquakes, cases, sightings), extruded footprints coloured by data, and point symbols from a
sprite sheet. SREP 9 draws `fill`, `line`, `circle` and the text of `symbol`; it skips `heatmap` and
`fill-extrusion` with a warning and draws no icons, and its `heatmap-density` evaluates to null. SREP 10 extrudes
building footprints at fixed attributes but ignores the style's `fill-extrusion` layers. Authors reach for
MapLibre styles that already carry these layers (the MapLibre render-test fixtures are a ready corpus), so the
format MUST draw them, deterministically, from the same style properties.

## Specification

### Syntax

`basemap` gains `sprite` children and the attribute `icons`.

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `icons` | boolean | true | draws the `symbol` layers' icons; false draws none (text labels follow `labels`) |

`sprite` (child of `basemap`, repeatable):

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `name` | NCName | default | the sprite id the style's `sprite` entries use; `default` names the plain `icon-image` namespace |
| `index` | IDREF | required | a `file` asset holding the sprite index JSON (entries with `x`, `y`, `width`, `height`, `pixelRatio`, `sdf`) |
| `image` | IDREF | required | an `image` asset holding the sheet (PNG, straight RGBA) |

Style properties this SREP reads (MapLibre style specification v8; defaults in the reference module):

| Layer | Properties |
|---|---|
| `heatmap` | `heatmap-radius` 30 (px, ≥ 1), `heatmap-weight` 1 (≥ 0, per feature), `heatmap-intensity` 1 (≥ 0), `heatmap-color` (ramp over `["heatmap-density"]`; the specification's blue–royalblue–cyan–lime–yellow–red default), `heatmap-opacity` 1 |
| `fill-extrusion` | `fill-extrusion-height` 0 and `fill-extrusion-base` 0 (metres, per feature), `fill-extrusion-color` #000000 (per feature), `fill-extrusion-opacity` 1, `fill-extrusion-vertical-gradient` true, `fill-extrusion-translate` [0, 0], `fill-extrusion-translate-anchor` map |
| root `light` | `anchor` viewport, `position` [1.15, 210, 30], `color` #ffffff, `intensity` 0.5 |
| `symbol` layout | `icon-image`, `icon-size` 1, `icon-anchor` center, `icon-offset` [0, 0], `icon-rotate` 0, `icon-padding` [2], `icon-allow-overlap` false, `icon-overlap`, `icon-ignore-placement` false, `icon-optional` false, `icon-rotation-alignment` auto, `icon-pitch-alignment` auto, `icon-keep-upright` false, `icon-text-fit` none, `icon-text-fit-padding` [0, 0, 0, 0], `symbol-placement` point, `symbol-spacing` 250, `symbol-sort-key`, `symbol-z-order` auto, `symbol-avoid-edges` false |
| `symbol` paint | `icon-opacity` 1, `icon-color` #000000, `icon-halo-color` rgba(0,0,0,0), `icon-halo-width` 0, `icon-halo-blur` 0, `icon-translate` [0, 0], `icon-translate-anchor` map |
| root `sprite` | a URL, or an array of `{id, url}`; the URL is matched to a `sprite` child by `id` = `name` and never fetched |

**Validation** (an engine reports every rule it can check; the first six are checked when the style is read):

- **DL1** (error): a `sprite` child whose `index` is not a `file` asset or whose `image` is not an `image` asset.
  The basemap draws without that sprite.
- **DL2** (error): a sprite index entry without `x`, `y`, `width` and `height`, with a non-positive `pixelRatio`,
  empty, or lying outside its sheet.
- **DL3** (error): `heatmap-radius` below 1, a negative `heatmap-weight` or `heatmap-intensity` constant, or
  `heatmap-opacity` outside 0..1.
- **DL4** (error): a `light` whose `anchor` is not `map` or `viewport`, whose `position` is not three numbers,
  whose `intensity` lies outside 0..1 or whose `color` is not a colour.
- **DL5** (error): a `symbol` layout or paint value outside its enumeration or range (`icon-anchor`,
  `icon-overlap`, `icon-text-fit`, `symbol-placement`, `icon-rotation-alignment`, `icon-pitch-alignment`,
  `symbol-z-order`, `icon-translate-anchor`; negative `icon-size`, `icon-halo-width` or `icon-halo-blur`;
  `icon-opacity` outside 0..1; an `icon-padding` that is not one number or four), or a `fill-extrusion` paint
  outside its range (`fill-extrusion-opacity` outside 0..1, a non-boolean `fill-extrusion-vertical-gradient`,
  an anchor that is not `map` or `viewport`, a colour that is not a colour).
- **DL6** (error): a `heatmap-color` that is not an `interpolate` (`linear` or `exponential`) or `step` ramp over
  `["heatmap-density"]` with increasing stops (at least two for `interpolate`).
- **DL7** (error): two `sprite` children of one basemap with the same `name`.
- **W-DL1** (warning): an `icon-image` that names no entry of the basemap's sprites, or a prefixed name whose
  sprite id has no `sprite` child; the symbol has no icon and is reported once per layer.
- **V17** (error): `sprite` children or `@icons` in a document before version 1.8, or an attribute `spriteType`
  does not declare.

Rules RL1–RL6 of the relief draft and SREP 9's rules are unchanged. The Schematron asserts above are the diff
this draft proposes; the engine checks DL2–DL6 and W-DL1 when it reads the style and the sprites.

### Semantics

All computations are in the map's pixels (SREP 9: Web Mercator, R = 6378137 m, tile size 256, the map's zoom,
centre and rotation) on the first basemap's visible tile set; features whose first vertex falls in a tile outside
the visible set, or in a tile the archive lacks, are not drawn. Colours are premultiplied floats; a layer's pixels
are composited over the pixels below it in SREP 9's paint order, each primitive at the basemap's `@opacity`.

1. **Heatmap density.** For a `heatmap` layer every vertex of every feature (Point, MultiPoint, the points of
   lines, the vertices of polygon rings without the closing repeat; MapLibre's circle bucket) is a kernel centre
   `c` with weight `w` = `heatmap-weight` evaluated for the feature (negative values read as 0), radius `r` =
   `heatmap-radius` (px) and intensity `I` = `heatmap-intensity`. The density at a pixel centre `p` is the sum
   over centres of `kernel(|p − c|², r, w, I)` = `w · I · G · exp(−4.5 · |p − c|² / r²)` with `G` =
   0.3989422804014327 (`kernel`, `density`), where a centre contributes only inside the square `|px − cx| ≤ e`
   and `|py − cy| ≤ e` of half-side `e` = `r · sqrt(−2 ln(Z / (w · I · G))) / 3` (the quad MapLibre's vertex
   shader draws, `kernel_extent`), `Z` = 1/255/16 = 1/4080; a centre whose peak `w · I · G` is at most `Z` draws
   nothing. The density `t` is not clamped while summing (`density`).
2. **Heatmap colour.** `heatmap-color` is a ramp over `["heatmap-density"]` (`ramp_stops`); within the ramp,
   `heatmap-density` evaluates to `min(1, max(0, t))` (this amends SREP 9's null). `interpolate` interpolates
   the stops' straight RGBA linearly, or with MapLibre's exponential factor `(base^(t − t0) − 1) / (base^(t1 −
   t0) − 1)`, and `step` takes the last stop not above `t`; the result is premultiplied (`ramp_colours`). A
   pixel with `t` = 0 is transparent. The layer's pixels are that colour × `heatmap-opacity` × `@opacity`
   (`heatmap_pixels`), composited at the layer's position in SREP 9's order.
3. **The light.** The style's root `light` (defaults above, `light`) gives the direction `L` = MapLibre's
   `sphericalToCartesian` of `position` = (radial, azimuthal, polar): with `a` = azimuthal + 90° and `p` = polar,
   `L` = radial · (cos a sin p, sin a sin p, cos p); with `anchor` `viewport` the (x, y) part is turned by the
   map's rotation, with `map` it is not (`light_direction`). The default is (0.2875, −0.4980, 0.9959).
4. **Lit colour.** A face with unit normal `n` and straight colour `(r, g, b, a)` is shaded as MapLibre's
   `fill_extrusion` vertex shader does (`shade`): `rgb` ← `(r, g, b) · a`; `luma` = 0.2126 r + 0.7152 g +
   0.0722 b of that; `rgb` ← `rgb` + 0.03 (the ambient term); `d` = clamp(`n · L`, 0, 1); `d` ← mix(1 − `I`,
   max(1 − `luma` + `I`, 1), `d`) with `I` the light's intensity; on a wall (`n` not vertical) with
   `fill-extrusion-vertical-gradient` true, `d` ← `d` · clamp(`(t + base) · sqrt(height / 150)`, mix(0.7, 0.98,
   1 − `I`), 1) where `t` is 1 at the wall's roof edge and 0 at its foot and `base`, `height` are the feature's
   metres; each channel is then clamp(`rgb` · `d` · `lightcolour`, mix(0, 0.3, 1 − `lightcolour`), 1) and the
   result, alpha `a`, is multiplied by `fill-extrusion-opacity` × `@opacity`. Roofs take no gradient.
5. **Extrusions.** For each feature of a `fill-extrusion` layer, `top` = max(0, `fill-extrusion-height`) and
   `base` = max(0, `fill-extrusion-base`) evaluated for the feature; a feature whose `top` is not above its
   `base` (including a missing height) is skipped (`extrusion`). On a 2D map (`map`, SREP 9) the layer draws the
   roofs: each polygon (with its holes, non-zero winding at pixel centres, `fill_polygon`) filled with the lit
   colour of the upward normal (0, 0, 1), features in tile and feature order, each over the previous
   (`roof_pixels`); `fill-extrusion-translate` shifts the footprints by its pair in pixels (anchor `map`: turned
   with the map's rotation; `viewport`: as is). Walls are not drawn on a 2D map.
6. **Prisms.** On a 3D map (`primitive="map"`, SREP 10) with `@buildings`, when the first basemap's style has
   `fill-extrusion` layers, the buildings are those layers' features in place of SREP 10's `building(s)` rule:
   each feature with `top` above `base` becomes a prism per polygon between `base` and `top` metres (SREP 10's
   scale, clipping and terrain placement), with the feature's `fill-extrusion-color` as the prism's base colour
   under `@material` (`prisms`, `building_prisms`). The scene's lights light the prisms; the style's `light` and
   the vertical gradient apply to the 2D roofs only. Without `fill-extrusion` layers SREP 10's rule stands.
7. **Sprites.** Each `sprite` child supplies a sheet: its index entries (`sprite_index`) have the pixel rectangle
   (`x`, `y`, `width`, `height`), `pixelRatio` (default 1; the display size is width/ratio × height/ratio pixels)
   and `sdf` (default false). The style's `sprite` entries are matched to children by id = `name`; a plain
   `icon-image` name is looked up in the `default` child, `id:name` in the child named `id` (`sprite_name`). The
   style's URLs are never fetched (rendering never fetches, SREP 9). Entries with `stretchX`, `stretchY` or
   `content` are drawn whole (see Open issues).
8. **Icon candidates.** With `@icons` true, every `symbol` layer whose layout has `icon-image` contributes one
   icon per anchor of SREP 9's rule (`candidate_anchors`: each point of a Point, the mean of the vertices of a
   Polygon's largest ring, the midpoint by length of each line piece for `symbol-placement` `line`, of the whole
   line for `line-center`, none for lines placed as points) for every feature whose `icon-image` (a constant, a
   `{token}` string or an expression) names a sprite entry; a name with no entry is W-DL1 and gives no icon. With
   `s` = `icon-size`, anchor fractions `(ax, ay)` of `icon-anchor` (left 0, centre ½, right 1; top 0, bottom 1)
   and the entry's display size `(w, h)`, the unrotated box's top-left is `q + s · (icon-offset − (ax · w, ay ·
   h))` and its size `s · (w, h)` (`icon_box`; `icon-offset` is in icon pixels, multiplied by `icon-size`). The
   box is turned clockwise about `q` by `icon_rotation`: `icon-rotate` alone when the alignment is `viewport`,
   plus the segment angle (folded into [−90°, 90°) when `icon-keep-upright`) when it is `map`;
   `icon-rotation-alignment` `auto` is `map` on line placements and `viewport` on points (`icon_quad`). When the
   layer also has text and `icon-text-fit` is not `none`, the box is `fit_icon_to_text` of the text box
   (`fitIconToText`: stretched to the text box plus `icon-text-fit-padding` in the fitted dimensions, centred on
   it in the others; `icon-anchor` is then ignored). `icon-pitch-alignment` has no effect on a flat map.
9. **Placement.** Icons join SREP 9's label placement (`place`): a feature's text and icon form one candidate,
   candidates are ordered by SREP 9's priority (later layers first; within a layer lower `symbol-sort-key`
   first, then feature order), and each box is grown by its padding (`text-padding`; `icon-padding`'s one or
   four values top, right, bottom, left). A box wholly outside the frame is rejected. Overlap follows
   `getOverlapMode` (`icon-overlap`, else `icon-allow-overlap` as `always`/`never`; `text-overlap` likewise):
   `never` rejects a box that overlaps any placed box, `always` rejects nothing, `cooperative` rejects a box only
   where the placed box it overlaps was placed as `never`. Then the pair: with neither `icon-optional` nor
   `text-optional`, both are placed or neither; with `icon-optional`, the text is placed on its own and the icon
   only with the text; with `text-optional`, the reverse. SREP 9's duplicate rule drops the text (and with it a
   non-optional icon); a dropped duplicate occupies nothing. A placed box occupies space unless its
   `icon-ignore-placement` (`text-ignore-placement`) is true. Touching boxes do not overlap.
10. **Drawing icons.** Placed icons are drawn in placement order, over the labels pass of SREP 9's paint order
    (its step 6, after the basemap's layers) and clipped to the frame. A pixel whose centre lies inside the quad
    maps to the sprite rectangle by the quad's affine inverse and samples the sheet bilinearly (straight PNG
    pixels premultiplied before interpolation, sample positions clamped to the entry) (`icon_pixels`). A sprite
    with `sdf` false gives that sample × `icon-opacity` × `@opacity`. An `sdf` sprite reads the sample's alpha as
    the distance `dist` and draws, per MapLibre's `symbol_sdf` fragment shader, the fill `icon-color` ×
    smoothstep(0.75 − γ, 0.75 + γ, `dist`) with γ = 0.105 / `icon-size` (`sdf_fill`) over the halo
    `icon-halo-color` × min(smoothstep(`edge` − γh, `edge` + γh, `dist`), 1 − fill) with `edge` = (6 −
    `icon-halo-width` / `icon-size`) / 8 and γh = (`icon-halo-blur` · 1.19 / 8 + 0.105) / `icon-size`
    (`sdf_halo`; no halo when the width is 0), the result × `icon-opacity` × `@opacity`. `icon-translate` shifts
    the icon as `fill-extrusion-translate` shifts footprints.

## Rationale

- **MapLibre's formulas, not a smoothed approximation.** The heatmap kernel, its quad cut-off, the lighting mix,
  the ambient term, the gradient floor and the SDF gammas are the numbers MapLibre's shaders use; an author who
  previews a style in MapLibre sees the same density scale, roof tones and icon edges in the renderer. Where
  MapLibre's result depends on the GPU (half-float versus byte density textures, the 256-sample ramp texture,
  linear texture filtering) the draft takes the exact value: density clamped to 1 only at the lookup, the ramp
  evaluated at `t`, bilinear sampling at the pixel centre.
- **Sprites as assets.** SREP 9 never fetches at render time; sprite sheets are declared assets like tiles and
  styles, with the style's `sprite` ids matched by `name`, so a document is complete offline and verifiable
  (`@sha256` on the assets).
- **Roofs on 2D maps.** With no camera, a flat map shows an extruded footprint as its roof; drawing the lit roof
  keeps the colour an author tuned in MapLibre (where a pitch-0 view also shows roofs only) without inventing
  walls. On 3D maps the format already has prisms (SREP 10), so the layer feeds them.
- **One placement pass.** Icons and text of one feature stand or fall together, as in MapLibre, and the
  `cooperative` mode reads the placed box's mode, so the engine stores the mode with each placed box.
- **Every vertex is a kernel centre.** MapLibre's heatmap uses its circle bucket, which emits every vertex of
  lines and polygons; following it keeps heatmap styles over line data identical.

## Rejected alternatives

- Drawing walls on a 2D map by a fixed oblique projection: not what MapLibre shows at pitch 0 and not
  reproducible across engines without a camera model; rejected.
- Nine-slice stretching of icons from `stretchX`/`stretchY`/`content`: a large surface for a rarely used
  feature of text-fitted labels; left to an Open issue, the icon is drawn whole.
- Fetching the style's `sprite` URL: contradicts SREP 9's offline rule and A03; rejected.
- A raster `heatmap` texture of 256 ramp samples with linear filtering (MapLibre's `renderColorRamp`): a
  GPU-shaped approximation of the ramp; the exact evaluation differs from it by less than one level and is
  deterministic.
- Clamping the density while summing: MapLibre's half-float path does not, and a clamp per kernel changes
  overlapping sums; clamped once at the lookup.

## Backwards compatibility

Additive. Documents without `sprite` children and `@icons` validate and render as before; a `heatmap` or
`fill-extrusion` layer that SREP 9 skipped with a warning is now drawn, and `symbol` layers with `icon-image`
now draw icons when a sprite is declared (none otherwise, with W-DL1), so an existing document with such a style
changes its picture once it declares version 1.8. `heatmap-density` evaluates to the density inside
`heatmap-color` and stays null elsewhere. SREP 10's `building(s)` rule is replaced only when the style has
`fill-extrusion` layers.

### Kit cases

To be measured on the engine (SREP 14's seek check applies to each):

1. `heatmap-default`: twelve points at the default paint over a white background; the density image's peak and
   covered pixel count equal the reference's, every pixel within 1/255.
2. `heatmap-weight-ramp`: `heatmap-weight` from a property, a `step` ramp and `heatmap-opacity` 0.5; pixels
   within 1/255.
3. `extrusion-roofs`: four footprints with heights from a property, one flat; three roofs in the reference's
   tones within 1/255, the flat one absent.
4. `extrusion-prisms`: the same style on a 3D map with `@buildings`; three prisms with SREP 10's geometry and
   the style colours as base colour.
5. `icons-sprite`: a declared sprite with a raster, an SDF and a pixelRatio-2 entry; pixel-exact copies of the
   unscaled icon, the SDF fill and halo within 1/255.
6. `icons-placement`: overlapping icons with `never`, `always` and `cooperative` and an `icon-optional` pair with
   text; the placed set equals the reference's.
7. `icons-line`: icons along a line with `icon-rotation-alignment` `map` and `icon-keep-upright`; anchors and
   angles within 1e-6.
8. `data-layers-errors`: the bad document; the engine reports DL1–DL7 and V17 and renders the valid remainder
   with W-DL1.

## Open issues

1. Nine-slice icons (`stretchX`, `stretchY`, `content` in the sprite index) are drawn whole; MapLibre stretches
   them under `icon-text-fit`. A later revision may add the slicing.
2. High-density sprites (`@2x`, `pixelRatio` 2) display at half their pixel size; the renderer has no device
   pixel ratio, so a document that wants crisp icons at scale 2 draws them from a `pixelRatio` 2 sheet at
   `icon-size` 2.
3. `symbol-spacing` repeats symbols along a line in MapLibre; SREP 9 places one label per line piece and this
   draft follows it for icons.
4. The text box that `icon-text-fit` needs comes from SREP 9's label layout; the reference module draws no
   text, so the fit is tested on a given text box.
5. `symbol-z-order` `viewport-y` reorders drawing by screen y in MapLibre; this draft draws in placement order
   and reads the property only for validation.
6. Heatmaps on globes (SREP 10's drape) are not defined here; the relief draft's drape rule would carry the
   layer image.
7. `fill-extrusion-translate` with a rotated map turns the shift for anchor `map`; the reference example has
   rotation 0 and the turn is untested numerically.
