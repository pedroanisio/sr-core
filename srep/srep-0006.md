# SREP 6 — Package format 1.1: hash-covered metadata and safe reading

## Abstract

Format 1.1 adds `packed.metaSha256`, which records the SHA-256 of the package's `README.md` and
`vpkg.schema.json`, so every byte of a package is covered by a hash. It also makes normative how a reader
treats a package it cannot trust:
- It validates the package completely before writing anything.
- It never writes outside the folder it extracts into.
- It rejects paths containing control characters.

Three packing rules change as well:
- a symbolic link that leaves the project is refused;
- references inside `<include>`d documents are rewritten like those in scenes;
- font files anywhere in the project are candidates for resolving font families.

## Motivation

A package is meant to be handed to someone else, so its reader must assume it can be hostile. Format 1.0,
as implemented, had these gaps:
- **Extraction despite errors.** `verify` and `unpack` recorded an unsafe entry name or an invalid manifest,
  but extracted anyway. A manifest path such as `../../x` wrote outside the extraction folder, even during a
  plain `verify`.
- **A newline hid a parent reference.** The path pattern's `..` check used `.*`, which does not cross a
  newline, so `a\n/../../../x` passed validation and escaped when unpacked or fetched.
- **Unhashed metadata.** `README.md` and `vpkg.schema.json` were not covered by any hash, so an edited README,
  for example one telling the reader to pipe a download into a shell, still verified.
- **Symlinks leaked files.** `pack` followed a symbolic link out of the project and bundled the file it
  pointed at, without saying so.
- **Broken includes.** A reference to a file outside the project, made inside an `<include>`d document, was
  copied to `_external/` but not rewritten, so the package failed its own `verify`.
- **Fonts outside `fonts/` were missed.** Font files outside `fonts/` were not considered, although the
  documentation said they were.
- **Stale renders.** A render step declared no inputs, so editing its scene left the render "up to date".
- **Host-dependent bytes.** Media types came from the host's `mimetypes` tables, so the same project could pack
  to different bytes on different machines.

## Specification

1. **`packed.metaSha256`** (object, file name → SHA-256) MUST list `README.md` and `vpkg.schema.json` in
   every packed manifest of format 1.1 or later.
   - A reader MUST reject a 1.1 package when the key is missing, when an entry is missing, or when a hash
     differs.
   - For a 1.0 package it MUST warn that these two files are not covered.
   - `README.md` is generated from the manifest without this key, and the key is added afterwards.
2. **The packed manifest's `formatVersion`** is the format of the tool that packed it. An authoring
   `vpkg.json` may declare any version up to the tool's own.
3. **`relpath`** MUST NOT contain control characters (U+0000–U+001F, U+007F). Its parent-reference check
   spans the whole string. Validators MUST treat the pattern's `$` as the end of the string.
4. **Reading.**
   - A reader MUST complete every check that needs no writing before it writes anything: entry names, the
     manifest against the schema, stray entries, and the metadata hashes.
   - After any error, it MUST NOT write anything from the package. It SHOULD still hash the remaining entries
     in memory, so that every problem is reported.
   - Every write target, including fetch destinations, MUST resolve inside the extraction or project folder,
     following links that already exist on disk. A target that doesn't is an error.
5. **Packing.**
   - A symbolic link whose target resolves outside the project MUST be refused, unless the author's
     `exclude`, or a default exclude the author did not override, leaves it out.
   - References to files outside the project are rewritten in every XML document that holds them, listed
     scenes and `<include>`d documents alike, relative to that document.
   - Every font file in the project, wherever it is and unless excluded, is a candidate when resolving font
     families. A candidate that is used is bundled at its own path.
   - `mediaType` comes from a fixed table in the tool, not from the host.
6. **Running.** A render step's inputs are its scene, or the variant used for the engine, plus every file
   that scene references, in addition to any declared `inputs`.

## Rationale

Refusing to write is the only rule a reader can follow without trusting the package. Checking containment on
the resolved path catches what the name checks miss, including links already on disk.

Recording the metadata hashes in the manifest, rather than regenerating and comparing them, keeps packages
verifiable by later tool versions, whose README text or schema file may differ.

## Rejected alternatives

- **Regenerating README.md at verify time and comparing.** Any change to the README template or the schema
  file in a later release would fail every earlier package.
- **Storing symbolic links in the zip.** Many unzip tools recreate them, which reproduces the escape on the
  reader's machine.

## Backwards compatibility

- This is a format MINOR. 1.0 packages still read, with a warning about the uncovered metadata.
- Tools that read 1.0 treat 1.1 packages by the rule of SREP 4: they ignore `packed.metaSha256` with a warning.
- Packages that relied on the unsafe behaviour (escaping paths, links out of the project) no longer pack or
  read. That is intended.
- The JSON Schema file is now `vpkg-1.schema.json`, and its `$id` is `urn:scene-render:vpkg:1`, named by
  major version.

## Engine impact

None. This is a package format; engines are called by `run` as before.

Reference implementation: `sr_core/vpkg` (sr-core 1.1.0).
