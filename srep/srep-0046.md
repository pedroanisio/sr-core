# SREP 46 — Set morph targets of an imported model by name

## Abstract

An `object3D` of `primitive="mesh"` can set the morph targets of an imported model only as a positional list
(`morphWeights`), which is the same list for every mesh of the model. A new child element, `<morph name="…" weight="…"/>`,
sets one target by the name the model's file gives it, and its `weight` animates like any attribute. A document that
uses no `morph` element renders as before.

## Motivation

The NOLN face-model assessment (§C, item 2) lists named morph weights: a face model carries dozens of targets
(the converted ICT-FaceKit head has 7, the models it surveyed up to several hundred), and "a 57-entry positional list is
error-prone"; a preset expression is a weighted sum of named targets. With the Rust reference, `morphWeights` is a
positional list that replaces every node's weights, and the targets' names are not read.

## Specification

### Syntax

```xml
<!-- object3DType gains a child -->
<xs:element name="morph" type="morphType"/>

<xs:complexType name="morphType">
  <xs:annotation><xs:documentation>With an object3D of primitive="mesh" and an imported model: the weight of one morph
  target of the model, by the target's name. It replaces that target's weight from the clip or the rest pose, and wins
  over the same target in the object's @morphWeights. The weight animates. Version 1.2.</xs:documentation></xs:annotation>
  <xs:group ref="animationElements" minOccurs="0" maxOccurs="unbounded"/>
  <xs:attribute name="name" type="xs:string" use="required"/>
  <xs:attribute name="weight" type="xs:double" default="0"/>
</xs:complexType>
```

```xml
<!-- the version gate, V5: documents before version="1.2" cannot use 1.2 elements -->
<sch:assert id="V5" test="not(assets/tiles|.//basemap|.//object3D/rigidBody|.//object3D/morph|…)">
```

The existing V5 test gains `.//object3D/morph`; the rest of its test is unchanged. `morph` is a new element, so it needs
version 1.2 (SREP 0, Versioning).

### Semantics

**1. Names.** The name of a target is, for glTF, the entry of `mesh.extras.targetNames` at the target's index (the
convention of Blender's exporter and most others); for FBX, the name of the blend channel. Names belong to a mesh: a
model whose nodes use different meshes may repeat a name, and a `morph` sets every target of that name.

**2. Weights.** The weights an object draws are, for each node, the clip's (or the rest pose's) weights, replaced
as a whole by `@morphWeights` when that is set, and then each `morph`, in document order, sets the weight of the targets
it names. A later `morph` of the same name wins. A weight is any number (a value above 1 or below 0 extrapolates the
target, as in `morphWeights`).

**3. Errors.** A `name` that no target of the model has MUST be reported, listing the names the model has, and has no
effect; a model with no named targets MUST be reported as having none.

### Defaults and the neutral case

No `morph` element: the weights are the clip's or `@morphWeights`, as before.

## Rationale

- **A child element, not an attribute.** Weights animate; the document's animation system animates the attributes of
  child elements (as `blob`), where a string list could not be keyed.
- **By the name the file gives.** glTF's `targetNames` is an `extras` convention rather than part of the glTF core
  schema (the specification gives `extras` no defined content; the convention is stated from common exporter
  behaviour, not from the specification text, which was not re-read for this draft).
- **Wins over `morphWeights`** so a document can start from a positional list (for a model without names) and adjust
  by name.

## Rejected alternatives

- **`morphWeights="smile:0.8 blink:1"`.** A string cannot be keyed.
- **A name per primitive.** glTF names targets per mesh; a model's primitives share their mesh's names.

## Backwards compatibility

Class: Added element, MINOR, gated by version 1.2 (V5). Documents of version 1.0 and 1.1 that use no `morph` are
unaffected; no existing document is invalid under the new gate because the element did not exist.

## Conformance

| Case | Checks | Tolerance |
|---|---|---|
| `srep-NNNN-morph-by-name` | a triangle with two named targets that move it 0.4 m in x and y: `right` at 1 moves it 40 px in x only; both at 0.5 and 1 combine | 1.5 px |
| `srep-NNNN-morph-keyed` | the weight keyed 0 to 1 over a second moves the triangle linearly | 1.5 px |
| `srep-NNNN-morph-precedence` | with `morphWeights="1 1"`, a named weight of 0 removes only its target | 1.5 px |
| `srep-NNNN-morph-unknown` | an unknown name is reported with the model's names; a model with none says so | exact |
| `srep-NNNN-morph-version` | `morph` under `version="1.1"` fails V5 | exact |

## Open issues

- Whether `morph` should also work on `primitive="mesh"` fracture sources (the Rust reference applies it to the drawn
  model only).
- Whether a preset (a named set of weights) deserves its own element.
