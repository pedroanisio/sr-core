# SREP 24 — Define which force fields act on a simulation

## Abstract

`particleEmitter`, `flock` and `fluid` take `forceFields`, a list of `forceField` ids, but the schema does not say
what an element without the list receives, and gives no way to say "no field". This SREP states the rule the
reference engine already follows (no list: every force field of the scene) and adds `useForceFields`, a
boolean with the neutral default `true`: `false` means no force field acts on the element, whatever
`forceFields` lists.

## Motivation

A scene with one vortex for one emitter bent every other emitter as well: the other emitters had no
`forceFields`, and the engine gives such an element every field. Nothing in the schema or the conformance
definitions says so, and an author cannot opt an element out: `forceFields` is `xs:IDREFS`, which needs at least
one id, so there is no way to write an empty list.

## Specification

### Syntax

In `particleEmitterType`, `flockType` and `fluidType`:

```xml
<xs:attribute name="forceFields" type="xs:IDREFS">
  <xs:annotation><xs:documentation>
    The force fields that act on this simulation. Absent: every forceField of the scene. Present: only
    those listed.
  </xs:documentation></xs:annotation>
</xs:attribute>
<xs:attribute name="useForceFields" type="xs:boolean" default="true">
  <xs:annotation><xs:documentation>
    false: no force field acts on this simulation, whatever forceFields lists.
  </xs:documentation></xs:annotation>
</xs:attribute>
```

`useForceFields` is a new attribute with a neutral default, so it is accepted in every schema version and no
version gate changes. No Schematron rule is added: `forceFields` keeps rule R34 (its ids name force fields),
and `useForceFields="false"` with a `forceFields` list is valid, the list having no effect.

### Semantics

For each `particleEmitter`, `flock` and `fluid`, the force fields acting on it at a simulation time are:

1. none, when `useForceFields` is `false`;
2. otherwise the listed fields, when `forceFields` is present;
3. otherwise every `forceField` of the scene.

In every case a field acts only inside its own time window and when its `affects` is `all` or `particles`
(emitters, flocks and fluids are particle simulations). Rigid and soft bodies are
unchanged: they take every field whose `affects` includes `bodies`.

### Defaults and the neutral case

`useForceFields` defaults to `true`, and an element without `forceFields` receives every field, as the
reference engine has always done. Every existing document renders exactly as before.

## Rationale

- **Every field by default.** A scene's fields usually describe its world (gravity, wind, a stirring vortex),
  and Blender (effector collections, all by default) and Unity (particle system external forces, every
  layer by default) give a system every field unless it is restricted. It is also what documents written
  for the reference engine already rely on.
- **An explicit opt-out.** An empty `forceFields` cannot be written, and a sentinel id would need a reserved
  name in a space of author ids. A separate boolean says exactly one thing and has a neutral default.
- **No rule for the combination.** `useForceFields="false"` with a list is harmless and useful while editing
  (switching the fields off without losing the list), so it is not an error.

## Rejected alternatives

- **No list means no field.** More explicit, but it changes every existing document whose simulations rely on
  the scene's fields, and makes the common case (one world-wide wind or gravity) verbose.
- **A reserved `forceFields="none"`.** `forceFields` is `xs:IDREFS`; a keyword would either be an id an author
  could also use, or need the type changed to a union.

## Backwards compatibility

None broken: the default rule is the reference engine's behaviour, now written down, and the new attribute's
default keeps it.

## Conformance

A 640 × 360 frame holds three emitters with a 2 s `preroll`, `rate="40"`, `speed="0"` and 8 px dots, and a
directional field of `forceX="0.1"` (10 px/s² at 100 px per metre) that starts at −2 s, under `gravityY="0"`.
The oldest particle of a pushed emitter moves g·h²·N(N+1)/2 = 10 · (1/120)² · 240 · 241 / 2 ≈ 20.1 px, so its
dots span about 28 px; an emitter the field does not act on keeps one 8 px dot.

| Case | Checks | Tolerance |
|---|---|---|
| force field scope | the emitter listing the field (red) and the one with no list (green) span 28 px; the one with `useForceFields="false"` (blue) is an 8 px dot at its origin | 2 px |

The case is added to the kit with this SREP's number; until then the reference engine's test
`force_fields_act_on_the_simulations_that_take_them` checks it.
