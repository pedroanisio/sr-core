# SREP 55 — Give nodes their own shutter angle

## Abstract

Motion blur has one shutter angle for the whole project (`project/@shutterAngle`). A new attribute on every node,
`shutterAngle`, sets the angle for that node and, by inheritance, its children: a fast arm can blur at 360° while the
body stays at 180°, or a node can be drawn sharp (0°) inside a blurred scene. Nodes without it use the project's angle, as before.

## Motivation

The NOLN motion research (§1.8 and item E8): "per-node shutter: the angle and sample count are project-wide; only
on/off is per node". With the Rust reference a dancing figure can only be blurred as much as the whole film, or not at
all (`motionBlur="off"`).

## Specification

### Syntax

```xml
<!-- nodeAttributes gains -->
<xs:attribute name="shutterAngle">
  <xs:annotation><xs:documentation>The shutter angle, in degrees, of this node's motion blur, instead of the project's: the
  nearest node up its parents that sets it, else project/@shutterAngle. 0 draws the node sharp; 360 blurs over the
  whole frame interval. Only where motion blur is on for the node.</xs:documentation></xs:annotation>
  <xs:simpleType><xs:restriction base="xs:double">
    <xs:minInclusive value="0"/><xs:maxInclusive value="720"/>
  </xs:restriction></xs:simpleType>
</xs:attribute>
```

```xml
None.
```

New attribute with no default, accepted in every version (SREP 0, Versioning); the range is the project attribute's.

### Semantics

The angle `a` of a node is that of the node itself if it sets `shutterAngle`, else of its nearest ancestor that does, else
`project/@shutterAngle`. Where motion blur is on for the node (`motionBlur`, inherited as before), the node is accumulated
over the shutter with `a` in place of the project's angle: the sample times are
`t + (φ/360 + (a/360)·(k + ½)/N)/fps` for `k = 0 … N−1`, with `φ` = `project/@shutterPhase` and `N` the sample count, both as before.
An angle of 0 means the node is not blurred. `motionBlur="off"` still wins: no blur whatever the angle.

### Defaults and the neutral case

No node sets `shutterAngle`: the project's angle, as before.

## Rationale

- **One attribute on the node group**, with the same range as the project attribute, and inheritance by the same
  nearest-ancestor rule as `motionBlur`.
- **Angle, not phase or sample count**: the angle is what an animator varies by node; the phase and the sample count stay project-wide.

## Rejected alternatives

- **A child opt-out under a blurred ancestor** (the second half of the research item): not defined here. A descendant that is
  exempt from its ancestor's blur has no well-defined pose, because its place in the frame depends on the ancestor's motion
  during the shutter; the question is left open (Open issues).

## Backwards compatibility

Class: Added attribute with no default, MINOR in effect, accepted in every version. No valid document changes validity or rendering.
