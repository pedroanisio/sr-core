# SREP 33 — Define safe-area enforcement and the safeAreaForce override

## Abstract

`safeArea/@enforce` has been in the schema since the baseline, with the documentation "enforce=warn|error checks
that text, captions and nodes tagged cta or logo stay inside the safe region", and no engine acted on it. This
SREP defines what the check measures, what each level does (a finding, or a failure that stops delivery), and
what a finding is called (`SA01`). It adds one attribute, `safeAreaForce`, on every node and on `symbol`, that
exempts a deliberate placement outside the region, and an information line (`SA02`) that lists every use of it.
A document that sets neither `enforce` nor `safeAreaForce` renders as before.

## Motivation

**Evidence.** The lab that exercises every attribute of the format against the Rust engine (the G2 lab, its
`frame.safearea-enforce-*` cases) found `safeArea@enforce` "accepted, never acted on": a text layer, a burned
caption and a node tagged `cta` or `logo` placed outside the safe region gave no finding at `validate`,
`render --strict` or `encode`, and all three exited 0 and wrote frames. A first version of the lab's check even
passed because the document was invalid and the non-zero exit counted as "reported".

**A second need, found in a production brand file.** A brand notch drawn at the frame's edge by design (x = 0)
failed the corrected check three times (`SA01` on one node). The author needs a way to say "this one is outside
on purpose" that does not turn the check off for the rest of the document, and that never hides: the exemption
has to be listed wherever the document is validated.

**Cost.** The first audit evaluated whole frames, simulations included, at up to 4,800 sample times. On a
7.3 MB physics film `validate` went from 4.6 s to over 15 minutes. After bounding the audit (below) the same
film validates in 13.7 s; on a 6,510-frame scene `validate` went from 3.5 s to 10.7 s.

## Specification

### Syntax

```xml
<!-- nodeAttributes (every node) and symbolType gain -->
<xs:attribute name="safeAreaForce" type="xs:boolean" default="false">
  <xs:annotation><xs:documentation>
    true exempts this node and everything it contains (for a symbol: every instance of it, and what it draws)
    from the safeArea enforce check (SA01); validate lists every node that carries it (SA02), so a deliberate
    placement outside the safe region is never silent.
  </xs:documentation></xs:annotation>
</xs:attribute>
```

A new attribute with a neutral default, accepted in every version (SREP 0, Versioning). No Schematron rules.
`safeAreaType/@enforce` and its default (`warn`) are unchanged.

### Semantics

**1. The safe region.** For a frame of width W and height H and a safe area with insets top, right, bottom and
left (fractions of the frame, explicit attributes over the preset's), the safe region is the rectangle
`[left·W, top·H] – [W − right·W, H − bottom·H]`. The insets a preset stands for are engine-maintained
approximations with no platform source; a document that depends on a platform's interface SHOULD declare a
custom safe area with explicit insets.

**2. What is checked.** With `enforce` of `warn` or `error` on the safe area the project uses (or, for a caption
track, the safe area that track names with `@safeArea`, else the project's), an engine MUST check:

1. every text layer (a layer whose asset is a `text` asset);
2. every node whose `tags` contain the token `cta` or `logo`;
3. every cue of a burned-in caption track.

Hidden nodes (world opacity 0, or not drawn at that time) and sidecar caption tracks MUST NOT be checked.
With `enforce="off"`, or no safe area, nothing is checked.

**3. How a node is measured.** A node or text layer is measured by its layout box (`[0, 0, w, h]` in the node's own
coordinates) mapped through its world transform: the axis-aligned bounding box of the four mapped corners. The box,
not the glyph ink, is held to the region; text that overflows its own box is not seen by this check. A burned
caption cue is measured by the bounds of its laid-out glyphs.

**4. Crossing.** For a measured box `[x0, y0, x1, y1]` the overshoot on each side is `region.left − x0`,
`region.top − y0`, `x1 − region.right`, `y1 − region.bottom`. The box crosses when the largest overshoot is at
least 0.5 px (smaller overshoots are rounding). The finding names the node (or the caption cue), the reason it is
checked (`text`, `cta`, `logo`, or a caption), the side with the largest overshoot, that overshoot in pixels, and the
first time it is seen.

**5. Levels.** A crossing is the finding `SA01`.
- `warn`: `SA01` is a warning; delivery goes on.
- `error`: `SA01` is an error. Validation fails, and rendering and encoding MUST stop before any frame or output file
  is written.

**6. Times.** The check applies at every frame validated or rendered. An engine MAY audit a subset of frames when
the range is long, and MUST then say that it did (`sampled N of M frames`). The subset MUST include the first and last
frames and SHOULD include the start and end of every checked node, its containers' keys, and a coarse grid. An engine
MUST NOT run simulations to audit placement; the layout is what is measured.

**7. `safeAreaForce`.** A node with `safeAreaForce="true"`, everything it contains, and (for a `symbol` with the
attribute) every instance of the symbol and what it draws, are exempt from `SA01` at both levels. Validation MUST
print one information line `SA02` for every node that carries it, naming the node: `<id> forced outside the safe
area`. An `SA02` line is not a warning: it MUST NOT change the exit code and MUST NOT fail `--deny-warnings`.

**8. Compile errors at validation.** Validation MUST also report the errors that compiling the document for rendering
would raise (an animated key that does not parse as its property's type, an expression with an unknown function or on
a property the element lacks), so that a document validation accepts is one rendering can compile. This sentence
is the reason `SA01` can be decided at validation: the layout it needs is the compiled document's.

### Defaults and the neutral case

`safeAreaForce` defaults to `false`. A document without it, and without `enforce` of `warn` or `error` that matches
content outside the region, produces the same pictures and the same exit status as before. A document whose
safe area is `enforce="warn"` (the schema default, once a `safeArea` is declared) gains `SA01` warnings it did not
have: that is the point of the SREP and is stated under Backwards compatibility.

## Rationale

- **The baseline said so.** The attribute's own documentation promises the check; this SREP defines the check
  rather than adding a feature.
- **Layout box, not ink.** The box is what the author placed and is cheap and exact; measuring ink needs rendering.
  The cost is that text overflowing its box is not seen, which belongs to the text-fit finding (`TXT-FIT`, SREP 18).
- **Force is explicit and loud.** A brand element that bleeds by design must be expressible without weakening the
  check for everything else; listing every use at validation means a force can never hide.
- **Bounded audit.** Exhaustive auditing of a 6,510-frame scene with simulations is impractical; the key times of the
  checked nodes are where placement changes.

## Rejected alternatives

- **Exempt by tag** (a `tags` token such as `bleed`). Tags are free-form and already read by other features; a
  boolean attribute is validated and visible to the schema.
- **A project-level allow list.** It would hide which nodes are exempt from the node itself.
- **Measure glyph ink for text layers.** Needs a render per frame; the lab's cases show the box check is enough for
  the failures found.

## Backwards compatibility

- **Class: Added, MINOR (1.1 files carry it; it is accepted in every version).** One attribute with a neutral default.
- **Rendering.** No picture changes.
- **Behaviour.** A document that declares `<safeArea enforce="warn"/>` or `enforce="error"` (the schema's default is
  `warn`) and places checked content outside the region now gets `SA01`; with `error` it no longer renders. Such a
  document asked for the check; no engine honoured it before. The affected documents are the ones that declared a
  safe area and relied on it being ignored: the lab's brand file fails with three `SA01` on one node until
  `safeAreaForce` is applied.
- **Version gate.** None.

## Conformance

| Case | Checks | Tolerance |
|---|---|---|
| `srep-NNNN-safe-warn` | a text layer 10 px past the right edge of the region with `enforce="warn"`: validation reports `SA01` (side `right`, 10 px) and exits 0; rendering writes frames | exact side, 0.5 px |
| `srep-NNNN-safe-error` | the same with `enforce="error"`: validation exits non-zero, rendering and encoding write nothing | exact |
| `srep-NNNN-safe-hidden` | the same node at opacity 0, and a sidecar caption track: no finding | exact |
| `srep-NNNN-safe-force` | the same node with `safeAreaForce="true"`, then inside a forced group, then as an instance of a forced symbol: no `SA01`; `SA02` printed once per carrier; `--deny-warnings` exits 0 | exact |
| `srep-NNNN-safe-sampling` | a one-instant violation in a 9,600-frame scene: found, and the output says it sampled | exact |

The cases need an engine's report channel (exit status and the lines printed), not a measured picture; the runner
checks them as validation cases.
