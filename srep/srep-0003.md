# SREP 3 — Unversioned file names for the canonical schema

## Abstract

The canonical schema files are renamed from `scene-render-1.1.xsd` and `scene-render-1.1.sch` to
`scene-render.xsd` and `scene-render.sch`, and keep those names in every version. The format version is the
XSD's `xs:schema/@version`, and each released version is a tag in sr-core. The XSD header's reference to its
companion Schematron file uses the new name.

## Motivation

With the version in the file name, every minor release renames both files. Every engine's vendoring, every
tool that locates the schema, and every link to it then has to change. Git history is split across names. The
version is already recorded inside the file, and SREP 0 already ties releases to tags.

## Specification

1. The canonical files are `sr-core/schema/scene-render.xsd` and `sr-core/schema/scene-render.sch`. They
   MUST NOT carry a version in their names.
2. The format version is the value of `xs:schema/@version` in `scene-render.xsd`. Each released version is
   the tag `schema-<version>` (for example `schema-1.2`) on the commit that releases it.
3. In `scene-render.xsd`, the schema-level documentation names its companion as "(scene-render.sch)" instead
   of "(scene-render-1.1.sch)". No declaration changes.
4. Engines MAY vendor the files under any name, but SHOULD record the version and SHA-256 they vendored.

## Rationale

This is the scheme most format schemas use for a working copy: one stable path, with versions in the content
and in tags. SREP 2's reference to the old file name is annotated rather than rewritten, because an SREP
records what was true when it was accepted.

## Rejected alternatives

- **Keeping a versioned copy beside the unversioned one.** Two copies of the canonical file would drift.
- **A directory per version (`schema/1.1/`).** This has the same problem, with renames moved to the directory.

## Backwards compatibility

- Documents are unaffected: every declaration is unchanged, and documents never name the schema file.
- The XSD's SHA-256 changes from `91d4d88e…` to `3ab6491f…`. The Schematron is byte-identical.
- Engines keep their own vendored file names until they next vendor.
