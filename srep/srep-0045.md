# SREP 45 — Give link a spring or exponential follower

## Abstract

A `link` drives a property from another value, delayed and smoothed with a moving average. A moving average only lags;
it cannot overshoot, so a head or a wire that follows a body never swings past and settles. Four optional attributes add
a follower: `follow="exponential"` (a first-order lag with time constant `timeConstant`) and `follow="spring"` (a
damped spring with `stiffness`, `damping` and `mass`, as the `spring` curve of a key has). Both are linear filters of the
source's history, evaluated at any time without state, like the rest of the evaluation. A link with no `follow` is
unchanged.

## Motivation

The NOLN motion research (§1.3, item E5) lists "`link` with a spring or exponential follower" for secondary motion (head,
hair, wires, follow-through): the baseline `link` has a delay and a box filter only, "no overshoot", and a hand-built
substitute needs a helper node plus an expression per property. With the Rust reference a linked property follows its
source through `delay` and `smoothing`; for a source that steps from 0 to 100, the output never exceeds 100.

### Semantics

**1. Order.** For a link at composition time `t`, the source value `s(τ)` is read at `τ = t − delay` (as before). When
`smoothing` is above 0 the link uses its moving average (as before) and `follow` is not applied: a link with both is an
error of the document's author and the engine MUST report that `follow` is ignored. Otherwise a follower produces
`f(t)` from `s`, and then `scale`, `offset`, `min` and `max` apply to `f(t)` as they do to `s` (so a spring overshoot
can be clipped by `max`).

**2. The filter.** The follower is the linear time-invariant system with impulse response `h` and unit gain
(`∫₀^∞ h = 1`). `f(t) = ∫₀^∞ h(u) · s(t − u) du`, where `s(τ) = s(0)` for `τ < 0` (the source is taken to have held its
value from before the start, so a constant source gives that constant at all times).

- `exponential`: `h(u) = (1/T) · e^(−u/T)`, `T = timeConstant`.
- `spring`: the spring of a key's `spring` curve: `ẍ = (k/m)(s − x) − (c/m) ẋ` with `k` = `stiffness`, `c` = `damping`,
  `m` = `mass`. With `ω₀ = √(k/m)` and `ζ = c / (2√(k·m))`:
  - `ζ < 1`: `h(u) = (ω₀/√(1−ζ²)) · e^(−ζω₀u) · sin(ω₀√(1−ζ²) · u)`;
  - `ζ = 1`: `h(u) = ω₀² · u · e^(−ω₀u)`;
  - `ζ > 1`: `h(u) = ω₀² (e^(p₁u) − e^(p₂u)) / (p₁ − p₂)` with `p₁,₂ = −ω₀(ζ ∓ √(ζ²−1))`.

  These are the standard results for a second-order system `ω₀² / (s² + 2ζω₀s + ω₀²)`. For a source that steps from 0 to 1
  at time 0, `f` is the step response of the spring.

**3. Evaluation.** The integral is evaluated numerically over a window of `W = ln(1000)/λ` seconds, with `λ = 1/T`
for the exponential and `λ = ζω₀` for the spring (for `ζ ≥ 1`, the slower pole's rate `ω₀(ζ − √(ζ²−1))`), so that the
response has decayed to 0.1 % at the end of the window. The window is cut into `N = clamp(⌈480·W⌉, 16, 2048)` equal
intervals, `h` is taken at their midpoints, and the weights are normalised to sum to 1 (a constant source then gives
exactly that constant). An engine MAY use any method whose result is within 1 % of the range of the source over the
window of the integral above; the Rust reference reproduces the step responses of the Conformance table within 1 % of
the step. A source with a discontinuity is sampled across it and the output does not step.

**4. Vectors.** A source with several components (a point) is filtered component by component.

**5. Errors and inert parameters.** `timeConstant` with a `follow` other than `exponential`, and `stiffness`, `damping` or
`mass` set to a non-default value with a `follow` other than `spring`, have no effect and an engine SHOULD report them
(SREP 18).

### Defaults and the neutral case

`follow` absent or `none`: the link is evaluated as before.

## Rationale

- **Linear filters of the history**, not integration of state: the evaluation of a frame is a pure function of time
  (SREP 0, Evaluation); a spring that carries its state frame to frame would make a frame depend on the frames before it
  and break seeking, segmenting and parallel rendering. The follower's response to a source is the same whatever frames
  were rendered, because it is computed from the source's history.
- **The spring parameters of a key** (`stiffness`, `damping`, `mass`, with the defaults 100, 10, 1) give authors one
  vocabulary for both. The same differential equation, so a link follower and a `spring` key respond alike to a step.
- **An exponential follower** is the common first-order smoothing without overshoot, and is cheaper to reason about than
  a box filter for audio-reactive properties (no ringing at the window edge).
- **`smoothing` and `follow` are not combined** to keep the cost of an evaluation bounded (a moving average of a
  filter of the source would multiply the samples).

## Rejected alternatives

- **Stateful integration across frames.** Breaks seeking and segmented rendering.
- **An expression function (`follow()`).** Expressions read the current value only; the follower needs the source's
  history, which is a property of links.
- **A `spring` easing on a `link`.** A curve maps a progress, not a history.

| `srep-NNNN-link-follow-spring` | the same with the defaults of a spring (underdamped): the output peaks above 100 and settles to 100; at the first peak it is 100(1 + e^(−πζ/√(1−ζ²))) | 1 |
