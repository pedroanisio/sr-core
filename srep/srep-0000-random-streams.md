# SREP 0 — Define the random streams derived from the D24 hash

## Abstract

[SREP 14](srep-0014.md) rule 2 requires every random or procedural value to come from the D24 lattice hash and
"from the derived draws that a Semantics SREP on random streams defines on top of it". This is that SREP: the F1
building block of [SREP 12](srep-0012.md). It defines, as pure functions of integers, the unit draw, the normal
draw, permutations, the packing of 2D and 3D lattice indices, value and gradient noise, the octave sum, 3D Perlin
noise over a hashed permutation, the per-element seed as the CRC-32 of `project seed:id:@seed:purpose`, and one
address for the draws of simulations: element seed, purpose, step and index. Every definition except the
simulation address is what the reference implementation already computes, with its golden values; the
simulation address replaces, for documents of version 1.8 and later, the second hash that the reference's
simulations use today. No element or attribute changes.

## Motivation

- **The rule names a document that does not exist.** SREP 14 rule 2 points every stochastic SREP of the plan
  (F2 terrain, F4 wind, the A, S, T and G tracks of SREP 12) at "a Semantics SREP on random streams". Until it
  exists, each of those SREPs would define its own draws, which is what SREP 14's rationale calls splitting the
  format's randomness.
- **The reference derives nine draws from D24 that no SREP states.** `crates/sr-vector/src/d24.rs` of the
  reference at 67a661a defines, beside D24's hash and noise, a normal draw (Box–Muller from one hash, line 39),
  a Fisher–Yates permutation (line 48), a 21-bit lattice packing (line 32), the CRC-32 element seed (lines 59
  and 72), 3D Perlin noise over a hashed permutation (line 79) and a weighted octave sum (line 158);
  `crates/sr-vector/src/modifiers.rs:449` adds smoothstep value noise. Text animators (`sr-text/src/animate.rs:353`,
  `:362`, `:1053`), generators (`sr-gpu/src/render.rs:2173`), effects and transitions (`sr-gpu/src/fx.rs:1455`,
  `:2223`, `:3027`, `:3090`) and expressions (`sr-eval/src/eval.rs:777`) read them. A second engine cannot
  reproduce a seeded text animator or a glitch transition from the SREPs alone.
- **The reference's simulations draw from a different hash.** `crates/sr-sim/src/rng.rs:4` mixes
  `seed ⊕ a·0x9E3779B97F4A7C15 ⊕ b·0xC2B2AE3D27D4EB4F` through the SplitMix64 finaliser, and 2D particles
  (`sr-sim/src/particles.rs:133`, `:177`), flocks (`flock.rs:57`), slime (`slime.rs:78`, `:122`), erosion
  (`erosion.rs:61`), 3D particles (`particles3d.rs:675`), whitewater (`ocean/whitewater.rs:419`), ejecta
  (`cratering/ejecta.rs:187`) and pyro turbulence (`pyro.rs:1759`) draw from it. Their element seeds, when the
  element has no `@seed`, are the FNV-1a hash of the id (`sr-eval/src/rng.rs:33`, read at `sim.rs:392`,
  `:1460`, `agents.rs:112`, `program.rs:1466`, `solid.rs:72`), not the CRC-32 seed. That is two generators,
  which SREP 14 rule 2 forbids, and nothing in the SREPs says which one a simulation uses.
- **A seeded element must re-render alone to the played frame.** SREP 14 rule 5's seek check holds only when
  every draw is addressed, never sequenced. The simulation address below makes the step part of the address,
  so a draw at step t does not depend on how many draws steps 0 to t − 1 made.

## Specification

All integers are 64-bit two's complement unless a range is stated; a negative value enters a hash as its two's
complement. All real arithmetic is IEEE 754 binary64 in the order written. `splitmix64`, `H` and `N` are those
of D24 (`conformance/DEFINITIONS.md`), restated here so that this section can be implemented alone.

### 1. The hash and the unit draw

- **mix64(z):** z ← (z ⊕ (z ≫ 30)) · 0xBF58476D1CE4E5B9; z ← (z ⊕ (z ≫ 27)) · 0x94D049BB133111EB;
  result z ⊕ (z ≫ 31), all modulo 2⁶⁴.
- **splitmix64(x)** = mix64(x + 0x9E3779B97F4A7C15 mod 2⁶⁴).
- **H(s, c, i)** = splitmix64(s ⊕ splitmix64(c ⊕ splitmix64(i))): the lattice hash of seed s, channel c and
  index i (D24).
- **U(s, c, i)** = ⌊H(s, c, i) / 2¹¹⌋ / 2⁵³, in [0, 1) ([SREP 26](srep-0026.md)).

Every draw below MUST be computed from H with the arguments stated; no draw MAY read a generator's state.

### 2. Derived draws

- **2.1 Normal draw G(s, c, i).** With h = H(s, c, i), u₁ = (⌊h / 2³²⌋ + ½) / 2³² and u₂ = (h mod 2³²) / 2³²,
  G = √(−2 ln u₁) · cos(2π u₂). u₁ is never 0, so G is finite; its largest magnitude, at h = 0, is
  6.763705635001895.
- **2.2 Permutation P(s, c, n).** Start with p = (0, 1, …, n − 1). For i = n − 1 down to 1, with k counting
  from 0, let j = min(⌊U(s, c, k) · (i + 1)⌋, i) and swap pᵢ with pⱼ. P(s, c, 0) and P(s, c, 1) make no draw.
- **2.3 Lattice index pack(i, j, k).** For i, j, k in [−2²⁰, 2²⁰): (i mod 2²¹) + (j mod 2²¹) · 2²¹ +
  (k mod 2²¹) · 2⁴². A 2D index is pack(i, j, 0). A draw over a lattice is U(s, c, pack(i, j, k)). An SREP that
  addresses a lattice MUST keep its coordinates in that range (an engine MAY mask larger values, but the
  result is then not defined by this SREP).
- **2.4 Gradient noise N(s, c, x)** (D24): gᵢ = 2 U(s, c, i) − 1 at lattice point i; with i = ⌊x⌋,
  f = x − i and u = 6f⁵ − 15f⁴ + 10f³, N = 2 · (gᵢ f + (gᵢ₊₁ (f − 1) − gᵢ f) · u). It lies in [−1, 1] and is 0
  at integers.
- **2.5 Octave sum W(s, c, x, n, m).** With n read as 1 when below 1 and as 16 when above 16: for k = 0 to
  n − 1, add mᵏ · N(s, c · 1024 + k mod 2⁶⁴, x · 2ᵏ) and mᵏ to a sum and a weight; W is the sum divided by the
  weight, or 0 when the weight is 0. D24's fractal noise is W with m = ½; the `wiggle` expression of D25 is W
  with its `ampMult`.
- **2.6 Value noise V(s, c, x).** vᵢ = 2 U(s, c, i) − 1 at lattice point i; with i = ⌊x⌋, f = x − i and
  u = 3f² − 2f³, V = vᵢ + (vᵢ₊₁ − vᵢ) · u. It lies in [−1, 1].
- **2.7 Perlin noise perlin3(p, x, y, z).** Improved Perlin noise (Perlin 2002) with the 256-entry
  permutation p, read modulo 256, the gradient of hash value h in 0 to 15 as in that paper, the quintic fade,
  and the result clamped to [−1, 1]; NaN when an input is not finite. The permutation an element uses is
  P(s, c, 256) for the seed and channel the element's SREP names.

### 3. Seeds

- **3.1 Project seed.** `project/@seed`, 0 when absent (schema 1.7.1, `projectType/@seed`).
- **3.2 Element seed E(project, id, seed, purpose).** The CRC-32 (IEEE 802.3, reflected, polynomial
  0xEDB88320, as zlib's `crc32`) of the UTF-8 text `project:id:seed:purpose`, where `project` is the decimal of
  the project seed, `id` the element's id (empty when it has none), `seed` the decimal of the element's
  `@seed` (empty when absent), and `purpose` a string the element's SREP states. Each draw of an element reads
  one purpose; an SREP MUST name every purpose its element uses. An element that a `<program>` emitted has
  the id that [SREP 87](srep-0087.md) scopes.
- **3.3 Purposes in use** (schema 1.7.1, normative through this SREP): text animators `order` (the random
  `order`) and `scramble` (the `scramble` text, with the seeds of the node's animators summed modulo 2⁶⁴ and
  XORed into E); generator assets `generator`; transitions `transition:glitch` and `transition:leak`; effects
  use the decimal print of their `@seed` with one fractional digit (`0.0` when absent, `7.0` for `seed="7"`)
  as the purpose.

### 5. Simulation streams

An SREP that adds a simulation (SREP 14, scope) MUST address its draws as follows, for documents of version
1.8 and later.

- **Element seed.** e = E(project, id, `@seed`, "stream"). A simulation that needs several independent seeds
  (an emitter and the particles it owns, a solver and its tracers) derives them with further purposes
  (`stream:emit`, `stream:tracer`), each stated by its SREP.
- **Stream draw S(e, p, t, i)** = U(e, p + t · 2³², i), with purpose p in [0, 2³²), step t in [0, 2³²) and
  index i any 64-bit integer. **S_signed** = 2 S − 1. **S_normal** = G(e, p + t · 2³², i).
- **Purposes.** Each SREP assigns a purpose number to each quantity it draws (the birth position of a particle,
  the direction of a tracer, the turbulence of a cell) and states whether the purpose is read once per element
  (t = 0, i the element's ordinal) or once per step (t the step, i the cell or particle ordinal). A purpose
  MUST NOT be read both ways.
- **Lattice draws.** A draw over a grid at step t is S(e, p, t, pack(i, j, k)).
- **Seeking.** Because t is in the address, the state after stepping from the start to step t reads the same
  draws whether or not earlier frames were rendered (SREP 14 rules 1 and 5).

### 6. Version gate

Documents of version 1.0 to 1.7 keep the draws of their engines (Appendix A states the reference's). From
version 1.8, the reference implementation MUST draw as sections 1 to 5 state, and a document whose
simulations' pixels differ from those of its 1.7 rendering by more than the kit's tolerance is expected
(Backwards compatibility). No Schematron rule is added: the gate is `scene/@version` alone.

### 7. SREP 14 rules

| Rule | How it is met |
|---|---|

| 2. Randomness | Every draw is H with the arguments stated; no generator carries state. |
| 3. Order independence | Each draw is a function of its address; a counter (section 4) is defined by the order the owning rule states, never by evaluation order. |
| 4. Units and frames | None: integers and unit numbers only. |

## Rationale

- **One hash, as SREP 14 decided.** Section 5 could have made the reference's simulation mixer normative. It
  is a second generator with its own seeds (FNV-1a of the id), which rule 2 of SREP 14 forbids and whose only
  argument is that it exists. The evidence against keeping it is concrete: SREP 14 rule 2 names the D24 hash,
  the draws of sections 2 to 4 already come from it, and a document author who sets `@seed` on a particle
  emitter today gets a seed derived one way for its `wind` field's noise and another for its emissions.
- **The step in the address, not a per-step counter.** A counter that restarts at each step still depends on
  how many draws the step makes, which changes with cell counts and with branches in the solver; an address
  of (purpose, step, index) does not.
- **CRC-32 for element seeds.** It is what the reference computes for every non-simulation element and what
  its golden tests fix; a 32-bit seed is enough because it enters H, whose output is 64 bits.
- **Two's complement for negative indices.** A lattice coordinate left of the origin must hash; the
  reference's tests fix H(42, 7, −5) with −5 read as 2⁶⁴ − 5.
- **The purpose of an effect is a float print.** Section 3.3 records it because changing it would change every
  seeded effect of every existing document; it is listed under Open issues for the next MAJOR.

## Rejected alternatives

- **Keeping two hashes (D24 for elements, the sr-sim mixer for simulations).** Rejected under SREP 14 rule 2,
  and because every stochastic SREP of SREP 12 would then have to say which one it uses.
- **Defining the streams on the sr-sim mixer and deprecating D24 draws.** It would change every seeded
  text animator, generator, effect and expression of 1.0 to 1.7 documents; the simulations are fewer and are
  all behind the 1.3 gate.
- **A counter-based generator with a stream object (Philox, PCG, the reference's unused `Stream`).** SREP 14
  rejected a second generator; `rng::Stream` in the reference has no caller outside its tests.
- **Hashing the purpose string for simulations instead of numbering it.** A string purpose costs a CRC per
  draw; numbering is free and the element seed already carries the string purpose "stream".

## Backwards compatibility

- Every document valid under 1.7 is valid under 1.8: no declaration or rule changes.
- Documents of version 1.0 to 1.7 render as before: the gate of section 6 leaves their draws untouched.
- A document re-declared as 1.8 renders its simulations with different random values (positions, directions,
  lifetimes, turbulence); its non-simulation elements render the same, because sections 2 to 4 state what
  the reference already does. The affected elements are those of the 1.3 extensions and the baseline's 2D
  simulations: `particleEmitter` (2D and 3D), `flock`, `slime`, `erosion`, `whitewater`, `crater` ejecta,
  `pyro` turbulence and `forceField` noise (`sr-sim/src/fields.rs:65`, `:83`).
- Version gate: `scene/@version` 1.8 or later; no Schematron rule.

## Open issues

- [SREP 80](srep-0080.md) (Final) defines the cell seed of a voxel fracture as the FNV-1a-64 hash of the
  owner's id and its draws as `splitmix64(seed + (3s + a + 1) · 0x9E3779B97F4A7C15)` (its section 683 and
  735). That is a third derivation. Leaving it as SREP 80 states keeps 1.6 documents exact; moving it under
  the 1.8 gate to S(E(…, "stream"), …) needs an amendment of SREP 80, which this SREP proposes but does not make.
- The purpose string of effects (3.3, a float print of `@seed`) is kept for compatibility; a MAJOR version may
  replace it with the plain decimal.
- Whether `S_normal` should use the Box–Muller form of 2.1 or a ziggurat; 2.1 is exact and cheap enough for
  per-particle draws, and a ziggurat would need its tables stated here.

## Appendix A: the reference's pre-1.8 simulation draws (informative)

Stated so that an engine can reproduce documents of version 1.3 to 1.7 exactly; not normative beyond that.

- **hash(seed, a, b)** = mix64(seed ⊕ a · 0x9E3779B97F4A7C15 ⊕ b · 0xC2B2AE3D27D4EB4F), products modulo 2⁶⁴
  (`crates/sr-sim/src/rng.rs:4`); **unit** = ⌊hash / 2¹¹⌋ / 2⁵³; **signed** = 2 · unit − 1.
- **Element seed** when `@seed` is absent: mix64(FNV-1a-64 of the id's UTF-8 bytes) (`sr-eval/src/rng.rs:33`),
  XORed with the project seed for 2D particle emitters (`sim.rs:1460`), alone for force fields (`sim.rs:392`),
