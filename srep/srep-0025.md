# SREP 25 — Develop the Rust engine only, for now

## Abstract

The C and Python engines are discontinued for now, and the Rust engine (`rs-scene-render`), the reference
implementation, is the only engine in active development; the JavaScript engine is not in active
development either. This SREP records that decision and what follows from it: an SREP is Final when the
**active** engines pass its cases, the compatibility kit runs the Rust engine by default, Engine impact
tables mark discontinued engines, and the schema's header stops listing engines by name. Historical records
are not rewritten.

## Motivation

SREP 0 counts every engine: an SREP stays Accepted until every engine passes its cases, and the kit renders
each case on each engine and fails the run when one is missing. With three of the four engines discontinued,
no SREP could become Final, and the kit's default run would always fail. The documents also described four
active engines, which is no longer true.

## Specification

1. **Active engines.** The Rust engine is the only active engine. The C and Python engines are discontinued
   for now; the JavaScript engine is not in active development.
2. **Final.** An SREP is Final when every active engine passes its cases and the schema version carrying it
   is released (SREP 0, Lifecycle). Discontinued engines are not waited for.
3. **Engine impact.** Tables in SREPs that are not yet Final mark discontinued engines `discontinued`, with
   no work listed. New SREPs list active engines only (the template).
4. **Compatibility kit.** `conformance/run.py` renders on the Rust engine by default. The runners for the
   other engines stay available with `--renderers`, for when an engine becomes active again.
5. **Schema header.** The header of `schema/scene-render.xsd` no longer lists engines by name; it says the
   schema is the contract every scene-render engine shares. This is a documentation change (PATCH), recorded
   in `schema/CHANGELOG.md`, and it supersedes the engine list SREP 2 put in the header.
6. **Records.** Accepted and Final SREPs, changelogs and History lines are records of what was decided, and
   are not rewritten.
7. **Revival.** An engine becomes active again by a dated line under History here, from the schema editor.
   From then on it counts for Final and runs in the kit by default.

## Rationale

- **Final must be reachable.** A rule waiting on engines nobody is developing would stop every SREP at
  Accepted.
- **The kit is a gate.** Its default run has to pass when the active engine passes.
- **Nothing is deleted.** The runners, the records and the definitions stay, so a discontinued engine can
  come back without reconstructing the process.

## Rejected alternatives

- **Rewriting past SREPs to remove the other engines.** They record what was true when they were decided.
- **Deleting the other runners from the kit.** Reviving an engine would mean rewriting them.

## Backwards compatibility

No schema declaration and no rendered picture changes. The schema's header wording changes (PATCH).

## Open issues

- **Definitions that cite a discontinued engine.** Several rulings in `conformance/CONVENTIONS.md` §5 (5.11,
  5.12, 5.17, 5.18, 5.20) and definitions take the Python or C renderer's behaviour as their source. Where
  that behaviour is not written out in DEFINITIONS.md, the reference implementation's behaviour now decides
  it (SREP 0, Baseline); writing it out belongs in a Semantics SREP.
