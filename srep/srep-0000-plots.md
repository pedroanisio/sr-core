# SREP 0 — Add coordinate systems and plots

## Abstract

[SREP 12](srep-0012.md) names, as its MF1 building block, "axes, number and complex planes, polar and 3D axes;
explicit, parametric, polar and implicit curves (marching squares); TeX tick labels", with the bar "plotted
points on the analytic curve within 0.5 px" (line 252). This SREP is that block. It adds an `axes` node that maps
a data range onto a pixel box and draws its axis lines, ticks, tick labels and grid; a `plot` element inside it
that draws an explicit, parametric, polar or implicit curve as a path; an `axes3D` object and `plot3D` curves
drawn as tubes. Every mapping, sampling and labelling rule is a pure function stated below and computed by a
reference module, so two engines label the same axis with the same text and place the same curve on the same
pixels. Everything a 1.7.1 document can say renders as before.

## Motivation

- **The plan depends on it.** Twelve of the catalogue's 36 shots need a coordinate system (SREP 12, Appendix A:
  shots 2, 5, 9, 11, 12 and 16 in "Math and fields", and the plots inside shots 25, 30, 33, 34, 35 and 36). The
  SRC-17 measurement (2026-10-24) scored shots 2, 11 and 12 as gaps and 5, 9 and 16 as custom, each because its
  axes and curves are hand-written shapes and expressions. Milestone 1 of the plan is "MF1 to MF5" (line 355).
- **The pieces exist but not the mapping.** SREP 70's `parametricPath` samples (x(t), y(t)) in pixel space, so
  a curve in data units is written today as `x="40 + 160 * t"`, `y="200 - 100 * Math.sin(t)"`: the author
  does the axes' arithmetic by hand in every expression, ticks are one `shape` each and labels one `formula`
  asset each (probe 11 of `conformance/tools/srep12_cases.py` spends 14 elements on one empty axes). There is no
  implicit curve at all, and no 3D axes.
- **Two engines must agree on text.** A tick label is text, and text is the one output a pixel tolerance does
  not forgive: "0.30000000000000004" against "0.3" is a wrong frame. The label rule (5) therefore fixes the
  decimals from the step, never from the float.
- **Manim and Motion Canvas authors expect it.** Manim's `Axes`, `NumberPlane`, `ComplexPlane`, `PolarPlane`,
  `ThreeDAxes`, `plot`, `plot_parametric_curve`, `plot_polar_graph` and `plot_implicit_curve` are the vocabulary
  of the catalogue's math channel; this SREP gives each a declarative counterpart.

## Specification

### Syntax

The diff is against `schema/scene-render.xsd` at 1.7.1 and `schema/scene-render.sch`. It is stated here for
the schema editor; the schema files are not changed by this draft.

**1. The `axes` node.** `nodeChoice` (xsd:5359) gains `<xs:element name="axes" type="axesType"/>`. `axesType`
has `nodeBehaviour`, `nodeAttributes` (xsd:2681), the `strokeStyle` group (xsd:326) and:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `kind` | `cartesian` \| `complex` \| `polar` \| `number-line` | `cartesian` | what the box shows (rule 9) |
| `x`, `y` | `xs:double` | 0 | the box's top-left, in the parent's pixel space |
| `width`, `height` | `positiveDecimal` (xsd:31) | required | the box, in pixels; `number-line` reads `height` as the tick band |
| `xMin`, `xMax`, `yMin`, `yMax` | `xs:double` | −1, 1, −1, 1 | the data ranges, `xMin < xMax`, `yMin < yMax` (PLT2) |
| `xStep`, `yStep` | `positiveDecimal` | the nice step of rule 4 | the tick step |
| `ticks` | `xs:boolean` | true | draw tick marks |
| `labels` | `xs:boolean` | true | draw tick labels |
| `grid` | `xs:boolean` | false | draw grid lines at the ticks |
| `tickLength` | `positiveDecimal` | 6 | pixels, centred on the axis line |
| `labelSize` | `positiveDecimal` | 14 | the labels' font size in pixels |
| `stroke` | `paintType` (xsd:159) | `#FFFFFFFF` | the axis lines and ticks |
| `strokeWidth` | `positiveDecimal` | 2 | the axis lines; ticks and the grid use half of it |
| `gridStroke` | `paintType` | the `stroke` at 25% alpha | the grid lines |
| `clip` | `xs:boolean` | true | clip plots and children to the box (rule 2); the same attribute `group` has (xsd:4597) |

Its content is `(plot | nodeChoice)*` in document order, and the group's `blend`, `effects` and `isolate`
(xsd:4570) apply as they do to a `group`. The `width` and `height` of a child node keep their pixel meaning;
only its `x`, `y`, `anchorX` and `anchorY` are read in data units (rule 9).

**2. The `plot` element.** `plotType` carries `strokeStyle`, `trimPath` (xsd:352), `strokeMarkers` (xsd:378) and:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `id` | `xs:ID` | optional | for expressions and constraints |
| `kind` | `explicit` \| `parametric` \| `polar` \| `implicit` | required | which rule samples it |
| `y` | `expressionString` (xsd:303) | — | `explicit`: y of `x`; `parametric`: y of `t` |
| `x` | `expressionString` | — | `parametric`: x of `t` |
| `r` | `expressionString` | — | `polar`: r of `theta` |
| `f` | `expressionString` | — | `implicit`: f of `x` and `y`; the curve is f = `level` |
| `x0`, `x1` | `xs:double` | `xMin`, `xMax` | `explicit`: the sampled x range |
| `t0`, `t1` | `xs:double` | 0, 1 | `parametric`: the t range |
| `theta0`, `theta1` | `xs:double` | 0, 2π | `polar`: the θ range, radians |
| `level` | `xs:double` | 0 | `implicit`: the iso-level |
| `samples` | 2 to 1000000 | 256 | points of an `explicit`, `parametric` or `polar` plot |
| `resolution` | 1 to 4096 | 64 | cells per side of an `implicit` plot's grid |
| `closed` | `xs:boolean` | false | `parametric`: the curve closes, sampled as SREP 70 rule 2 |
| `stroke` | `paintType` | `#FFCC00FF` | the curve |
| `strokeWidth` | `positiveDecimal` | 3 | the curve |
| `fill` | `paintType` | none | fill of a closed `parametric` or of an `implicit` loop |

Schematron **PLT1**: `kind="explicit"` has `y` and none of `x`, `r`, `f`; `parametric` has `x` and `y`;
`polar` has `r` only; `implicit` has `f` only. **PLT2**, on `axes` and `axes3D`: each min is below its max, as a
literal, and `xStep`, `yStep` and `zStep` are positive.

**3. `object3D primitive="axes"`.** The `primitive` enumeration (xsd:4133) gains `axes`, and `object3DType`'s
child choice gains `axes3D` and `plot3D`. **PLT3** (the pattern of PAR2): `primitive="axes"` has exactly one
`axes3D`, and only such an object has one or has a `plot3D`. `axes3DType`: `xMin`… `zMax` (defaults −1, 1 on
each axis), `width`, `height`, `depth` (`positiveDecimal`, required, scene units), `xStep`, `yStep`, `zStep`
(the nice step), `ticks`, `tickLength` (default `0.02 × min(width, height, depth)`), `lineWidth` (default
`0.01 × min(width, height, depth)`), `color` (`paintType`, default `#FFFFFFFF`). `plot3DType`: `x`, `y`, `z`
(`expressionString` of `t`, required), `t0`, `t1`, `samples` (256), `closed`, `tubeRadius` (`positiveDecimal`,
default `0.015 × min(width, height, depth)`), `tubeSegments` (3 to 64, default 8), `color` (default
`#FFCC00FF`), `material` as the object's other children have it.

**4. Version gate.** A pattern `p-srep<n>` after `p-srep75` (sch:851) with **V17**: documents of version 1.0 to
1.7 contain no `axes`, no `plot`, no `object3D[@primitive='axes']`, no `axes3D` and no `plot3D`.

### Semantics

The reference module is `conformance/tools/plots_reference.py`; function names in parentheses.

**1. The mapping** (`to_pixel`, `from_pixel`). An `axes` box maps data (x, y) to its local pixel
(px, py) = ((x − xMin)/(xMax − xMin) · width, (yMax − y)/(yMax − yMin) · height): data y grows upward, pixel y
downward (CONVENTIONS 2.1), and the box's top-left is the node's (`x`, `y`) in its parent. The inverse maps a
pixel back to data. Both are affine and exact in 64-bit floats.

**2. Clipping** (`clip_polyline`). With `clip="true"`, every plot and every child is clipped to the box
[0, width] × [0, height] before the group's own effects. A polyline is clipped segment by segment against the
four half-planes; a run of consecutive clipped segments whose ends coincide is one subpath, so a curve that
leaves and re-enters the box is drawn as several subpaths with no joining line. A boundary cut sets the cut
coordinate to the boundary value exactly.

**3. Axis lines** (`axis_position`). The x axis is drawn at data y = 0 when `yMin ≤ 0 ≤ yMax`, else at `yMin`;
the y axis at x = 0 when inside, else at `xMin`. Each is a line across the whole box with `stroke` and
`strokeWidth`. A `number-line` draws only the x axis, through the middle of its `height`.

**4. Ticks** (`nice_step`, `ticks`). The default step of an axis is the smallest s = m · 10ᵏ, m ∈ {1, 2, 5},
k an integer, with (max − min)/s ≤ 10: at most ten intervals, at most eleven ticks. The ticks of a range are
the multiples k · s inside [min, max], each computed as the product k × s, never by accumulation, with a
tolerance of 10⁻⁹ · s at both ends so 3 × 0.1 is inside [0, 0.3]. A tick is a line of `tickLength` centred on
the axis line, perpendicular to it, at half `strokeWidth`. The tick at the origin is drawn; its label is not
(rule 5).

**5. Tick labels** (`label_decimals`, `tick_label`). The label of the tick at value v with step s is the
decimal text of v with d decimals, where d is the fewest decimals (0 to 12) that write s exactly (1 → 0,
0.5 → 1, 0.25 → 2, 0.001 → 3); trailing zeros and a trailing point are removed, and −0 is written 0. On the
imaginary axis of a `complex` box the text gets the suffix i, with 1 and −1 written i and −i and 0 kept as 0.
The label at v = 0 is omitted on both axes of a cartesian or complex box, and drawn on a `number-line`. The text
is typeset as a `formula` asset typesets its `tex` (xsd:1825) at `labelSize`, in `stroke`'s colour: the x axis'
labels centred below their tick at a gap of 4 px, the y axis' labels right-aligned left of their tick at the same
gap, so the digits of "−0.5" and "0.5" align on the point. Labels that would leave the box are still drawn:
they are not subject to rule 2.

**6. Grid.** With `grid="true"`, a line in `gridStroke` at half `strokeWidth` crosses the box at every tick of
both axes, under the axis lines, ticks, plots and children.

**7. Sampled plots** (`sample_explicit`, `sample_parametric`, `sample_polar`, `split_finite`). Let N = `samples`.
- `explicit`: points (x_i, y(x_i)) at x_i = x0 + i · (x1 − x0)/(N − 1), i = 0 … N − 1.
- `parametric`: points (x(t_i), y(t_i)) with t_i as SREP 70 rule 2: Δ = (t1 − t0)/(N − 1), or (t1 − t0)/N
  when `closed`.
- `polar`: points (r cos θ_i, r sin θ_i) with r = r(θ_i) and θ_i = θ0 + i · (θ1 − θ0)/(N − 1), radians.
A point with a non-finite coordinate is dropped and breaks the path, as in SREP 70: the finite points between
two drops form one subpath each. The points are mapped by rule 1, clipped by rule 2, and the plot then draws
exactly as a `shape="path"` with that path data, the plot's `stroke`, `strokeWidth`, stroke style, trim and
markers (SREP 15) and, when `closed` or `fill` is set, its `fill`, would draw inside the box.

**8. Implicit plots** (`marching_squares`). Let R = `resolution`. The box's data range is cut into R × R
cells with corners (x_i, y_j), x_i = xMin + i · (xMax − xMin)/R, y_j = yMin + j · (yMax − yMin)/R, and
v_{i,j} = f(x_i, y_j) − level is evaluated once per corner. A corner is *below* when v < 0. In each cell:
- a cell with a non-finite corner draws nothing;
- a cell with no or four below corners draws nothing;
- a crossing on an edge whose corners differ is placed by linear interpolation of v along the edge, from the
  edge's left or lower corner; the two cells that share the edge share its crossing exactly;
- one or three below corners: one segment between the crossings of the two edges at the odd corner;
- two adjacent below corners: one segment between the crossings of the two edges that cross the boundary;
- two opposite below corners (the saddle): the mean of the four corner values decides. When it is below, the two
  below corners are joined through the centre, so the segments isolate the two above corners; otherwise they
  isolate the two below corners.
Segments with a common endpoint are joined into polylines, and a polyline that closes repeats its first point
at its end. Each polyline draws as rule 7's path: `M` at its first point, `L` at the others, `Z` when closed.
The grid resolution is the author's accuracy control; rule 12's bar is stated at R = 64 for a unit circle.

**9. Kinds and children.** `cartesian`: rules 3 to 6 on both axes. `complex`: the same with rule 5's suffix on
the y axis and the labels "Re" and "Im" typeset at the positive end of each axis, inside the box, at
`labelSize`. `polar`: no x or y axis line; instead circles at every tick of the nice step of [0, R] with
R = max(|xMin|, |xMax|, |yMin|, |yMax|), centred on data (0, 0), and twelve rays at 30° intervals, all in
`gridStroke`; the radial labels on the ray at 0°. `number-line`: rule 3's one axis, ticks and labels, no grid;
`yMin` and `yMax` are not read. A child node of the `axes` (any `nodeChoice` element) has its `x`, `y`,
`anchorX` and `anchorY` read in data units and mapped by rule 1 before its own transform; its other
attributes are in pixels, so a `shape` of `width="8"` at `x="0.5" y="0.25"` is an 8 px dot on the plane.
An expression that reads a child's `x` through `prop` reads the data value. The `track` constraint and SREP 14's
`prop` see the same data values.

**10. 3D axes and tubes** (`Axes3D`, `to_scene`, `tube_frames`, `tube`). An `axes3D` maps data (x, y, z) to
the object's local space (CONVENTIONS 2.5): s = ((x − x̄)/(xMax − xMin) · width, −(y − ȳ)/(yMax − yMin) · height,
(z − z̄)/(zMax − zMin) · depth), where x̄, ȳ, z̄ are the range midpoints, so the data centre is the object's
origin and +y data is −y scene, "up". The three axis lines, each from its min to its max through the other
two coordinates' rule-3 positions, and their ticks are cylinders of `lineWidth` and `tickLength` in `color`.
A `plot3D` samples (x, y, z)(t_i) as rule 7's `parametric`, maps the points by this rule, and draws a tube of
`tubeRadius` around the polyline: at each point the parallel-transport frame (T, N, B) is T_i the unit central
difference of the points (one-sided at the ends; the previous T where it vanishes), N₀ the unit part normal to
T₀ of the coordinate axis least aligned with T₀, N_i = N_{i−1} made normal to T_i and renormalised, B = T × N;
ring i is the `tubeSegments` vertices p_i + r (cos φ_j N_i + sin φ_j B_i), φ_j = 2πj/`tubeSegments`.

**11. The tube as a surface.** The rings of rule 10 are the vertex grid of a `parametricSurface` (SREP 70 rule
3) with U = `samples` rows and V = `tubeSegments` columns, `closedV` and, when `closed`, `closedU`; normals,
triangles, front faces and non-finite vertices follow that rule. A ring whose point is non-finite is dropped
with its two cells.

**12. Accuracy.** Each sampled point of rules 7, 8 and 10 lies on the analytic curve up to floating-point
rounding; the chord between two consecutive points of a plot deviates from the curve between them by at most
(Δ²/8) · max|f″| in data units. At the defaults this is under 0.5 px for every catalogue shot: the numeric table
records 0.0076 px for a sine over one period on a 500 px box and 0.022 px for the implicit unit circle at R = 64
on a 300 px box. An author who needs more raises `samples` or `resolution`; an engine MUST NOT resample
adaptively, so the point set is the same on every engine.

**13. Expressions and time.** `x`, `y`, `r` and `f` use the expression language of `expressionType` (xsd:522)
with the variables of their kind (`x`; `t`; `theta`; `x` and `y`) and every built-in it lists, in 64-bit floats,
evaluated at each frame as SREP 70 rule 1, so a plot that reads `time`, `prop` or `param` animates. The axes'
ranges and steps are attributes and animate through `animate` and `expression` children like any numeric
attribute. Nothing in this SREP keeps state between frames (SREP 14 rules 1 to 3): every frame is a function of
the document and the frame number, and a seek to any frame equals the frame played from 0.

## Rationale

- **A node, not an asset.** An `axes` is a `group` with a mapping, so it composes with constraints, effects,
  blend modes and clipping the way a group does, and its children can be any node. An asset would have had to
  reinvent that.
- **Children in data units, sizes in pixels.** A dot or a label placed on a plane is placed by its data
  coordinates and sized by its pixels: the Manim convention (`Dot(axes.c2p(x, y))`), and the one a camera zoom
  on the plane expects (the dot keeps its pixel size while its position follows the data).
- **The step decides the decimals.** Formatting a float by its own shortest representation prints
  0.30000000000000004 for the third tick of 0.1; formatting by the step's decimals prints 0.3 on every engine.
- **The saddle by the centre value.** Lorensen and Cline's asymptotic decider needs a bilinear model; the mean
  of the four corners is the bilinear value at the centre, gives the same topology where the model is bilinear
  and is one addition. Both engines compute it identically.
- **Parallel transport, not Frenet.** The Frenet frame flips and vanishes on straight runs; parallel transport
  keeps a tube's seam continuous along a helix and a straight line, and is what Manim's and three.js' tube
  geometries use.
- **No adaptive sampling.** Adaptive refinement puts different points on different engines and different
  points on consecutive frames of an animated plot, which jitters a trimmed path. A fixed sample set is
  deterministic and, at 256 samples, within the 0.5 px bar for every shot in the catalogue.

## Rejected alternatives

- **Draw plots through `shape="parametric"` with helper expressions** (`axes.toPx(x)`): keeps the schema
  smaller, but leaves the ticks and labels to the author and gives no implicit curves. Rejected; the probes of
  SRC-17 show what that costs.
- **A `chart` element.** The 1.x `chart` asset is a data chart (bars, lines over categories, `sr-text/chart.rs`),
  not a coordinate system; extending it with expressions would mix two models.
- **Adaptive sampling (Manim's `plot` with `use_smoothing`).** Rejected above: non-deterministic across
  engines and frames.
- **Labels as plain text, not TeX.** Minus signs, exponents and `i` typeset differently in a text font and in the
  formula font the rest of a math shot uses; one typesetter keeps a shot consistent.
- **Degrees for `theta`.** Every expression built-in (`Math.sin`) takes radians; a polar plot in degrees would
  need a conversion in each expression.

## Backwards compatibility

- Every 1.7.1 document validates and renders unchanged: `axes`, `plot`, `axes3D` and `plot3D` are new elements,
  `primitive="axes"` a new enumeration value, and no existing rule changes.
- A 1.8 document that uses them is refused by a 1.7 validator (unknown element or value), as V17 states for the
  schema's own gate.
- SREP 70's `parametricPath` is unchanged and remains the pixel-space primitive; rule 7 defines `plot` by
  reduction to it.

## Open issues

- **Arrow tips.** Manim draws arrows at the positive ends of the axes by default; this SREP draws plain lines
  and leaves tips to `strokeMarkers` (SREP 15) on the axis lines, which the Syntax table does not yet expose.
  The editor decides whether `axes` gets `markerEnd` or an `arrows` boolean.
- **Poles in implicit plots.** A function with a pole inside a cell (1/(x² + y²) − 1) has finite corners of
  opposite sign around it and draws a spurious segment; rule 8 does not detect it. A `domain` expression that
  masks cells is a candidate.
- **3D labels.** Rule 10 draws no tick labels in 3D; billboarded labels need the text-in-3D facility of
  SREP 12's MF3 row and are left to it.
- **Log scales.** `xScale="log"` is a one-line change to rule 1 and rule 4 (ticks at powers of 10) but is not in
  the catalogue; deferred to the editor.
