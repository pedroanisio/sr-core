# SREP 90 — Let SREP 87 refuse two kinds of 1.6 documents in 1.7.0

## Abstract

SREP 0 (Versioning) says that a MINOR release adds and does not break: every document valid under 1.N stays valid
under 1.N+1 and renders the same. SREP 87 scopes the ids that a `<program>` emits by the program's id, without a
version gate, and so refuses two narrow kinds of documents that schema 1.6.0 accepts. This SREP records the schema
editor's exception to SREP 0 for exactly those two kinds, so that SREP 87 keeps the class Added and enters the MINOR
release 1.7.0. It covers nothing else. No rule, declaration or picture changes.

## Motivation

SREP 87 gives each build-mode program its own id scope: an id `E` emitted by the program `P` is `P.E` in the document
(its Semantics 2). Its Backwards compatibility names two kinds of documents valid under schema 1.6.0 that it refuses
with PRG14, and its Open issues, item 7, named three ways to reconcile that with SREP 0: a version gate on document
version 1.7, the class Breaking (schema 2.0.0, with a Process SREP and a migration tool), or the class Added by an
exception that the editor grants explicitly, recorded as SREP 86 records its exception to Versioning. The schema
editor chose the exception on 2026-10-11.

SREP 0's table "When an SREP is needed" puts a change to versioning in a Process SREP, and SREP 86 (Specification 4)
says that a later SREP that wants an exception to SREP 0 needs its own Process SREP. A note in SREP 87 alone would
therefore not do.

## Specification

1. **Kinds covered.** The exception covers exactly these two kinds of documents, which SREP 87 refuses with PRG14
   (its Semantics 2) and schema 1.6.0 accepts:

   | Kind | Example | SREP 87 kit case |
   |---|---|---|
   | a document that writes an id equal to `P.E`, where `P` is the id of a build-mode program in the composition and `E` an id its output holds | `<shape id="p.g1">` beside a program `p` that emits `g1` | `srep-0066-program-id-collision` (as SREP 87 amends it) |
   | a document with two build-mode programs whose namespaced ids compose to the same value | a program `a` emitting `b.c` beside a program `a.b` emitting `c`: both produce `a.b.c` | `srep-0087-program-ids-composed-collision` |

   Schema 1.7.0 and later MAY refuse these documents, whatever version they declare, although SREP 0 (Versioning)
   requires a MINOR release to keep them valid. SREP 87's class is Added (SREP 4), and the release that carries it is
   MINOR.
2. **The third kind recorded at acceptance is not covered.** SREP 87 recorded at acceptance a third kind: a `link`
   whose `link/@source` names an emitted node, which its rules as accepted did not resolve. Its erratum of 2026-10-11
   makes the node id of `link/@source`, the overrides of an `instance` or an `include` and the bone names of skin
   weights positions of its rules 3 and 4, so such documents keep the element SREP 66 gave them. They need no
   exception, and this SREP gives them none.
3. **Nothing else.** The exception covers no other document. A document valid under schema 1.6.0 that SREP 87 is
   found to refuse, or to render differently, and that is of neither kind in item 1, is a defect of SREP 87 or of an
   engine. It is corrected under SREP 0 (Changes after acceptance), not admitted under this SREP. A later SREP that
   wants the same treatment needs its own Process SREP, as SREP 86 (Specification 4) says.
4. **Validators and engines of 1.6.0.** Neither kind is visible to the XSD or the Schematron, which do not run
   programs, so validators of 1.6.0 and of 1.7.0 give such a document the same verdict. An engine that implements
   schema 1.6.0 (SREP 66 without SREP 87) renders it; one that implements 1.7.0 refuses it when it builds the
   document, with PRG14.

## Rationale

- **No known document is affected.** Both kinds need an id that contains a `.` and equals a program's id, a `.` and an
  id its module emits. Apart from the two kit cases written for the rule, no kit case and no document with a program in
  the reference engine's corpus and examples has such an id (SREP 87, Backwards compatibility).
- **The alternatives cost more than they save.** A version gate keeps both id spaces in every engine for as long as
  documents of version 1.6 exist, for documents that no one is known to have written. Breaking makes the release
  2.0.0, with a migration tool for documents that do not exist. The exception keeps one id space and the MINOR release.
- **A closed list.** Naming the two kinds keeps the exception from becoming a precedent that later changes could cite
  without a decision, as SREP 86 does for its constructs.

## Rejected alternatives

- **A version gate on document version 1.7.** It satisfies SREP 0 as written, but it changes SREP 87's accepted rules
  (a new SREP under SREP 0, Changes after acceptance) and keeps two behaviours in every engine (Rationale).
- **Breaking, schema 2.0.0.** SREP 0 requires a Process SREP listing every breaking change and a migration tool, for
  two kinds of documents with no known instance (Rationale).
- **Recording the exception in SREP 87 alone.** SREP 0 puts a change to versioning in a Process SREP, and SREP 86
  (Specification 4) requires one for every later exception (Motivation).

## Backwards compatibility

The two kinds of item 1 are refused by schema 1.7.0 although schema 1.6.0 accepts them; that is the exception this SREP
records. No declaration, rule, message or picture changes otherwise.

## Conformance

None of its own. The two kinds are covered by SREP 87's cases `srep-0066-program-id-collision` (as SREP 87 amends it)
and `srep-0087-program-ids-composed-collision`, both refused with PRG14.
