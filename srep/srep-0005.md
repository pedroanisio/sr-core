# SREP 5 — Engine-neutral wording in the schema's comments and documentation

## Abstract

Several comments and documentation strings in `scene-render.xsd` called baseline features "rs-scene-render
extensions", and named one engine's command (`scene-render resolve`) and one transcription implementation. They
now describe the behaviour without naming an engine. No declaration changes.

## Motivation

- **The "extension" label is wrong.** Under [SREP 0](srep-0000.md), everything in the baseline is standard.
  Calling some of it one engine's extensions tells implementers those features are optional, when they are not.
- **Engine specifics don't belong in normative text.** Naming one engine's command in the documentation
  strings, which also appear in the generated reference, ties normative text to that engine's internals. SREP 0
  keeps those under "Engine impact".

## Specification

In `scene-render.xsd`, the following wording changes.

1. The comments before the screen-space lighting and path-tracer attributes, before the 2D simulations, and
   before the contact-shadow attributes drop the words "rs-scene-render extension(s)".
2. In `generatedAssetType` and `captionTrackType`, "`scene-render resolve` fills/writes the cache" becomes "a
   resolve step, run before rendering, fills/writes the cache".
3. On `captionTrackType`:
   - `@provider` reads: "The transcriber the resolve step runs to fill @cache: whisper (the Whisper speech
     recognition models), or the name of any provider program. Rendering only reads the cache."
   - `@model` and `@prompt` drop the "rs-scene-render extension" prefix.

With comments and documentation removed, the file is identical, in canonical XML, to its previous version.

## Rationale

The wording follows SREP 0's rule for engine-neutral specification. Which program performs the resolve step is
an engine's choice, reported in its own documentation.

## Rejected alternatives

- **Keeping the labels as history.** The history is recorded in `schema/CHANGELOG.md` and in git. Normative
  text should state what is true now.

## Backwards compatibility

Documentation only. Every document validates and renders as before.
