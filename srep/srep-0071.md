# SREP 71 — Add subsurface scattering, a procedural sky and generator-fed material maps

## Abstract

This SREP closes three gaps in the 3D look.

1. **Subsurface scattering.** PBR materials gain subsurface attributes, after OpenPBR: weight, colour, radius
   and per-channel radius scale. The scattering profile is stated, so jade and wax no longer depend on
   transmission tricks.
2. **A procedural sky.** A `dome` light gains `sky="gradient"`: an exactly specified zenith, horizon and ground
   gradient with an optional sun disc. Image-based lighting and chrome then work without an HDR file.
3. **Generator-fed maps.** A material's map attributes (`baseColorMap`, `normalMap` and the rest) may name a
   `generator` or `image` asset of the document with `#id`. Noise, cells (Worley) and the other generator
   kinds then feed material channels.

On the MaterialX path: the reference's MaterialX translator has no noise nodes today (checked). This SREP does not
add them (Open issues).

## Motivation

**The owner's 72-cell atlas test (2026-10-09, not published).**

- **Subsurface.** It was missing for jade and wax. This is one of the 3 cells of procedural meshes and materials,
  with SREP 70.
- **The sky.** "Ambient lighting requires an HDR file; without it the chrome is flat grey (visible in the test)."
- **Procedural textures.** "I did not see how to connect the noise and Worley generators to the channels of the
  PBR materials, nor noise nodes in MaterialX."

**Today** (schema 1.5.0, `rs-scene-render` commit `c09b58a`):

- **Subsurface.**
  - `materialType` has `transmission`, `thickness`, `attenuationColor` and `attenuationDistance` (the glTF
    KHR_materials_transmission and KHR_materials_volume terms), but no subsurface term.
  - No source file of the engine contains the word "subsurface" (searched in `crates/`). The MaterialX
    translator (`crates/sr-3d/src/mtlx.rs`) does not read the subsurface inputs of `standard_surface` or
    `open_pbr_surface`.
- **The sky.**
  - A `dome` light needs `environment`, an equirectangular file (XSD: "type="dome": equirectangular HDRI used for
    image-based lighting and reflections").
  - Without one, the reference lights the scene "uniformly, like an ambient light"
    (`crates/sr-gpu/src/render_three.rs:2126-2136`). A mirror-like material then reflects a uniform colour,
    which is the flat grey chrome the owner saw.
- **Maps.**
  - The map attributes are `xs:anyURI` files (`baseColorMap`, `normalMap`, `metallicRoughnessMap`,
    `occlusionMap`, `emissiveMap`, `displacementMap`).
  - The reference opens them as image files and uploads them as 8-bit RGBA
    (`render_three.rs:501-531`, `map_texture`). It has no path from a `generator` asset.
- **MaterialX.** The pattern-graph compiler (`crates/sr-3d/src/mtlx_graph.rs`) accepts:
  - `constant`, `image`, `tiledimage` and `texcoord`;
  - arithmetic (`add`, `subtract`, `multiply`, `divide`, `modulo`, `power`, `min`, `max`, `absval`, `floor`,
    `ceil`, `sqrt`, `sin`, `cos`, `tan`, `exp`, `ln`, `sign`, `round`, `invert`, `clamp`, `mix`, `remap`, `range`,
    `smoothstep`);
  - vector operations (`normalize`, `magnitude`, `dotproduct`, `crossproduct`, `combine2/3/4`, `extract`,
    `swizzle`, `convert`, `normalmap`).

  Any other node, including `noise2d`, `noise3d`, `fractal3d`, `cellnoise2d` and `worleynoise2d`, fails with
  "unknown MaterialX pattern node" (`mtlx_graph.rs:516`). The MaterialX path therefore cannot carry noise today.

## Specification

### Syntax

```xml
<!-- materialType gains -->
<xs:attribute name="subsurface" type="unitDecimal" default="0"/>
<xs:attribute name="subsurfaceColor" type="colorType" default="#CCCCCCFF"/>
<xs:attribute name="subsurfaceRadius" type="nonNegativeDecimal" default="10">
  <xs:annotation><xs:documentation>Mean free path in scene units (pixels), multiplied per channel by subsurfaceRadiusScale.</xs:documentation></xs:annotation>
</xs:attribute>
<xs:attribute name="subsurfaceRadiusScale" type="unitTripleType" default="1 0.5 0.25"/>

<xs:simpleType name="unitTripleType">
  <xs:restriction><xs:simpleType><xs:list itemType="unitDecimal"/></xs:simpleType><xs:length value="3"/></xs:restriction>
</xs:simpleType>

<!-- lightType gains (type="dome" only) -->
<xs:attribute name="sky" default="none">
  <xs:simpleType><xs:restriction base="xs:string"><xs:enumeration value="none"/><xs:enumeration value="gradient"/></xs:restriction></xs:simpleType>
</xs:attribute>
<xs:attribute name="skyZenith" type="colorType" default="#3A6EA5FF"/>
<xs:attribute name="skyHorizon" type="colorType" default="#C8D8E8FF"/>
<xs:attribute name="skyGround" type="colorType" default="#4A4038FF"/>
<xs:attribute name="skyExponent" type="positiveDecimal" default="0.5"/>
<xs:attribute name="sunAzimuth" type="xs:double" default="0"/>
<xs:attribute name="sunElevation" type="xs:double" default="45"/>
<xs:attribute name="sunSize" type="nonNegativeDecimal" default="0.53"/>
<xs:attribute name="sunColor" type="colorType" default="#FFFFFFFF"/>
<xs:attribute name="sunIntensity" type="nonNegativeDecimal" default="0"/>
```

The map attributes keep the type `xs:anyURI`. A value that begins with `#` is a same-document reference
(Semantics 3).

```xml
<sch:pattern id="p-srep71">
  <sch:rule context="lights/light[@sky and @sky != 'none']">
    <sch:assert id="SKY1" test="@type='dome'">sky applies to dome lights only.</sch:assert>
    <sch:assert id="SKY2" test="not(@environment)">a dome has either an environment image or a procedural sky, not both.</sch:assert>
  </sch:rule>
  <!-- one rule per map attribute; baseColorMap shown, likewise normalMap, metallicRoughnessMap, occlusionMap,
       emissiveMap and displacementMap, each in its own pattern because a pattern fires
       at most one rule per node -->
  <sch:rule context="material[starts-with(@baseColorMap, '#')]">
    <sch:assert id="MTX1-baseColorMap" test="/scene/assets/generator[@id = substring(current()/@baseColorMap, 2)]
        or /scene/assets/image[@id = substring(current()/@baseColorMap, 2)]">a material map that starts with # names a generator or image asset of the document.</sch:assert>
  </sch:rule>
</sch:pattern>
```

No version gate applies. These are new attributes with neutral defaults, accepted in every version under SREP 4.
A `#id` map value is new meaning for a value that today fails to render (the reference tries to open a file named
`#id`), so no valid rendering document changes.

### Semantics

**1. Subsurface.** With weight w = `subsurface`, the material's diffuse base lobe becomes:

    (1 − w) · (the diffuse lobe as today) + w · (the subsurface lobe)

- **Profile.** The subsurface lobe is a diffusion profile. Light entering the surface at one point leaves it at
  points at distance r (measured along the surface), with the per-channel reflectance profile:

      R_c(r) = A_c · (e^(−r/d_c) + e^(−r/(3·d_c))) / (8π · d_c · r),     with ∫₀^∞ R_c(r) · 2πr dr = A_c

- **Terms.** A_c is `subsurfaceColor` (linear working values). The shape parameter is
  `d_c = ℓ_c / s(A_c)`, with:
  - `ℓ_c = subsurfaceRadius · scale_c`, the mean free path, where `scale` is `subsurfaceRadiusScale`;
  - `s(A) = 1.85 − A + 7·|A − 0.8|³`.

  This is the normalized diffusion profile of Christensen and Burley, with their fit of the shape parameter to
  the mean free path.
- **What must hold.** An engine MAY compute this lobe by random walk (path tracing), by texture-space or
  screen-space diffusion, or by any other method. Its picture MUST satisfy:
  1. **Neutral case.** With w = 0 the picture is the picture without these attributes.
  2. **Zero radius.** As ℓ → 0 (`subsurfaceRadius="0"`), the lobe is the Lambertian diffuse lobe with albedo
     A_c.
  3. **Wrap.** With w > 0 and ℓ > 0, the radiance just past the shadow terminator (where n·l < 0) is at least the
     radiance with w = 0. It grows with ℓ.
  4. **Energy.** The lobe reflects no more energy than it receives: ∫R_c = A_c ≤ 1.
  5. **Bleeding order.** A channel with a larger ℓ_c spreads farther. With the default scale (1, 0.5, 0.25),
     light past the terminator is redder than light on the lit side.

  These properties, not one algorithm, are normative.

**2. The procedural sky.** For a dome with `sky="gradient"`, the environment radiance in a unit direction d is
defined as follows. The scene space is that of CONVENTIONS 2.1: +x right, +y down, +z forward. The dome's own
yaw, pitch and roll turn the sky as they turn an environment image (DEFINITIONS D5.1, CONVENTIONS 5.5).

- **Gradient.** Let `s = −d_y`, the sine of the elevation, with up = −y. Let Z, H and G be the linear working
  values of `skyZenith`, `skyHorizon` and `skyGround`, decoded as colour literals are (CONVENTIONS 1.4), and let
  k = `skyExponent`:

      L(d) = H + (Z − H) · s^k          if s ≥ 0
      L(d) = H + (G − H) · (−s)^k       if s < 0

- **Sun.** The sun direction is `(cos e·sin a, −sin e, cos e·cos a)` for azimuth a = `sunAzimuth` and elevation
  e = `sunElevation`, in degrees. Azimuth 0 is +z, and positive azimuth turns toward +x. Where the angle between
  d and the sun direction is at most `sunSize`/2, L(d) gains `sunColor · sunIntensity` (linear). With
  `sunIntensity="0"`, the default, there is no sun.
- **Use.** The sky then takes the place of the environment image for everything the dome does:
  - image-based diffuse and specular lighting, scaled by the dome's `intensity` and `exposure` as an image is;
  - the visible background when `environmentVisible="true"`. There it is L(d) through the camera's pixel rays,
    exact per pixel, with no texture resolution.

**3. Generator-fed maps.** A map attribute whose value is `#id` reads the document's `generator` or `image` asset
with that id, in place of a file.

- **Size.** The map's image is the asset at its declared `width` × `height`. A generator is evaluated at the
  frame's time, so its animated parameters animate the map.
- **Sampling.** UV (0, 0) to (1, 1) covers the image once, and `uvScaleX`/`uvScaleY` repeat it as for a file.
  Colour slots (`baseColorMap`, `emissiveMap`) are display-encoded and decoded to linear, as 8-bit files are. The
  other slots are read as linear data.
- **Normal maps.** A `normalMap` from a generator is read as an RGB tangent-space normal, as a file is. To bump
  with a noise generator, an author uses `displacementMap` with `displacementScale`, or bakes the normal outside the
  document. A height-to-normal conversion is an Open issue.
- **Seeds.** A generator's seed rules apply unchanged, so a noise map is the same on every render.

### Defaults and the neutral case

- `subsurface` is 0 (Semantics 1, item 1).
- `sky` is `none`, so a dome without an image still lights uniformly as today.
- A map that does not begin with `#` is a file, as today.

The other new attributes are read only when these are set.

## Rationale

- **The OpenPBR parameters.** Weight, colour, radius and radius scale are the subsurface interface of OpenPBR
  Surface 1.1.1. MaterialX `open_pbr_surface` documents carry these values, so a later translator can map them
  one to one. OpenPBR's default radius scale is (1.0, 0.5, 0.25); this SREP keeps it. Its default radius is 1 in
  scene units. One pixel is too small for that to be a useful default, so this SREP uses 10 px.
- **Properties, not an algorithm, for subsurface.** Random walk and screen-space diffusion give different pictures.
  Requiring either one would rule out the other renderer of the reference, which has a raster path and a path
  tracer. The five properties are what a viewer checks: no change at 0, Lambert at radius 0, wrap, energy, and
  colour bleeding.
- **A gradient sky, not a physical one, as the normative default.** It is exact, it has a closed form for the kit,
  and it fixes the flat chrome. A physical model (Preetham 1999; Hosek and Wilkie 2012) is a later enumeration
  value, `sky="physical"`, once its tables are pinned (Open issues).
- **`#id` in the existing attributes.** No new attribute per channel, and the asset-kind check follows SREP 28.

## Rejected alternatives

- **New `*Generator` attributes per channel** (`baseColorGenerator="g"`): six more attributes for one idea.
- **Noise nodes in the MaterialX graph as the route to procedural maps.** MaterialX defines its noise nodes by
  reference shader code, not by formulas in the specification. Making them deterministic across engines means
  pinning that code. The generator assets already have seeded definitions in the format.
- **A sky as a new light type** (`type="sky"`): the sky is an environment, so it belongs on the dome, which already
  owns image-based lighting and the visible background.

## Backwards compatibility

The change is MINOR and adds neutral attributes. As noted under Syntax, the meaning given to `#id` map values only
affects documents that fail to render today.

## Conformance

The cases are in `conformance/srep_cases/srep-0071.json`, written by `conformance/tools/srep71_cases.py`, which
evaluates the sky along the implicit camera's pixel rays. All are pending.

| Case | Checks | Tolerance |
|---|---|---|
| `srep-0071-sky-gradient` | five background pixels follow L(d) with exponent 1 (2) | 3 code values |
| `srep-0071-sky-horizon` | the horizon row is the horizon colour (2) | 3 |
| `srep-0071-sky-sun` | a 5° red sun straight ahead is a disc of radius 24.2 px at the centre (2) | 2 px |
| `srep-0071-sky-sun-azimuth` | azimuth 10° and elevation 5° place the sun right of and above the centre (2) | 2 px |
| `srep-0071-sky-not-dome`, `-sky-and-environment` | SKY1, SKY2 | exact |
| `srep-0071-map-generator` | a solid green generator as `baseColorMap` of an unlit plane (3) | 2 px |
| `srep-0071-map-not-an-image-source` | MTX1-baseColorMap | exact |
| `srep-0071-subsurface-zero-neutral` | weight 0 equals the render without subsurface (1, item 1) | needs a render-comparison form in the kit |
| `srep-0071-subsurface-wraps-terminator` | weight 1 brightens past the terminator (1, item 3) | needs a render-comparison form in the kit |

**Assumption, not checked:** that the visible dome background is written without tone mapping, so that L(d)
appears as its own code value. If the reference applies a view transform to the environment, the sky cases need its
inverse, or a statement under Semantics 2.

## Open issues

- `sky="physical"` (Hosek–Wilkie or Preetham) with pinned coefficient tables.
- A height-to-normal option for generator maps (`normalMapMode="height"`).
- MaterialX noise nodes, if their reference code is pinned.
- `subsurfaceAnisotropy` (OpenPBR `subsurface_scatter_anisotropy`): meaningful only for volumetric random walks.
  It is left out of this draft.
