# SREP 43 — Attach 3D elements to a joint of an imported model

## Abstract

A 3D element (`object3D`, `particles3D`; a `camera` or `light` through its constraint) can have a parent (`@parent`,
or a `transformConstraint` of type `parent`). When that parent is an `object3D` that draws an imported model, the new
attribute `parentJoint` (and `targetJoint` on a constraint) names a node of the model, the joint, and the element is
placed in the frame of that node as the model's clip poses it, frame by frame. A prop in a hand, a light on a head, a camera on a wrist and a
particle emitter on a shoulder then follow the animation without baking. A document that uses neither attribute renders
as before.

## Motivation

The NOLN glTF/FBX assessment lists "attach a node or constraint to an imported joint (strings to wrists, prop in hand)"
as not found, and asks for "joint sockets: let a node, wire end or constraint target `model#jointName`" (NOLN glTF/FBX
assessment, §A and §D item 3). With the baseline the only parent an element can have is another element's own frame, which
for an imported model is the model's origin: a held prop stays at the origin while the hand moves. The only workaround is
to bake the prop into the model or to copy the joint's motion by hand.

## Specification

### Syntax

```xml
<!-- object3DType and particles3DType gain -->
<xs:attribute name="parentJoint" type="xs:string">
  <xs:annotation><xs:documentation>With a @parent (or a transformConstraint of type="parent") that is an object3D
  drawing an imported model: the name of a node of that model. The element is placed in that node's frame as the model's
  clips pose it, instead of in the object's own frame. The first node of that name in the model's node order is used.
  </xs:documentation></xs:annotation>
</xs:attribute>
<!-- transformConstraintType gains -->
<xs:attribute name="targetJoint" type="xs:string">
  <xs:annotation><xs:documentation>With a @target that is an object3D drawing an imported model: the name of a node of
  that model whose pose is the target's transform (parent, copy-position, copy-rotation, copy-scale, copy-transform,
  look-at and distance).</xs:documentation></xs:annotation>
</xs:attribute>
```

```xml
None.
```

New attributes with no default, accepted in every version (SREP 0, Versioning). That the parent draws a model with a node of
that name is decided at evaluation, where the model is loaded (Semantics 3).

### Semantics

**1. The joint frame.** Let O be the parent object, `W_O` its world matrix (as for any parent), `B` the model's
source-to-scene axis and unit conversion with `u` its uniform scale (scene units per model unit, the length of the image
of the model's x axis), `S` the inverse of the selected node's model-space world matrix when O has `@node` (identity
otherwise), and `J` the model-space world matrix of the named joint at the frame's pose. The pose is the pose O draws: its
clips at O's time, blended as `@animationBlend` says (SREP 42). The joint's frame is

```
F = W_O · B · S · J · scale(1/u)
```

The factor `scale(1/u)` takes the unit conversion out of the frame (a joint 0.6 model units from the origin is `0.6·u`
scene units away, and a child one scene unit from the joint is one scene unit from it), so that the element's own
transform is in scene units. It is applied as `W_element = F · local`, exactly as it would be in `W_O` without the joint. A
constraint's `@influence` weights `F` as it weights `W_O`. A constraint with `@targetJoint` uses `F` as the target's
world matrix for every constraint type that reads one: its position for `look-at` and `distance`, its rotation, scale or
whole transform for the `copy-*` types, its whole frame for `parent`.

**2. Scale.** `J` carries the joint's scale. A child therefore scales with a joint that scales, as a child of any
scaled parent does.

**3. Errors.** When the parent is not an `object3D` that draws an imported model, or no node of the model has the
name, the engine MUST report it and the element is placed as if the attribute were absent.

**4. Skinned joints.** The joint is a node of the model, not a vertex: it is at the node's pose, and does not follow
vertex deformation of skinned or morphed primitives other than through the node's own transform.

### Defaults and the neutral case

Neither attribute set: parents resolve to the parent object's frame, as before.

## Rationale

- **A name, not a path.** glTF, FBX and USD name their nodes; indexes change when a file is re-exported. The same
  choice as `@node` (SREP 38) and for the same reason.
- **A separate attribute rather than `parent="model#joint"`.** `@parent` is an IDREF; changing it to a string
  would lose the validation of ordinary parents.
- **Full frame, not only the position.** A held prop turns with the hand; a position-only attachment would leave it
  upright.
- **`W_O · B · S · J` is the placement the engine already gives the joint's own geometry** (`W_O · B · S · J ·` the
  primitive's mesh), so a child at the joint's origin sits where a mesh attached to that joint would be drawn; only the
  unit conversion is taken out, because authors place children in scene units.

## Rejected alternatives

- **`model#jointName` inside `@parent`.** See above.
- **Attaching to a vertex or a skin weight position.** Needs a vertex selection and is a different feature.
- **A `<socket>` element on the model with its own offset.** The element's own transform already is the offset.

## Backwards compatibility

Class: Added, MINOR in effect, accepted in every version. No valid document changes validity or rendering.

## Conformance

| Case | Checks | Tolerance |
|---|---|---|
| `srep-NNNN-joint-socket` | a model with a clip that moves one joint 0.6 m: an object with `parentJoint` of that joint is drawn displaced by 60 px at the end of the clip, and unmoved at its start | 1.5 px |
| `srep-NNNN-joint-socket-rotate` | a joint rotated 90°: a child offset 0.5 m along x lands on y | 1.5 px |
| `srep-NNNN-joint-socket-unknown` | an unknown joint name is reported and the child sits in the object's frame | exact |

## Open issues

- Whether a 2D `link` or stroke end (a wire) can take a joint as its end: it needs a projection of the joint into the 2D
  frame, which depends on the camera.
- Motion blur sub-frames: the Rust reference evaluates the joints at each sub-frame time.
