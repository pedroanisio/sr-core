# SREP 8 — Close the version gate and check the 1.1 additions

## Abstract

The Schematron rules did not keep up with the elements and attributes that scene format 1.1 gained:
- `version="1.0"` documents could use 1.1 elements;
- paint and token references on newer attributes went unchecked;
- several references could name the wrong kind of element;
- several attributes took values with no meaning.

This SREP adds the missing rules and tightens four value types. Under SREP 4 these are corrections, because
they reject only documents whose meaning was undefined. They ship as schema 1.1.3.

## Motivation

A review found each of these documents passing both the XSD and the Schematron:
- `flock`, `slime`, `geo` and `map` under `version="1.0"`;
- `slime colorLow="url(#nope)"`;
- `flock shape="sprite"` with no sprite;
- `forceFields` naming nothing;
- an `erosion` heightmap naming an audio asset;
- `clay` with no blobs;
- a `fluidSource` ending before it starts;
- `<flock id="f" parent="f">`;
- `pin lat="200"`, `route points="hello world"`, `palette="banana"` and `domain="5 1 3"`.

The same checks on older node types did reject: R10 for a self-parented shape, R24 for a bad `fill`
reference. So the gaps were omissions, not decisions.

A comparison of the 1.1 XSD with the 1.0 schema found 19 elements and 7 `object3D` primitives that 1.1 added
and the version gate never mentioned. The reviewer's list was a subset of these.

## Specification

The Schematron gains patterns p50–p60.

1. **V6.** A `version="1.0"` document contains none of `audioEffect`, `blob`, `burst`, `bus`, `destination`,
   `erosion`, `flock`, `fluid`, `geo`, `map`, `master`, `param`, `pin`, `poster`, `representation`, `shake`,
   `slime`, `span` or `thumbnail`. These are the 1.1-only elements reachable from a context 1.0 allows.
   The rest are already gated through their sections by V1–V4.
2. **V7.** A `version="1.0"` document has no `object3D` with the 1.1 primitives `capsule`, `clay`, `cone`,
   `cylinder`, `extrude`, `text` or `torus`.
3. **R30-\*.** `url(#id)` must name an element of `paints` on every paint-typed attribute, not only the eight
   R24 lists. The additions are `colorEnd`, `colorHigh`, `colorLow`, `headFill`, `noData`, `outline` and
   `paint2`.
4. **R31-\*.** `var(--name)` must name a `styles/token` on every colour or paint attribute, not only the eight
   R25 lists. There are 15 additions, from `attenuationColor` to `specularColor`.
5. **C50.** `shape="sprite"` on `flock` or `particleEmitter` requires `@sprite`.
6. **R32.** `@sprite` names an image, image-sequence, video or generator asset.
7. **R33.** `erosion/@heightmap` names an image asset.
8. **R34.** Every id in `@forceFields` names a `physics/forceField`.
9. **R35.** `@textStyle` names a `styles/textStyle`.
10. **C51.** `object3D primitive="clay"` has at least one `blob`.
11. **C52.** A `fluidSource` with both `start` and `end` ends after it starts.
12. **C53.** `geoLayer/@domain` values increase.
13. **R10** applies to every element with both `@parent` and `@id`, not only the ten node types it listed.
14. **Renumbering.** The geo reference checks, until now `R24` and `R25` and sharing those numbers with the
    paint and token checks, become `R36` (geoLayer/@geo) and `R37` (route/@geo).
15. **XSD types.**
    - Latitudes (`pin`, `flyTo`, map `centerLat`) are in [−90, 90], and longitudes in [−180, 180].
    - `route/@points` is two or more `lon,lat` pairs.
    - `geoLayer/@palette` is a whitespace-separated list of colours.

## Rationale

- **The gate is computed, not listed by hand.** It covers every 1.1-only element that can appear under an
  element 1.0 allows, which is why it is wider than the reviewer's list.
- **Rules are generic by attribute** (every paint attribute, every element with `@forceFields`), so the next
  attribute of that type is checked without editing the rule.
- **The reference implementation shows the meaning was undefined:**
  - it silently draws streaks when `shape="sprite"` has no sprite;
  - it drops palette entries it cannot parse;
  - it resolves a heightmap only from a still image.

## Rejected alternatives

- **Treating these as Breaking and waiting for 2.0.** Every rejected document either rendered something the
  author did not ask for, or failed at render time. A major version would signal a migration that nobody
  needs.
- **Adding the new names to V3 and V4.** New patterns keep the change separate from rules that pending SREPs
  also edit.

## Backwards compatibility

Correction under SREP 4: it rejects only documents whose meaning was undefined. All 110 scene documents found
locally (productions, engine examples, conformance cases) were validated with 1.1.2 and 1.1.3. One verdict
changed: a debug variant (`nophys.scene.xml`) whose physics section had been removed while a
`forceFields="pullAO"` reference to it remained. Documents keep `version="1.1"`.
