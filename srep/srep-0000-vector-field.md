# SREP 0 — Add vector-field layers to the map

## Abstract

SREP 12's M4: **wind and ocean currents** as moving particles on a map. A **`uvGrid`** asset names one or more
**GRIB2** or classic **NetCDF** files holding the two horizontal components of a field (`u` eastward, `v`
northward, in m s⁻¹) and, after the **resolve step**, one **`cache`** file (a classic NetCDF file in its
**64-bit offset** variant, CF-1.8) whose SHA-256 the document pins in **`cacheSha256`**; the renderer reads only
the cache. A **`flow`** map child advects **`particles`** through the cache after **webgl-wind** (**ISC**,
Mapbox and Vladimir **Agafonkin**): each frame the trail is faded by `floor(255 c fade) / 255`, every particle
is painted with the **`colors`** ramp at its speed fraction, then moved by a **midpoint** step of
`speedup / fps` data seconds in metres mapped to degrees through R and **cos**(latitude), and dropped with
probability `dropRate + speed · dropBump` to respawn at a position drawn from the element's **random-streams**
(purposes `spawnX`, `spawnY`, `drop`, step = frame, index = particle). The field at a frame is sampled
**bilinear**ly in longitude and latitude and linearly in time at the data time T = **`timeOrigin`** +
**`time`** (the time-series draft's data time). Frame k is the replay of frames 0 to k from the same seeds, so a
frame rendered alone equals the played frame (SREP 14's **seek check**). Validation rules VF1–VF4, warnings
W-VF1 and W-VF2, the schema gate V20. Reference `conformance/tools/vector_field_reference.py` (**numpy**; it
also carries the GRIB2 and NetCDF writers and readers the tests use), tests `tests/test_vector_field.py`.
Engine card [SR-115](https://faz-ai.atlassian.net/browse/SR-115).

## Motivation

A weather explainer shows the jet stream and a storm's inflow; an ocean explainer shows the Gulf Stream and
the gyres. The data is public: NOAA's **GFS** forecasts ship as GRIB2 (10 m wind as `UGRD` and `VGRD` at
surface type 103, value 10) and NASA's **OSCAR** surface currents as NetCDF, both in the **public domain** or
under open terms (open issue 1). SREP 9 draws tiles and geo features, the data-layers draft colours grids, and
nothing in the format moves. Authors today render webgl-wind in a browser and screen-record it, which is
neither reproducible nor seekable, and the recording's particles differ from run to run because the browser
seeds them from `Math.random`. SREP 12 names this gap (M4: vector fields, wind particles) and the
random-streams draft gives the tool: a deterministic draw per particle per frame. This draft reads the two
public formats, pins the resolved field, and defines the particle animation pixel for pixel.

## Specification

### Syntax

A new asset kind, `uvGrid`:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `src` | xs:string, one or more | required | The source files or URLs, GRIB2 or classic NetCDF, in the resolve step's order. |
| `format` | auto, grib2, netcdf | `auto` | The sources' format; `auto` sniffs the magic (`GRIB`, `CDF`). All sources share one format (VF1). |
| `u` | xs:string | `UGRD` | The eastward component: a GRIB2 parameter (`UGRD`, `VGRD` or `discipline:category:number`) or a NetCDF variable name. |
| `v` | xs:string | `VGRD` | The northward component, as `u`. |
| `surface` | xs:string | `103:10` | GRIB2 only: the first fixed surface as `type` or `type:value` (103:10 is 10 m above ground). |
| `cache` | xs:string | required | The flow cache the resolve step writes and the renderer reads (section 3). |
| `cacheSha256` | xs:string | required | The SHA-256 of the cache file, 64 hex digits; the renderer refuses a cache that differs (VF1). |
| `credit` | xs:string | absent | The data's attribution, copied into the cache's `credit` attribute. |

A new map child, `flow`, drawn in the map's child order:

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `grid` | xs:IDREF | required | A `uvGrid` asset (VF3). |
| `timeOrigin` | xs:string | `0` | A time (time-series draft rule 1): the data time at `time` 0. |
| `time` | xs:double, animatable | `0` | Data seconds added to `timeOrigin`; T selects the field's time step. |
| `particles` | xs:positiveInteger | `65536` | Particles alive at every frame, 1 to 1 000 000 (VF2). |
| `speedup` | positiveDecimal | `6000` | Data seconds a particle advances per composition second; a frame moves it `speedup / fps` seconds of flow. |
| `fade` | xs:decimal | `0.996` | The trail's per-frame factor, 0 to below 1 (VF2); webgl-wind's `fadeOpacity`. |
| `dropRate` | xs:decimal | `0.003` | The per-frame probability a particle respawns, 0 to 1 (VF2). |
| `dropBump` | xs:decimal | `0.01` | Added to `dropRate` in proportion to the particle's speed fraction, 0 to 1 (VF2). |
| `colors` | stop list | webgl-wind's ramp | Colour stops `position:colour` with positions increasing in 0..1 (VF2); the speed fraction selects the colour. |
| `seed` | xs:long | absent | The element seed of the random-streams draft; absent is the empty seed field. |
| `strokeWidth` | positiveDecimal | `1` | The particle's size in pixels; 1 paints the pixel holding it, larger values a disc. |
| `opacity` | xs:decimal | `1` | Multiplies the painted colour, 0 to 1 (VF2). |

The default `colors` are webgl-wind's: `0:#3288bd 0.1:#66c2a5 0.2:#abdda4 0.3:#e6f598 0.4:#fee08b 0.5:#fdae61
0.6:#f46d43 1:#d53e4f`.

**Validation** (an engine reports every rule it can check):

- **VF1** (error): a `uvGrid` whose `format` is not `auto`, `grib2` or `netcdf`; whose `u` or `v` is neither a
  GRIB2 parameter nor a variable name; whose `surface` is not `type` or `type:value`; without `src`, `cache` or
  a 64-digit `cacheSha256`; or whose cache file's SHA-256 differs from `cacheSha256`.
- **VF2** (error): a `flow` whose `particles` is not an integer in 1..1 000 000, `speedup` or `strokeWidth` is
  not positive, `fade` is outside [0, 1), `dropRate`, `dropBump` or `opacity` is outside [0, 1], `seed` is not an
  integer, or `colors` is not a list of stops with increasing positions in 0..1 and parseable colours.
- **VF3** (error): a `flow` whose `grid` does not name a `uvGrid` asset.
- **VF4** (error): a `timeOrigin` that is not a time, or a `time` that is not a number or keys of numbers.
- **W-VF1** (warning): the data time T of a frame lies outside the cache's time span; the field is held at the
  nearest step and the warning is reported once per flow.
- **W-VF2** (warning): at resolve, a valid time holding only one of the two components; the step is dropped and
  reported once per asset. When no step is complete the resolve step fails.
- **V20** (error): a `uvGrid` or `flow` in a document before version 1.8, or an attribute the schema does not
  declare on them.

### Semantics

1. **GRIB2 reading.** `grib2_messages`: a source is a sequence of GRIB2 messages (edition 2; the indicator's
   `GRIB`, discipline at octet 7, edition at octet 8, total length in octets 9–16; the trailer `7777`); each
   message's sections 1 (reference time), 3 (grid definition **template 3.0**, latitude-longitude: Ni, Nj, the
   first and last points, the increments in units of 10⁻⁶ degrees, the scanning mode), 4 (product definition
   template 4.0: category, number, the forecast time with its unit from code table 4.4, the first fixed
   surface), 5 (data representation **template 5.0**, **simple packing**: the reference value R as IEEE
   float32, the binary scale E and decimal scale D in **sign-magnitude** form, the bit count), 6 (bitmap:
   indicator 255 none, 0 present) and 7 (the packed values, most significant bit first). Regulation 92.9.4
   gives each value as Y = (R + X·2^E) / 10^D (`simple_values`); a bitmap's absent points are missing. Other
   grid, product or data templates, other scanning modes than i consecutive with either direction, a wrong
   edition, a truncated message or a missing trailer are errors, not guesses. The reader normalises every
   field to rows north to south and columns west to east and reports the grid's north-west corner.
2. **NetCDF reading.** `netcdf_read`: a source is a classic NetCDF file (`CDF` 1, the classic format, or
   `CDF` 2, the 64-bit offset format, of the Unidata specification: the record count, the dimension list, the
   global attributes, the variable list with each variable's type, size and begin offset; big-endian values;
   header padding of zero bytes, data padding of the type's fill value; record variables interleaved per
   record). A variable's values apply **`_FillValue`** and `missing_value` (missing), then **`scale_factor`**
   and `add_offset` (`netcdf_values`). NetCDF-4 (HDF5) files are not read: the resolve step converts them with
   **netCDF-C** (BSD-3) or **ecCodes** (**Apache-2.0**), as it converts a GRIB2 file in another template, and
   records the tool in the cache's `history` (open issue 2). The reference's writer reproduces the
   specification's examples byte for byte (the 32-byte empty file, the 92-byte `tiny` file).
3. **Resolve step.** `resolve`: for GRIB2 sources, the messages whose parameter is `u` or `v` and whose first
   surface is `surface` are grouped by valid time (reference time + forecast time); every message lies on one
   grid (else an error); a valid time with both components is a step, one with a single component is dropped
   (W-VF2). For NetCDF sources, `u` and `v` name variables on dimensions (time, lat, lon) in that order whose
   coordinate variables carry CF `units` (`… since …` for time, read by `time_units`); rows are flipped to
   north to south when the latitudes ascend; files are merged by time. The steps are written as the **flow
   cache** (`flow_cache`): a 64-bit offset NetCDF file with dimensions `time`, `lat`, `lon`; `time` in seconds
   since 1970 (double), `lat` north to south and `lon` increasing (float), `u` and `v` in m s⁻¹ (float, NaN
   where missing); global attributes `Conventions` = **CF-1.8**, `title` and `credit`. The writer is
   deterministic, so the same sources give the same bytes and `cacheSha256`. The renderer reads the cache
   alone and refuses one whose SHA-256 differs (VF1).
4. **Sampling.** `sampler`: the field at (λ, φ, T) is bilinear in longitude and latitude on the cache's grid
   and linear in time between the two steps around T, clamped to the first and last step; a grid whose
   longitudes close the circle (`wraps`: the step past the last longitude reaches the first plus 360°) wraps,
   otherwise a point outside the grid has no value; a point whose contributing corners (those with positive
   weight) include a missing value has no value. A frame whose T lies outside the cache's time span is
   warned once (W-VF1).
5. **Data time.** `frame_time`: T = `timeOrigin` + `time` at the composition time `frame / fps`, with `time`
   read as the time-series draft reads animated numbers; `data_time` is its rule 2.
6. **Streams.** `element_seed`, `stream`: the element seed is E(project seed, `id`, `seed`, `"stream"`) of the
   random-streams draft, and a draw is S(E, purpose, step, index) = U(E, purpose + step·2³², index) with the
   purposes `spawnX` = 1, `spawnY` = 2 and `drop` = 3, step the frame and index the particle. Draws are
   addressed, never sequenced: a particle's draw at a frame does not depend on how many draws came before.
7. **Spawn.** A particle i starts at frame 0 at pixel (S(E, spawnX, 0, i)·w, S(E, spawnY, 0, i)·h) of the map's
   w × h window; a particle respawned in the update of frame k takes (S(E, spawnX, k+1, i)·w,
   S(E, spawnY, k+1, i)·h).
8. **Fade.** `fade_buffer`: at every frame, before painting, each channel c of the trail buffer becomes
   `floor(255 · c · fade) / 255`, webgl-wind's quantised fade, so that a trail reaches exactly zero.
9. **Paint.** `paint`, `ramp_colour`, `speed_fraction`: each particle with a field value is painted with the
   `colors` ramp at its speed fraction min(1, |v| / v_max) — v_max the cache's largest speed — interpolated
   linearly in straight RGBA between stops and then premultiplied, multiplied by `opacity`, composited
   source-over. `strokeWidth` ≤ 1 paints the pixel holding the particle (floor of its coordinates); a larger
   width paints every pixel whose centre lies within `strokeWidth` / 2 of it. Particles without a field value
   paint nothing. The map child paints the buffer where it sits in the map's child order.
10. **Advection.** `sphere_step`: after painting, each particle moves by one **midpoint** (RK2) step of
    h = `speedup` / fps seconds: with (u, v) the field at its position and (u', v') the field at the half-step
    point, the new longitude is λ + u'·h / (R cos φ') in degrees and the new latitude φ + v'·h / R, with φ' the
    half-step latitude and R = 6378137 m; a step past the poles or a particle without a field value is
    dropped. `plane_step` is the same rule in metres on the plane; in a **solid-body** field (u = −ωy, v = ωx)
    the step keeps a particle on its **analytic circle** to the order of (ωh)⁴ per step (numeric table).
11. **Drop.** A particle whose new position lies outside the window, whose field value is missing, or whose
    draw S(E, drop, k, i) < `dropRate` + speed fraction · `dropBump` respawns (rule 7); the others take their
    new position. `run` reports the respawns of the last update.
12. **Seek check.** `run`, `trace`: frame k is the replay of frames 0 to k from the spawns of rule 7 and the
    draws of rule 6; nothing is read from a previous render, so a frame rendered alone equals the played frame.
    `trace` returns the trail digests of frames 0 to k from one replay and `trace(doc, k)[j]` equals
    `run(doc, j)`'s digest.

## Rationale

- **Two public formats, one cache.** GFS is GRIB2 and OSCAR is NetCDF; reading both at render time would put a
  packing library in every engine. The resolve step reads them once (the reference shows the subset that
  needs no library) and the renderer reads one small, pinned, classic NetCDF file.
- **A classic NetCDF cache.** The classic format is a 15-rule grammar an engine implements in an afternoon;
  it needs no HDF5, and any NetCDF tool opens it for inspection.
- **webgl-wind's rules.** Its fade, drop and ramp are what every wind map since 2016 looks like; the draft
  takes the numbers (0.996, 0.003, 0.01, the ramp) and the quantised fade so the look is preserved and the
  trail ends.
- **Metres, not texture units.** webgl-wind moves particles in texture space with a 1/cos(latitude)
  distortion; the draft moves them in metres with a midpoint step so that `speedup` has units (data seconds
  per composition second) an author can reason about, and a particle at 60° N travels as far as one at the
  equator.
- **Random streams.** Spawn and drop draws come from the random-streams draft's addressed streams, so a frame
  needs no history beyond its replay and two engines agree particle for particle.
- **Replay for the seek check.** A particle system has state; the only way a frame rendered alone equals the
  played frame is to replay from frame 0. The replay is cheap (the reference replays 256 particles for 36
  frames in well under a second) and bounded by the frame index.

## Rejected alternatives

- **Streamlines or arrows instead of particles.** Rejected for M4: particles are what the plan and the public
  expect; a static `arrows` style is open issue 4.
- **Reading GRIB2 and NetCDF in the renderer.** Rejected: the resolve step already exists (SREP 9) and the
  renderer stays free of packing libraries.
- **Storing the cache as PNG as webgl-wind does.** Rejected: 8-bit components lose 0.4 % of the range per
  step and the PNG carries no coordinates, times or attribution.
- **Euler steps as in webgl-wind's shader.** Rejected: at `speedup` 6000 an Euler step spirals out of a
  vortex visibly; the midpoint step is one more sample per frame.
- **A per-engine particle count.** Rejected: `particles` is part of the picture (coverage); an engine that
  cannot afford it reports it rather than thinning silently.

Properties that hold for every input: a frame's result is a pure function of the document and the frame
index; the GRIB2 writer's output decodes to the input within half a packing step and the NetCDF writer's output

every digest changes whenever a painted pixel changes by 1/1000; the number of live particles is constant.

### Kit cases

To be measured on the engine (SREP 14's seek check applies to each):

1. `uvgrid-grib2`: two GFS-style GRIB2 files with U and V at two forecast hours and one unpaired U; the
   resolved cache's bytes and SHA-256 equal the reference's, with W-VF2.
2. `uvgrid-netcdf`: an OSCAR-style NetCDF file with `uo` and `vo` on ascending latitudes and `days since`
   time; the cache equals the GRIB2 case's within 1e-3 m s⁻¹.
3. `flow-frame-12`: the example at frame 12; the trail buffer equals the reference's pixel for pixel (1/255)
   and the respawn count is 11.
4. `flow-seek`: frames 0, 5, 12 and 36 rendered alone equal the played frames pixel for pixel; frame 36 carries
   W-VF1.
5. `flow-circle`: a solid-body cache (open issue 3) with one particle; after 100 frames its ground distance
   from the centre is within 1e-5 of the start.
6. `vector-field-errors`: the bad document; the engine reports VF1–VF4 and V20 and renders nothing for the
   invalid flow.

   classic`, ecCodes' `grib_set` to simple packing) and how the cache's `history` attribute records it.
3. A synthetic `uvGrid` (an analytic field written by the resolve step) for kit case 5, or a tiny cache
