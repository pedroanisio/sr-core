# SREP 14 — Adopt design rules for simulation, space and geodata SREPs

## Abstract

SREP 0 sets four design rules for every SREP: neutral defaults, determinism, one space and an engine-neutral
specification. This SREP adds eight rules that apply to SREPs adding simulations, random or procedural values,
external data or external coordinate frames: time, randomness, order independence, units and frames,
agreement between engines, validation, pinned external data, and permissive sources. It changes how the
compatibility kit compares such SREPs' results: a seek check within one engine, and tolerances each SREP
states and justifies between engines. It changes no schema and no rendered picture.

## Motivation

[SREP 12](srep-0012.md) plans about fifty Standards and Semantics SREPs for science-explainer video: fields,
space, optics, 3D simulation, terrain, weather and map layers. They share concerns that SREP 0's rules do not
settle:

- how a stepped simulation reaches a frame when an engine seeks to it;
- which generator produces random values, now that D24 already defines one;
- how results are compared between engines when floating-point simulations cannot match bit for bit;
- how geographic, celestial and planetary frames fit the rule that there is one space;
- which code and data a reference implementation may depend on.

A draft of SREP 12 stated these rules itself. They bind future SREPs and change how the compatibility kit
compares results, and SREP 0 requires a Process SREP for a change to the kit's thresholds. They are stated
here instead, once, so that each later SREP cites them rather than restating them.

## Specification

**Scope.** These rules apply to every Standards or Semantics SREP that adds a simulation, a random or
procedural value, a dataset resolved from outside the document, or a coordinate frame other than scene pixels.
They add to the design rules of SREP 0 and do not relax them. Each such SREP MUST state how it meets each rule,
or, under **Backwards compatibility**, why it cannot.

1. **Time.** A simulation MUST advance in fixed steps of a stated length from its own declared start. Its state
   at composition time t MUST be the state after stepping from the start to the last step at or before t, and
   MUST NOT depend on which frames were rendered before, or in what order. Engines MAY keep checkpoints; the
   specification fixes only the result. Where the SREP adopts a closed form in time (for example ocean
   spectra or analytic stream-power relief), the frame MUST be that closed form evaluated at t, and no state is
   kept. The SREP MUST say what a frame between two steps shows (the earlier step, or a stated
   interpolation).
2. **Randomness.** Every random or procedural value MUST be a function of `project/@seed`, the element's seed
   and integer indices (for example cell, particle, step), computed from the D24 lattice hash
   H(s, c, i) = splitmix64(s ⊕ splitmix64(c ⊕ splitmix64(i))) of `conformance/DEFINITIONS.md` (convention
   5.19), and from the derived draws that a Semantics SREP on random streams defines on top of it. No generator
   MAY carry state across elements or across steps, and no library generator MAY be used.
3. **Order independence.** Results MUST NOT depend on evaluation order or on the number of threads. Updates
   SHOULD be specified as functions of the previous step's state (gather form). Where contributions are
   summed, the SREP MUST state the order of summation or specify exact (integer or fixed-point)
   accumulation.
4. **Units and frames.**
   - Lengths are scene pixels; physical quantities convert through `physics/@pixelsPerMeter`, as for existing
     physics. Terrain heights and water and snow depths are pixels in the element's space. Temperatures are
     kelvin, times seconds, and angles follow the baseline's conventions.
   - A document MAY give inputs in an external frame: geographic coordinates and map projections, the ICRF,
     body-fixed planetary frames. The SREP that introduces such a frame MUST define its mapping into scene
     pixels, as [SREP 10](srep-0010.md) maps one map pixel to one scene unit. Every position that the document
     animates, measures or constrains MUST be in scene pixels.
   - Engines MAY compute in double precision and rebase coordinates internally (a floating origin) where
     single precision cannot hold the range. Such a frame MUST NOT be exposed to the document as a second
     space.
5. **Agreement between engines.**
   - Within one engine, the same document, inputs and frame MUST give identical pixels whether the frame is
     rendered alone or after playing from the start (the seek check).
   - Between engines, and between one engine's GPU and CPU paths, results are compared by the compatibility
     kit's geometric measurements, with the tolerance each case states. A tolerance above the kit's default of
     2 px MUST be justified in the SREP from the method's error bound.
   - The compatibility kit gains the seek check: for each case an SREP marks as seek-checked, `run.py`
     renders the case's frame alone and after the frames before it, and fails the case when the two differ.
6. **Validation.** Each SREP MUST name reference solutions with closed forms or published data. Each MUST
   become a conformance case where it can be measured on a still frame, and otherwise an engine test in
   sr-core that every engine runs.
7. **Pinned external data.** Data from outside the document (elevation, imagery, weather grids, ephemerides,
   catalogues, 3D tiles) MUST be fetched by a resolve step into a cache whose content hash is in the document,
   as for `<generated>` assets and the `<tiles>` assets of [SREP 9](srep-0009.md). Rendering MUST NOT access
   the network.
8. **Permissive sources.**
   - A reference implementation, and the tests of an SREP, MUST depend only on code in the public domain or
     under a permissive licence (MIT, BSD, Apache-2.0, ISC, zlib), and on data in the public domain or under
     CC0 or CC-BY. Code under the GPL, LGPL or MPL MUST NOT be a dependency, and a copyleft implementation of a
     published method MUST NOT be ported; the method is implemented from its publication.
   - Each SREP MUST name every library and dataset its reference implementation and tests use, with its
     licence.
   - Attribution is a plain credit line. The format defines no licence metadata and no enforcement; a source
     that would need either is out of scope.

## Rationale

- **Why a Process SREP.** Rule 5 changes how the compatibility kit compares results, and rules 1 to 8 bind
  every later SREP in their scope. SREP 0 assigns both to a Process SREP.
- **Time.** A simulation that seeks exactly is the property no peer offers (SREP 12). Fixed steps from a
  declared start make the result a function of the document and t; checkpoints are left to engines because
  they change cost, not pictures.
- **Randomness.** The D24 hash is already normative through [SREP 7](srep-0007.md) and implemented by the
  reference engine. It is counter-based, so a draw depends only on its address. A second generator would
  give two answers to the same question.
- **Frames.** Space and geodata need frames other than pixels as inputs. Mapping them into pixels, as SREP 10
  does for maps, keeps SREP 0's one-space rule; precision is an engine concern and stays out of the document.
- **Agreement.** Bit-identical results across engines would forbid fused multiply-add, GPU paths and
  different solvers, and would still fail on the order of floating-point sums. Seek consistency within one
  engine is testable exactly; between engines the kit's geometric measurements already carry tolerances.
- **Permissive sources.** Every engine, including engines in other languages, must be free to port the
  reference implementation. A copyleft dependency would bind every engine that follows it.

## Rejected alternatives

- **Each SREP stating its own rules.** Fifty SREPs would state them fifty ways.
- **Bit-identical results across engines.** See Rationale.
- **A new counter-based generator (Philox or PCG).** D24 already defines one; a second would split the
  format's randomness in two.
- **Licence metadata in documents.** It would need a vocabulary, checks and enforcement, and none of these
  changes what renders. A plain credit line is enough.
- **An exception to the one-space rule for astronomy.** Mapping frames into pixels, with rebasing inside the
  engine, serves the same scenes without a second space in the document.

## Backwards compatibility

None for documents: this SREP changes no schema, default or rendered picture. It applies to SREPs that enter
review after it is adopted. SREPs 9, 10, 11 and 13, already in review, are not required to meet it (see Open
issues).

| Case | Checks | Tolerance |
|---|---|---|

## Open issues

- Whether SREPs 9, 10, 11 and 13, in review, should be checked against these rules before acceptance.
- The cost of the seek check for long simulations: whether a case may limit it to a stated number of frames.
- A default tolerance between an engine's GPU and CPU paths, or none (each case states its own).
- Where shared reference-solution tests live in sr-core, and how engines in other languages run them.
