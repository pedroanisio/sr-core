# SREP 42 — Blend two clips of an imported model

## Abstract

An `object3D` of `primitive="mesh"` plays one animation clip of an imported model (`animationClip`). Three optional
attributes let it play two and blend between them: `animationClipTo` names the second clip, `animationBlend` is the
weight of the second clip (0 to 1, animatable), and `animationOffsetTo` shifts the second clip's time. Keying the weight
cross-fades one clip into another (idle into walk) without baking the transition in a modelling tool. A document that
uses none of them renders as before.

## Motivation

The NOLN glTF/FBX assessment lists "clip cross-fade / layering" as missing: with the baseline a model plays one clip, so
a character that goes from standing to walking jumps between two poses, and "the workaround today: bake the sequence in
Blender" (NOLN glTF/FBX assessment, §D item 2). With the Rust reference, an object's `animationClip` selects one clip and
`animationSpeed` and `animationOffset` retime it; no attribute names a second clip.

## Specification

### Syntax

```xml
<!-- object3DType gains -->
<xs:attribute name="animationClipTo" type="xs:string">
  <xs:annotation><xs:documentation>With primitive="mesh" and an imported model: a second clip (by name or index, as
  @animationClip) the model is blended toward by @animationBlend. It plays at the object's time scaled by
  @animationSpeed plus @animationOffsetTo.</xs:documentation></xs:annotation>
</xs:attribute>
<xs:attribute name="animationBlend" type="unitDecimal" default="0">
  <xs:annotation><xs:documentation>Weight of @animationClipTo, 0 to 1 (animatable): 0 is @animationClip alone, 1 is
  @animationClipTo alone, between them translation, scale and morph weights blend linearly and rotation along the
  shortest arc. A node a clip does not animate keeps its rest pose in that clip. Without @animationClipTo the weight
  blends toward the rest pose.</xs:documentation></xs:annotation>
</xs:attribute>
<xs:attribute name="animationOffsetTo" type="xs:double" default="0"/>
```

```xml
None.
```

New attributes with neutral defaults, accepted in every version (SREP 0, Versioning).

### Semantics

**1. Applicability.** The attributes apply to an `object3D` that draws an imported model. On any other object they have
no effect and a validator SHOULD report them as inert attributes (SREP 18). A fracture whose source is such an object
freezes the blended pose.

**2. Clip times.** Let `T` be the object's local time at the frame, `v` = `animationSpeed`. Clip A (`animationClip`, or
none) is sampled at `tA = (T·v + animationOffset) mod dA`, clip B (`animationClipTo`, or none) at
`tB = (T·v + animationOffsetTo) mod dB`, with `dA`, `dB` the clips' durations (a clip of duration 0, or no clip, is
sampled at 0 and means the rest pose).

**3. Blend.** With `w = clamp(animationBlend, 0, 1)` at the frame and `P_A`, `P_B` the node transforms and morph weights
the clips give (rest values where a clip has no channel for a node):

```
translation = (1 − w) · tA + w · tB          scale = (1 − w) · sA + w · sB
rotation    = slerp(qA, qB, w)  on the shortest arc (qB is negated first when qA · qB < 0), then normalised
weights     = (1 − w) · wA + w · wB          (when the two clips disagree on the count of a node's weights: A's)
```

`w = 0` is exactly clip A's pose and `w = 1` exactly clip B's. The blended local transforms replace the clip's in the
pose from which skinning and `node` selection proceed. `morphWeights` on the object still overrides the result.

**4. Errors.** A name of `animationClipTo` that matches no clip MUST be reported, as for `animationClip`; the object
then blends toward the rest pose.

### Defaults and the neutral case

`animationBlend` 0 (or absent): the pose is clip A's, as before. `animationClipTo` absent with a weight above 0 blends
toward the rest pose (a fade to the bind pose).

## Rationale

- **Two clips and a weight** is the smallest form that cross-fades (a transition is a weight keyed 0 to 1) and also
  mixes two clips steadily (a walk with a lean). A list of clips with transition times would hide the weight, which
  authors already animate with `animate`.
- **Shortest-arc rotation** is the standard way to interpolate unit quaternions between two poses (spherical linear
  interpolation; q and −q are the same rotation); linear blending of translation and scale follows glTF's own animation
  interpolation for those channels (glTF 2.0 specification, Animation, LINEAR).
- **Rest pose for unanimated nodes** is what each clip means when played alone, so w = 0 and w = 1 are exactly
  today's single-clip results.
- **Same speed for both clips** keeps one time scale per object; `animationOffsetTo` places the second clip's start
  (set it to `−T0·v` to start clip B at object time `T0`).

## Rejected alternatives

- **Per-clip speeds.** More attributes; an author who needs another speed can keep it in the clip.
- **Additive layers (a bone mask per clip).** Needs a way to name sets of joints; left for a later SREP.
- **Cross-fade only (a duration and a start time).** Cannot be keyed or driven by an expression.
