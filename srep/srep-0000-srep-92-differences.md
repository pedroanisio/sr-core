# SREP 0 — Decisions on the schema/engine differences SREP 92 observed

## Abstract

SREP 92 ends with a list of differences between the schema and the reference implementation, each left for "its own
decision (fix the schema, fix the implementation, or document the difference)". This SREP records one decision per
item, with the evidence read at the reference's current main. Most items resolve by documentation that is already
in schema 1.7.1 or in the Unreleased entries; three resolve by engine changes that have already landed; two are filed
on the engine board; none changes a declaration, a default or a rule, so no document changes meaning.

## Motivation

A declared attribute that does nothing misleads every author who sets it, and a documented range the engine does not
deliver is a broken promise. SREP 92 observed 60 such items from a reading of the reference at schema 1.7.0 and
resolved none. Reading the same attributes again at 67a661a shows that the reference moved under many of them: most of
the "declared but not used" attributes are read today. Leaving SREP 92's list in place without a verdict keeps both
documents and the engine board pointing at defects that no longer exist, and hides the few that do.

## Specification

Each row names the item as SREP 92 lists it, where the behaviour is read in the reference (paths under `crates/`),
and the decision. "Documented" means a sentence in `schema/scene-render.xsd` states what the reference does, so the
schema is the source an author reads. "Engine" means the reference changed or is asked to change, with the card.

### 5. Engine-side items

Two defects found while running the compatibility kit under the same work are filed on the engine board and their

### 6. Schema changes in this SREP

Annotation-only, PATCH under SREP 4:

- `oceanType/@gravity`: the sentence states the unit (metres per second squared) and the conversion.
- `particleEmitterType/@sprite`: the sentence names the four asset kinds R32 allows and the reference reads.

## Rationale

The alternative of deprecating the five attributes the reference never reads (`project/@mode`, `layout/@aspect`,
`marker/@color`, `colorManagement/@bitDepth`, `chartSeries/@name`) was rejected: a deprecation is MINOR and a removal
MAJOR under SREP 4, each value is a true description of the document (a layout's aspect, a marker's colour for an
editor), and a sentence that says the reference does not read it costs an author nothing. Implementing them is
feature work for their own SREPs, not a correction.

The alternative of changing the engine to honour the wider schema ranges (pdf `dpi`, node `opacity`) was rejected
because the schema facets already reject those documents; SREP 92 Semantics 4 makes the facet govern.

## Backwards compatibility

No declaration, default, facet, enumeration or rule changes. Every document valid before is valid after and renders
the same; `tests/test_schema_attribute_docs.py` checks the diff against the base is annotation-only and that every
conformance case keeps its verdict.

## Reference implementation

None needed. The reference at 67a661a already behaves as every sentence states.

## Conformance

No new kit case: no pixel changes. The existing cases of SREP 29 and SREP 32 that measure SR-59 and SR-60 stay
pending until the engine cards close.
