# SREP 34 — Amend SREP 18: five more inert-attribute rules and a mask finding

## Abstract

SREP 18 closes the table of inert-attribute findings at eight rules (I1 to I8) and says "a later SREP adds a rule only
with a condition that is inert under the conventions, the definitions and every accepted SREP". The Rust engine already
reports four more conditions as evaluation warnings, under its own codes E19 and E20. This amendment brings them into
SREP 18's table and registry: `INERT-I9` (`group/@collapse`), `INERT-I10` (a selective-color `@channel`), `INERT-I11` (an
effect `@source` that is never drawn), `INERT-I12` (a key's `overshoot` or `period` on a curve that does not read it), `INERT-I13` (an effect attribute its type does not read) and a new code `MASK-MISS` (a mask that leaves nothing of its node). It also
settles the severity of the engine's current output. SREP 18 is not otherwise changed.

## Motivation

SREP 18 was written for a report that no engine writes yet. The Rust engine meanwhile prints four findings of the same
kind when `validate` compiles the document. Without an amendment the engine's codes (E19, E20) and SREP 18's codes
(`INERT-*`) would name the same conditions twice, and the engine could not implement SREP 18 without renaming.

Each condition was found by the G2 lab, a style study or the motion research:

- **`group/@collapse`** is accepted and read by no code. The schema's documentation said collapsed groups share their
  parent's camera space instead of being flattened, which contradicts what the engine does (non-isolated groups already
  share the frame's camera space; isolated groups draw their children in an offscreen). The G2 sweeps recorded
  "`group@collapse` has no effect".
- **`selective-color/@channel`** is accepted (an `effect` takes it for every type) and the effect reads hue, tolerance,
  saturation, brightness, color and amount, never a channel.
- **An effect `@source` at opacity 0.** A node named as the `source` of a `displacement-map`, `difference-key` or
  `shader` effect is drawn with its own opacity; at 0 it contributes nothing and the effect does nothing, silently. The
  way to keep a map off screen is `visible="false"` at opacity 1.
- **A key parameter on the wrong curve.** `overshoot` and `period` (key overshoot and period draft) are read only by the
  `back-*` and `elastic-*` curves; on another curve they do nothing.
- **An effect parameter its type does not read.** A vignette given `intensity` (valid on every effect type) kept the default `radius` of
  4 px and darkened everything beyond about 4 px of the centre, with no diagnostic (found by a style-library study).
- **A mask in canvas coordinates.** Masks use the node's own coordinates; a rectangle or ellipse that adds to or
  intersects the node's shape and lies entirely outside the node's box leaves nothing of it, which looks like the node
  vanishing (silhouette study, defect E2).

## Specification

### Syntax

No XSD change. The documentation of `group/@collapse` changes (see the annotation SREP draft) to say it has no effect.

### Semantics

SREP 18, Specification 5, gains these rules. Each is reported as `INERT-<rule>` at `info` severity, with the same fields.

| Rule | Condition |
|---|---|
| I9 | `group` with `collapse="true"`. The attribute has no effect: a group that is not isolated passes its 2.5D children through, so they share the frame's camera space; an isolated group (clip, mask, matte, effects or blend) draws its children in its own offscreen. |
| I10 | an `effect` of type `selective-color` with `channel` other than `rgb`. The effect does not read `channel`. |
| I11 | an `effect` of type `displacement-map`, `difference-key` or `shader` whose `source` names a node with opacity 0 for the whole of its window (it is drawn with its own opacity, so it contributes nothing). `visible="false"` at opacity 1 is the way to keep the node off screen. |
| I12 | a `key` with `overshoot` on a segment whose curve is not `back-in`, `back-out` or `back-in-out`, or `period` on one whose curve is not `elastic-in`, `elastic-out` or `elastic-in-out` (the curve is the key's `interpolation`, else the animation's `defaultInterpolation`); see the key overshoot and period draft. |
| I13 | an `effect` carrying an attribute that its `type` does not read. `effectType` is one attribute bag shared by every effect type, so the XSD accepts any of them on any type; each type reads a defined subset (its documentation lists them), and the others, including `id`, `type`, `enabled` and `mix`, are exempt only where every type reads them (`id`, `type`, `enabled`, `mix`). |

The registry (Specification 4) gains:

| Code | Severity | Finding |
|---|---|---|
| `MASK-MISS` | warning | a `mask` of `type` `rect` or `ellipse` with mode `add` (or default) or `intersect`, not inverted, whose box lies entirely outside the box of the node it masks, in the node's own coordinates; `measured` is the mask's offset in pixels |

`MASK-MISS` is a warning, not an inert finding: the mask has an effect, and it is to hide the node, which is almost
never what the author meant.

**Severity of the engine's current output.** SREP 18 (accepted, Resolution of 2026-10-05) reports inert findings at `info`
severity. Until an engine writes SREP 18's report, an engine that prints these conditions on its own channel MUST print I9
to I13 as information (not warnings), so that they do not fail a strict mode that counts errors and warnings only.
`MASK-MISS` is a warning, as SREP 18's table and this amendment say: the mask has an effect (the node disappears) and
that is almost never intended, so strict modes count it. The Rust reference prints I9 to I13 as `E19` at `info` and
`MASK-MISS` as `E20` at `warning`.

### Defaults and the neutral case

Findings never change pixels. A document without `collapse="true"`, a selective-color `channel`, a source at opacity 0 or a
mask outside its node is unaffected.

## Rationale

- **Same condition, one name.** An engine code is a private name for a finding every engine will report.
- **Inert means by definition.** I9 to I13 are inert by the schema's own words once the documentation of `collapse` is
  corrected (rule 1 of the annotation SREP draft); a choice of semantics for `collapse` (implementing it for isolated groups) is
  left open for a later SREP, with the finding reporting the attribute until then.
- **Why `MASK-MISS` is a separate code.** I1 to I8 are attributes with no effect; a mask outside its node has the strongest
  effect possible.

## Rejected alternatives

- **Remove `collapse` from the schema.** It is a breaking change (a valid attribute becomes invalid) with no gain.
- **Implement `collapse`.** The engine's behaviour for non-isolated groups already is the collapsed one; no style needs
  the other.
- **Report I11 and `MASK-MISS` as errors.** The documents mean what they say.

## Backwards compatibility

- **Class: Added, MINOR (1.2, with SREP 18).** No attribute and no validity change.
- No picture changes. Documents that use the conditions gain findings.
